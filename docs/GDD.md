# 엄청엄청 위대한 마법사 키우기 — 핵심 시스템 기획서 (3판)

이 문서는 게임의 핵심 시스템(조작, 주문 컴파일러, 과열, 스쳐 피하기, 콤보와 결정, 커맨드 비기와 판정기, 강화 규칙, 주문 블록, HUD, 핵심 알고리즘, 만드는 순서)을 정한다. 세계, 캐릭터, 적, 온라인, 연출, 지팡이 겉모습은 각자의 문서가 정하고 이 문서는 요약과 가리키는 줄만 둔다(0절).

- `docs/DECISIONS.md`가 이 문서를 포함한 모든 문서보다 우선한다.
- 표기: **[확정]** 은 개발자가 직접 정한 것(`DECISIONS.md`의 [개발자] 항목 포함), **[조율]** 은 문서 사이의 충돌을 풀려고 `DECISIONS.md` 2절에 정리한 공통 규격, **[제안]** 은 아직 확인받지 않은 설계안이다. 표시가 없는 수치는 [제안]이다.
- 모든 수치는 플레이 테스트 전의 시작값이다. 이 값으로 먼저 만들고 QA에서 조정한다. **[확정]**
- 단위: 거리는 칸(1칸 = 64px), 속도는 칸/초, 시간은 초. 게임 시간은 1초 = 60틱이다. T는 "지팡이 트리 1회 실행의 피해"다.
- 절 번호 1~18의 주제는 고정이다(다른 문서가 "GDD 8절"처럼 번호로 가리키기 때문). 0절은 문서 지도, 19절은 온라인 구조 요약, 20절은 2판과 달랐던 곳의 기록이고, 맨 끝에 "개발자 확인 필요"가 있다.
- 이 문서의 본문은 전부 `DECISIONS.md` 기준의 지금 규칙이다. 2판의 규칙과 수치는 20절과 18절의 "기록" 부분에만 남아 있고 효력이 없다. 다른 문서의 "GDD와 달라지는 곳" 표도 2판과의 차이를 적은 기록이다.
- 이 문서가 주인이 아닌 내용(0절)은 숫자를 다시 적지 않고 주인 문서의 절을 가리킨다. 요약으로 적어 둔 값이 주인 문서와 다르면 주인 문서가 맞다.

## 1. 개요

- 장르: 2D 탑다운 아레나 액션 + 주문 조립 + 확률형 강화 + 커맨드 비기 + 온라인(결투, 광장, 거래, 시즌)
- 테마 **[확정]**: 야생에서 훈련하고 싸우는 초보 마법사. 은퇴한 대마법사 느루가 제자 다섯을 야생 한뎃벌에 던져 놓고 후계자를 고른다.
- 환경: macOS(Apple Silicon), Unity 2D(URP), C#. 게임은 빌드를 직접 배포하고 서버는 맥미니 한 대에 직접 올린다. 스팀은 쓰지 않는다. **[확정]**
- 그림 **[조율]**: 도트. 1칸 = 64px, 기준 화면 1920×1080, 그림 1픽셀 = 화면 1픽셀.
- 조작 **[확정]**: 전투는 키보드만 쓴다. 메뉴(야영 화면, 강화 화면, 광장 메뉴)는 마우스를 쓸 수 있고 키보드만으로도 된다.
- 캐릭터 **[확정]**: 5명. 전용 지팡이, 고유 능력, 능력치가 전부 다르다(10절).
- 모드 **[확정]**: 세 가지.
  1. **끝없는 웨이브**: 스테이지 구분 없이 야생 한 곳에서 계속 싸운다. 끝이 없고, 체력이 0이 되면 판이 끝난다. 시간 때우기용이다. 첫 보스는 스승의 허상이고 처음에는 이길 수 없다. 그 허상에게 복수하는 것이 플레이의 첫 목표다(11절).
  2. **결투(PvP)**: 1 대 1. 광장에서 대결 신청, 결투 방 생성·입장, 자동 매치로 들어간다.
  3. **광장**: 같은 서버 사람들이 만나고, 거래하고, 결투를 신청하고, 친구를 맺고, 대화한다.
- 성장 **[확정]**: 지팡이 강화(+0~+13)는 판이 끝나도 남는다. 강화는 메뉴에서 들어가는 전용 강화 화면에서 하고, 판 중에는 하지 않는다. 강화 단계마다 지팡이의 모양과 효과가 다르다.
- 시즌 **[확정]**: 시즌마다 서버 순위 1위가 후계자가 되고 한정판 보상을 받는다. 순위는 무한 웨이브 점수와 결투 점수의 합산이다.
- 서버 없이도 **[확정]**: 서버에 연결하지 못해도 무한 웨이브, 조립, 강화 화면이 기기 안의 오프라인 프로필로 완전히 돌아간다. 결제는 지금 넣지 않고, 나중에 연결만 하면 되는 구조로 둔다(19절).
- 재미의 축
  1. 블록을 조립해 내 마법을 만든다(주문 컴파일러, 4절).
  2. 어려운 커맨드를 넣어 비기를 쓴다(입력 트라이, 8절).
  3. 판에서 가져온 블록을 제물로 강화 도박을 하고, 자라는 지팡이를 남에게 보여 준다(9절).

## 2. 게임 루프

### 2.1 바깥 고리 (판 밖)

1. 게임을 켜면 프로필을 고른다. 오프라인 프로필은 처음 켰을 때 자동으로 생기고 계정이 필요 없다. 서버 프로필은 가입해서 만든다(아이디, 비밀번호, 닉네임, 이메일. 비밀번호를 잃으면 이메일로 복구한다. `online.md` 7.3절). 둘은 섞이지 않는다(19절).
2. 메인 메뉴: 원정(무한 웨이브), 강화, 조립과 서고, 연습, 기록, 옷장, 상점(골드 상점), 설정. 서버 프로필이면 광장, 결투, 시즌, 우편함, 친구, 순위표, 장터가 더 열린다(`online.md` 5.2절). 오프라인 프로필은 부적과 +0 새 지팡이를 이 메인 메뉴의 상점에서만 산다(`online.md` 2.4절, 8.1절).
3. 판에서 골드, 블록, 강화 재료를 가져온다 → 강화 화면에서 지팡이를 키운다 → 더 깊은 웨이브와 더 높은 리그로 간다.
4. 프로필에 남는 것: 캐릭터별 지팡이(자루마다 강화 단계, 역대 최고 단계, 변이, 확장 슬롯, 장인의 기운. 한 캐릭터의 지팡이를 개수 제한 없이 여러 자루 가질 수 있다, 10.1절), 서고의 블록, 출발 조립, 골드, 강화석과 부적, 캐릭터별 비기 해금, 꾸미기와 칭호, 기록. 판에만 있는 것: 열, 콤보, 결정, 체력, 판 중에 얻은 야생 블록과 원정 지갑. 전체 구분표는 `online.md` 1.1절.

### 2.2 무한 웨이브 한 판

1. 캐릭터를 고른다. 전용 지팡이가 따라온다(보관한 지팡이가 여러 자루면 하나를 고른다). 판 중에는 바꾸지 않는다. 출발 조립을 확인한다.
2. 시작 웨이브를 고른다(키운 계정이 앞의 웨이브를 그냥 지나가지 않게 하는 장치. 규칙은 `monsters.md` 4.7절).
3. 웨이브 전투: 이동, 발사, 스쳐 피하기, 비기. 적을 전멸시키면 끝난다.
4. 전리품: 골드 + 주문 블록 카드 4장 중 2장 선택(엘리트를 잡은 웨이브와 보스를 잡은 웨이브는 5장 중 2장. 보스를 잡지 않는 허상과의 첫 만남은 4장이다. 기준은 `monsters.md` 6.2절·3.9.3절). 판 중 보관함은 12칸.
5. 야영 **[조율]**: 조립, 회복, 비기 선택, 허수아비 연습만 한다. **강화는 없다.** 시간 제한 없음. 절차는 `monsters.md` 4.6절.
6. 하루 = 10웨이브 **[조율]**: 낮(1~4), 해질녘(5~7), 밤(8~9), 보스(10). 보스를 잡으면 다음 날이 시작되고 끝없이 반복한다. 시간대는 야영 중 4초에 걸쳐 바뀌고 전투 중에는 바뀌지 않는다. 밤에도 적은 온전히 보이고 시야·판정·적의 속도와 예고는 낮과 같다. 밤에만 있는 것은 스폰 가중치(`monsters.md` 4.1절)와 돌발 사건 "별똥 결정"(`world-characters.md` 2.3절, 이 문서 7절)뿐이다.
7. 체력이 0이 되면 판이 끝난다. 클리어는 없다. 기록은 "3일째 웨이브 23"처럼 적는다(N일째 = 올림(웨이브 ÷ 10)). **예외는 하나다 [확정]**: 프로필이 처음 닿는 웨이브 10은 스승의 허상과의 첫 만남이고, 거기서 쓰러져도 판이 끝나지 않는다. 체력을 회복하고 웨이브 11로 이어진다(11절, `monsters.md` 3.9절).
8. 정산: 원정 지갑의 골드, 귀환 가방에 담은 블록, 강화 재료가 프로필로 들어간다. 귀환 가방의 칸수와 영웅 블록 제한은 `monsters.md` 6.2절이 정한다. 5웨이브마다 중간 지점이 기록되어 판이 비정상으로 끝나도 거기까지는 정산한다(정산 절차는 `online.md` 1.2절).

전장 **[조율]**: 24×14칸, 사방이 막혀 있다. 적은 네 변 중 플레이어에게서 먼 두 변에서 나온다. 전장은 한 곳이고 시간대에 따라 바닥 색만 바뀐다(`world-characters.md` 2절).

### 2.3 결투와 광장

- 결투: 돌마당(24×14칸, 선돌 기둥 4개)에서 1 대 1. 조작, 컴파일러, 과열, 비기 판정기는 무한 웨이브와 같은 코어를 쓰고, 수치만 결투용으로 바뀐다. 모든 캐릭터에 똑같이 걸리는 규칙은 `online.md` 4절, 캐릭터마다 다른 값은 `world-characters.md` 5.4절이 기준이다. 돌마당의 기둥 좌표와 시작 위치는 `world-characters.md` 2.6절.
- 광장: 서버 프로필에서만 열린다. 강화하는 장소나 강화 NPC는 없다. 강화 화면은 광장 메뉴(Esc)에서도 열 수 있다(`online.md` 5절, `world-characters.md` 2.5절).

## 3. 조작 [확정]

| 키 | 기능 |
|---|---|
| WASD | 이동. 이동 방향 = 시야 = 발사 방향 (8방향) |
| J | 발사. 누르고 있으면 연사 |
| K | 비기 전용 |
| Shift (누르는 동안) | 자세: 시야를 잠그고 느려진 속도로 이동 |
| Space (누르는 동안) | 반전 자세: 시야를 180도 뒤집어 잠금 |

세부 규칙 [제안]:

- 자세에 들어갈 때 시야가 대각선이면 마지막에 누른 키 방향(상하좌우)으로 맞춘다. 자세 중에는 대각 사격이 없다.
- 반전 자세도 자세다. 자세 속도, 커맨드 인정. Space를 떼면 시야는 뒤집힌 방향으로 남고, 이동 키가 눌려 있으면 그 방향으로 바로 바뀐다.
- Shift를 누른 채 Space를 누르면 잠긴 시야만 180도 뒤집는다.
- 대각 이동 중 두 키를 0.08초 안에 차례로 떼면 대각 시야를 유지한다.
- 시야 화살표는 항상 발밑에 표시한다. 평소 반투명, 자세 중 불투명, 반전 중 다른 색.
- 대체 배치: 방향키 + Z 발사 / X 비기 / C 자세 / V 반전. 전 키 재설정 가능.
- 키는 물리 키 기준으로 읽고, 전투 중에는 한글 입력기의 영향을 받지 않아야 한다. 에디터가 아니라 빌드에서 확인한다.
- 대시는 없다.

플레이어 기준값 [제안]: 체력 6칸, 피격 후 무적 1초, 이동 속도 5.0, 자세 속도 85%(4.25), 피격 판정 반지름 0.15. 캐릭터마다 이 값에서 벗어난다(10절). 다섯 중 가장 느린 자세 속도는 달구의 3.76이고, 적의 모든 공격은 이 속도로 피할 수 있게 만든다(`monsters.md` 1.2절).

입력 이벤트 [조율]:

- 입력은 프레임이 아니라 이벤트로 기록한다. 이벤트 = (유효 틱, 틱 안 오프셋 1/256틱, 키, 누름/뗌, 순번).
- 같은 틱, 같은 오프셋에 방향과 K가 같이 들어오면 **방향이 K보다 먼저**다. 판정기(8절), 판 재실행 검증, 결투가 모두 이 순서를 쓴다.
- 히트스톱은 그림만 멈추고 게임 시간(틱)은 멈추지 않는다.

결투 한정 예외 [제안]: J 발사와 방향이 있는 비기는 상대 쪽으로 최대 10도까지 조준이 보정된다. "이동 방향 = 발사 방향"의 유일한 예외이고 무한 웨이브에는 없다. 결투의 피격 판정 반지름은 0.30이다(`online.md` 4.4절).

## 4. 주문 컴파일러 (핵심 알고리즘 1)

지팡이는 코어 슬롯 1개와 연결 슬롯 4개로 시작한다(갈피의 지팡이만 연결 5개). 확장 슬롯은 지팡이 하나당 평생 3칸까지 늘어난다(9절). 발사할 때 슬롯 배열을 실행 트리로 바꿔 깊이 우선으로 실행한다.

| 블록 종류 | 규칙 |
|---|---|
| 코어 | 투사체 블록만 들어간다 |
| 변형 | 현재 스코프의 모든 투사체에 붙는다 (누적) |
| 분열 | 현재 스코프의 투사체를 N개 부채꼴로 복제. 한 스코프에 1개만 유효하고, 두 번째는 경고와 함께 무시 |
| 적중 시 발동 | 새 스코프를 열고, 뒤에 오는 블록은 모두 그 안에 들어간다 |
| 투사체 (연결 슬롯) | 트리거 뒤 첫 투사체는 그 스코프의 주인, 그 외에는 같은 스코프에서 동시 발사 |

- 트리거는 투사체당 첫 적중 1회만 발동한다. 폭발은 중심에서 1회. 적을 지나가는 탄(그림자 구체, 관통탄)도 첫 적중에서만 발동한다.
- 발사 간격은 코어 블록의 간격을 쓴다.
- 부채꼴 각도: 2갈래 ±10도, 3갈래 -15/0/+15도.
- 안전장치: 트리거 깊이 최대 3단, 트리 실행 1회당 투사체 최대 64개(넘으면 가장 깊은 스코프부터 생략), 스코프가 깊어질 때마다 피해 ×0.85(갈피의 지팡이만 ×0.92).
- 화면 전체 플레이어 투사체 상한 300개, 적 투사체는 별도로 150개. 생략된 만큼은 생성된 탄의 피해 배율로 환산한다. 결투의 상한은 `online.md` 4.2절.
- 트리거 뒤에 투사체가 없으면 야영의 조립 화면에 경고를 띄운다. 그림자 구체에 "관통 +2"를 붙인 것처럼 효과가 없는 조합에도 경고를 띄운다.
- 실행 함수는 처음부터 `Execute(트리, 위치, 방향, 피해 배율, 열 면제 여부, 진영)` 형태로 만든다. 비기, 갈피의 사본 마법진, 보스(스승의 허상)가 같은 함수를 쓴다.
- 컴파일과 실행은 유니티와 분리된 결정론 코어 안에서 고정소수점 정수로 계산한다(15절). 같은 입력이면 기기와 서버에서 같은 결과가 나와야 한다.

속성 [조율]:

- 탄의 피해 속성, 색, 모양은 **그 탄을 만든 투사체 블록의 속성**이다. 변형·제어 블록의 속성은 피해 속성을 바꾸지 않는다(제물 보너스에만 쓰인다, 9절).
- 블록을 거치지 않는 피해(패시브와 고유 비기가 스스로 내는 피해)는 캐릭터의 속성이다(10절).
- 약점 속성은 피해 ×1.25, 저항 속성은 ×0.8. 적마다 약점 1개와 저항 1개가 있다(`monsters.md`).

피해 공식:

`기본 × 강화 배율 × (1 + 변형 보너스 합) × 변이 배율 × 임계 배율 × 비기 배율 × 감쇠^깊이 × 속성 배율 × 대상 상태 배율 × 캐릭터 배율`

- 강화 배율 = 1.15^단계(+13에서 약 6.2배). 결투에서는 다른 식을 쓴다(`online.md` 4.2절).
- 임계 배율 = (과열 3배 블록이 있으면 3, 없으면 2) + (유리 지팡이 변이가 있으면 1). 임계가 아니면 1.
- 비기 배율은 임계 배율과 같이 적용하지 않는다(비기는 임계 판정을 받지 않는다).
- 감쇠 = 0.85(갈피 0.92).
- 속성 배율 = 약점 1.25 / 저항 0.8 / 그 밖 1.
- 대상 상태 배율 = 잠식에 걸린 적이면 1.15, 아니면 1.
- 캐릭터 배율 = 그믐의 그림자 계약(가진 결정 1개당 +3%). 다른 캐릭터는 1.

## 5. 과열 [제안]

기준값(캐릭터별 차이는 10절):

- 발사 1회의 열 = 스코프별 (블록 열 합 × 그 스코프의 분열 배수)의 합. 분열 배수는 2갈래 ×1.6, 3갈래 ×2.2.
- 냉각: 발사를 0.2초 멈춘 뒤부터 초당 45.
- 임계: 이번 발사를 더한 뒤의 열이 임계 시작값(85) 이상이면 그 발사는 피해 2배.
- 잠금: 100을 넘긴 발사는 임계로 나가고, 직후 3초 동안 발사 불가. 풀리면 열 0.
- 잠금 중에는 콤보 타이머가 멈춘다.
- 열 게이지는 캐릭터 발밑의 링(반지름 44px)으로 표시한다. 오르는 중은 회청색, 임계 구간은 흰색 + 검정 이중 테, 잠금은 식은 재색으로 꺼진 링이 남은 시간만큼 줄어든다. **금색과 빨강은 쓰지 않는다**(금색은 엘리트와 값진 것, 빨강은 적의 공격 전용). 링 위에 그 캐릭터의 임계 시작값 눈금이 있다. 그리는 법은 `effects.md` 10절.

캐릭터별로 다른 것: 임계 시작값(달구 80, 성에 90), 냉각(초롱 50), 잠금(초롱 2.5초, 갈피 3.5초). 열의 예외는 둘이다: 갈피의 밑줄(맨 끝 칸 블록의 열 절반, 최대 −5), 달구의 불가마(지대 안에서 쏜 임계 발사의 열을 합계 16까지 대신 먹는다).

확인: 기준값에서 마력탄으로 임계 구간을 타면 69.2 DPS, J를 누르고만 있으면 44.9 DPS로 1.54배다(18절). 손맛 시제품에서 "임계 구간 플레이 DPS ÷ 꾹 누르기 DPS"가 1.4 이상인지 허수아비로 캐릭터마다 확인한다.

## 6. 스쳐 피하기 [제안]

- 피격 판정 반지름 0.15, 감지 판정 반지름 0.6(초롱 0.75).
- 인정 대상: 적의 탄, 적의 돌진, 예고 구역이 터지는 순간 경계 바깥 0.6 이내.
- 탄 하나당 1회, 같은 시전에서 나온 탄은 묶어서 1회만 인정.
- 보상: 열이 임계 시작값보다 낮으면 임계 시작값으로 올린다. 다음 발사 1회는 열이 오르지 않는다. 잠금 중이면 즉시 해제하고 열을 임계 시작값으로 맞춘다.
- 이동 속도 +20% 1.5초(초롱 2.0초. 중첩 없이 시간만 갱신), 콤보 +2.
- 결투에서는 상대 1명당 1.0초에 1회만 인정하고 보상도 줄어든다(`online.md` 4.3절).

## 7. 콤보와 마력 결정 [확정: 개념 / 제안: 수치]

기준값(캐릭터별 차이는 10절):

- 적을 맞힐 때마다 콤보 +1, 임계 적중은 +2. 단 발사 1회로 오르는 콤보는 최대 +3.
- 2초 동안 못 맞히면 0 (잠금 중에는 타이머 정지).
- 콤보 15마다 마력 결정 1개(초롱은 12마다). 최대 5개(달구 5, 초롱 5, 갈피 4, 성에 6, 그믐 7).
- 피격 시 콤보 0, 결정 1개 파괴(성에는 파괴 없음, 그믐은 2개).
- 비기로 맞힌 것은 콤보에 넣지 않는다.
- 콤보 말고 결정을 얻는 길은 밤 웨이브(하루의 8~9번째)의 돌발 사건 "별똥 결정" 하나다. 떨어진 별똥을 밟으면 결정 +1이고, 결정 상한은 넘지 않는다(상한이 차 있으면 얻지 못한다). 언제 얼마나 떨어지는지는 `world-characters.md` 2.3절이 기준이다. 그믐은 이 결정으로도 빚부터 갚는다. 결투에는 없다.
- 결정의 용도: 비기의 연료. 웨이브가 끝날 때 남은 결정은 개당 5골드로 바뀐다(그믐의 빚이 있으면 빚부터 갚는다).
- 결정은 판 안에만 있다. 판이 끝나면 사라진다.
- 결투에서 피격 벌칙(콤보 0, 결정 파괴)은 1.0초에 1회만 발동한다(`online.md` 4.3절).

## 8. 커맨드 비기 (핵심 알고리즘 2)

피파 개인기와 철권 커맨드처럼 입력 방법에 따라 다른 기술이 나가고, 어려운 입력일수록 보상이 크다. [확정: 방향 / 제안: 세부]

각 캐릭터는 공용 비기 10종에 고유 비기 1종을 더해 11종을 쓴다. 트라이는 판을 시작할 때 캐릭터별로 만든다(공용 10 + 그 캐릭터의 고유 1). 다른 캐릭터의 고유 노드는 트라이에 없다.

### 입력 규칙

- 방향 입력(앞/뒤/옆)은 자세 중에만 커맨드로 읽힌다. 시야 기준이다.
- 모든 비기는 K로 끝난다. 자세 밖의 K는 항상 마력 방출이다.
- 모든 입력은 키를 누르는 순간만 본다. 이미 누르고 있던 방향키는 입력이 아니므로, 쓰려면 뗐다가 다시 눌러야 한다.
- 섬(저스트): 방향 키를 누르고 0.07초 안에 K. 방향이 먼저여야 한다. 늦으면 같은 자리의 일반 기술이 나간다. K가 먼저면 그 시점의 커맨드로 처리한다(앞, K = 부채 전개). 방향과 K가 같은 오프셋이면 3절의 순서 규칙대로 방향이 먼저다.
- 입력 사이 최대 간격:

  | 구간 | 간격 |
  |---|---|
  | 기본 | 0.3초 |
  | 같은 쪽 옆 두 번(잔상 걸음) | 0.25초 |
  | 앞→뒤, 옆→앞, 앞→옆, 좌→우(반대쪽 옆), 달구의 뒤→뒤 | 0.2초 |
  | 만개의 각 입력(앞→뒤, 뒤→뒤, 뒤→앞, 앞→K) | 0.18초 |

  앞→뒤 간선은 팔방 전개와 만개가 같이 쓴다. 팔방 전개에는 0.2초, 만개에는 0.18초로 적용한다(적용하는 법은 아래 "판정기").

- 마지막 방향 입력 후 0.3초가 지나면 커맨드는 처음으로 돌아간다.
- 자세 진입, 해제, 반전 때 커맨드는 처음으로 돌아간다. 일시정지에서도 처음으로 돌아간다.
- 결정이 모자라면 불발. 더 싼 기술로 바뀌지 않는다. 예외는 둘이다: 고유 비기 5종은 결정이 2개에 못 미치면 부모 노드의 기술(결정 1개)이 대신 나가고, 그믐은 외상(빚 결정 2개까지)을 먼저 적용한다.
- 비기 공통 재사용 대기 0.4초. 대기가 끝나기 0.1초 전부터 누른 K는 보관했다가 끝나는 순간 처리한다.
- 모든 비기는 열을 올리지 않고, 임계 배율을 받지 않으며, 강화 배율은 받는다.
- 과열 잠금 중: 마력 방출은 쓸 수 있지만 잠금은 풀리지 않는다. 잠금을 푸는 수단은 스쳐 피하기와 방열 폭발뿐이다.
- 트리를 실행하는 비기의 피해 속성은 맞힌 투사체 블록의 속성이다. 트리를 쓰지 않는 고유 비기의 피해는 캐릭터 속성이다.
- 넉백, 기절, 경직은 적의 꼬리표에 따라 줄거나 듣지 않는다. 엘리트는 거리와 시간이 절반이고, 중량과 보스는 면역이다. 넉백, 기절, 경직의 꼬리표별 수치는 `world-characters.md` 3.6절이 기준이다(⑨ 뇌광창의 기절 1초는 그 절 효과별 표의 줄대로 일반 1초, 엘리트 0.5초, 중량 없음). 보스만 예외로, 뇌광창의 기절을 0.3초 동작 멈춤으로 받는다(`monsters.md` 3.2절).

### 해금

- 비기 해금은 프로필에 **캐릭터별로** 남는다. **[조율]** 한 번 해금하면 그 캐릭터로는 다음 판에도 쓴다.
- 시작: 마력 방출, 반동 사격, 그 캐릭터의 고유 비기 3종. 고유 비기를 처음부터 주는 것은 확정이다 **[확정]**.
- 해금 차례 [제안]: 웨이브 1~6을 넘길 때마다 그 캐릭터가 아직 해금하지 못한 공용 비기 중 후보 2개에서 1개를 무료로 고른다. 고르는 자리는 야영의 비기 탭이다. 공용 8종을 다 해금하면 차례는 더 오지 않는다(두 판이면 다 모인다). 시작 웨이브를 골라 1~6을 건너뛴 판에서는 출발 야영에서 차례대로 고른다.
- 부모 기술이 있어야 후보가 된다. 후보가 1개뿐이면 1개만 보여 준다.
- 뇌광창은 꿰뚫는 창 보유 + 웨이브 4 이후, 만개는 팔방 전개 보유 + 웨이브 6 이후.
- 결투에서는 해금과 무관하게 공용 10 + 고유 1을 전부 쓴다(`online.md` 4.1절).

### 판정기

- 트라이 노드: 자식 4개(앞/뒤/좌/우. 표기와 트리 그림은 좌우를 "옆"으로 묶는다), K 기술, 섬 기술, 들어오는 간선의 허용 간격, 실패 링크, 해금 여부, 부모 대체 여부(고유 비기 노드만 참).
- "좌, 좌"(잔상 걸음)와 "좌, 우"(그림자 손)는 서로 다른 노드다. 좌우는 대칭으로 양쪽 다 만든다.
- 방향 입력마다 커서가 한 칸 이동한다. 자식이 없으면 실패 링크를 따라간다. 입력당 O(1), 최악 O(깊이).
- K 판정: 현재 노드부터 실패 링크를 따라가며 "기술이 있고, 해금됐고, 그 경로의 간격을 모두 통과한" 첫 노드를 고른다. 해금하지 않은 노드는 기술이 없는 노드로 본다. 루트에는 마력 방출이 있어 항상 끝난다.
- 간선의 허용 간격은 그 간선으로 들어가는 노드에 하나만 저장한다(그 노드의 기본값). 어떤 노드의 간격 검사는 그 노드의 깊이만큼의 최근 방향 입력을 놓고, 경로 위 노드들의 기본값으로 한다. 실패 링크로 내려온 노드도 같은 방법으로 검사한다. 마지막 방향 입력에서 K까지는 0.3초다(섬은 0.07초).
- 만개 노드만 예외다. K 판정 때 자기 경로의 간격 넷(앞→뒤, 뒤→뒤, 뒤→앞, 앞→K)을 간선의 기본값 대신 전부 0.18초로 다시 검사한다. 그래서 앞-뒤 노드로 들어오는 간선은 기본값 0.2초를 저장하고, 팔방 전개에는 0.2초로, 만개에는 0.18초로 적용된다.
- 만개를 해금했고 커서가 만개 노드에 있는데 이 검사에서 떨어지면, 실패 링크를 따라가지 않고 불발로 끝낸다(위 K 판정의 유일한 예외. 결정 소모 없음, 늦은 입력을 표시). 만개를 해금하지 않았으면 만개 노드는 기술이 없는 노드이므로 실패 링크를 따라간다. 이때 먼저 걸리는 것은 뒤-앞 노드의 방열 폭발이다.
- 고른 기술의 결정이 모자랄 때:
  1. 그믐이면 외상을 먼저 적용한다(빚이 2개를 넘지 않는 범위에서. 만개는 제외).
  2. 그래도 모자라고 고른 노드가 고유 비기면 부모 노드의 기술로 한 번만 내려간다(외상 포함해 다시 본다).
  3. 그 밖에는 불발로 끝낸다. 더 내려가지 않는다.
- 발동하거나 불발하면 커서와 입력 기록을 비운다.
- 간격 검사는 최근 방향 입력 8개의 시각으로 한다.
- 시각은 입력 이벤트의 시각(틱 × 256 + 틱 안 오프셋, 정수)을 쓴다. 프레임 단위로 읽지 않는다. 1단위는 1/15,360초이고 간격은 정수로 비교한다: 0.07초 = 1,075, 0.18초 = 2,765, 0.2초 = 3,072, 0.25초 = 3,840, 0.3초 = 4,608. 히트스톱은 게임 시간을 멈추지 않으므로 영향을 주지 않는다.
- 화면의 "지금 K = 기술명(비용)"은 같은 판정 함수의 결과를 매 프레임 표시한다. 섬 기술이 있는 자리에서는 두 줄로 보여 준다. 결정이 모자라 부모 기술로 내려갈 자리에서는 내려간 기술명을 보여 주고, 그믐은 "외상 N"을 붙인다.
- 판정기는 유니티와 분리된 순수 C# 클래스로 결정론 코어 안에 만들고, 입력열 단위 테스트를 붙인다.

단위 테스트에 넣을 입력열(실패 링크 규칙으로 따진 기대값):

| 입력열 | 캐릭터 | 기대 |

| 앞, 앞, 앞, K | 전원 | 꿰뚫는 창 (잡입력이 섞여도 가장 긴 접미사) |

| 뒤, 뒤, 앞, K | 달구 | 방열 폭발 |

  - 판을 시작할 때 그 캐릭터의 지팡이 중 한 자루를 고르고, 판 중에는 바꾸지 않는다(2.2절).
  - 여러 자루를 가져도 9절의 강화 규칙은 자루마다 따로 돌아간다. 한 자루의 기운이나 역대 최고 단계가 다른 자루로 넘어가지 않는다. 그래서 여러 자루를 나란히 강화해도 첫 +13까지의 시간은 줄지 않는다(`online.md` 2.6절의 계산).

### 10.2 속성 [확정: 5개, 약점과 저항 / 조율: 규칙]

- 속성은 화염, 번개, 비전, 냉기, 암흑 다섯이다. 블록에는 속성이 없는 "무"도 있다.
- 피해 속성은 맞힌 투사체 블록의 속성이다. 약점 ×1.25, 저항 ×0.8. 적마다 약점 1개와 저항 1개가 있고, 배분은 `monsters.md` 2.5절이다.
- 주문색: 화염 주황, 번개 레몬, 비전 청록, 냉기 하늘, 암흑 푸른 보라. 탄은 색뿐 아니라 모양으로도 구분한다(색 값과 모양은 `effects.md` 0.1절).

- 새 블록 4종의 세부 [제안]:
  - 이동 감속(얼음 송곳, 서리, 달구의 불가마)은 서로 더하지 않는다. 가장 큰 값 하나만 적용하고 시간은 각자 갱신한다. 보스에게는 절반만 들어간다(−30% → −15%, −20% → −10%). 엘리트와 중량에게는 그대로 들어간다.
  - 그림자 구체는 적을 몇이든 지나가고 벽에서 사라진다. 같은 적은 한 번만 맞는다. "관통 +2"는 효과가 없다(조립 화면에 경고).
  - 잠식의 +15%는 겹치지 않고 시간만 갱신한다. 잠식을 건 그 탄의 피해에는 적용하지 않고 다음 피해부터 적용한다.
  - 서리와 잠식은 변형 블록이라 탄의 피해 속성을 바꾸지 않는다.
- 스승의 허상은 플레이어의 조립을 복사할 때 얼음 송곳의 감속과 서리·잠식의 부가 효과를 복사하지 않는다(`monsters.md` 3.4절).

## 11. 적과 웨이브 (요약)

이 절은 요약이다. 적의 수치, AI의 세부, 보스 패턴, 웨이브 곡선, 드랍의 기준은 `monsters.md`다.

공통 규칙:

- 위험색(색상각 330~15도, 채도·명도 70% 이상의 빨강·자홍)은 전장 안에서 적의 공격, 예고, 적 탄에만 쓴다. 플레이어의 몸, 지팡이, 주문에는 쓰지 않는다. **[조율]** 유일한 예외는 결투에서 상대의 탄을 자홍으로 그리는 것이다.
- 예고 구역은 빨강이 차오른 뒤 흰색으로 번쩍하고 판정이 나온다. **[확정]** 테두리는 3겹(검정, 빨강, 흰색)이고 내 효과가 예고를 덮는 정도에는 상한이 있다(`effects.md` 9.2절, 14절).
- 접촉 피해는 같은 적에게서 1.5초에 1회. 어떤 적 공격도 한 번에 3칸을 넘지 않는다(공격 쪽 상한이다. 그믐의 빚 +1칸은 그 뒤에 더해져 최대 4칸. `world-characters.md` 4.5절).
- 모든 공격은 가장 느린 캐릭터의 자세 속도 3.76(서리밭 위에서는 2.63)으로 피할 수 있어야 한다. 예고 없이 부딪치는 적은 3.76보다 느리다(덤불 늑대 4.5만 예외. 늑대는 반드시 예고 돌진을 한다). 동시에 떠 있는 예고들 사이에 피할 길이 없으면 새 예고를 시작하지 않는다(R5). 규칙과 검산표는 `monsters.md` 1.2절과 8절.
- 적 구성: 일반 12종(원형 4종 + 신규 8종), 엘리트(웨이브 12부터), 보스 6종.

원형 4종(15절의 알고리즘이 걸려 있는 네 종. 아래 값은 `monsters.md` 2.1절·2.2절을 옮긴 것이고 그쪽이 기준이다):

| 몬스터 | 체력 | 속도 | 피해 | 공격 | 예고 | 빈틈 |
|---|---|---|---|---|---|---|
| 이끼 슬라임 | 20 | 3.0 | 1칸 | 접촉 | 없음 | 없음 |
| 덤불 늑대 | 45 | 4.5 | 1칸 | 직선 돌진 6칸 | 직선 띠 0.5초 | 1.5초 경직 |
| 선돌지기 | 300 | 1.8 | 2칸 | 내려찍기 / 휩쓸기 | 원 1.1초 / 부채꼴 0.8초 | 1.2초 / 0.8초 |

알고리즘으로 남기는 것(15절):

- 늑대 돌진: 예고가 시작되는 순간 방향을 고정한다. 띠 폭 1.0, 돌진 속도 18, 발동 거리 3.5~5.5.
- 늑대 회피: 탄과의 최근접 거리와 도달 시간을 계산해 0.25초 안에 맞을 탄이면 수직으로 1.5칸 대시. 재사용 대기 1.5초. 추적 중에만 쓰고 예고·돌진·경직 중에는 쓰지 않는다.
- 선돌지기 철갑: 정면 120도로 받는 임계가 아닌 피해를 절반으로 줄인다. 빈틈 동안에는 줄이지 않는다. 꿰뚫는 창과 뇌광창은 무시한다. 꼬리표는 "중량"이다.
- 선돌지기 내려찍기: 플레이어 위치에 반경 2.5 원을 예고한다(사거리 8). 휩쓸기는 근접 3.0, 110도.
- 술사 엄폐: 체력이 절반 이하면 `엄폐물 위치 + normalize(엄폐물 − 플레이어) × 1.5`로 이동한다. 엄폐물은 선돌지기, 없으면 가시덩굴이다. 둘 다 없으면 거리를 벌린다.
- 동시 예고의 안전 경로 검사(R5): 전장을 0.5칸 격자로, 시간을 0.05초 단위로 끊어 너비 우선 탐색을 한다. 정수로만 계산한다.

웨이브와 보스:

- 하루 = 10웨이브: 낮 1~4, 해질녘 5~7, 밤 8~9, 보스 10. **[조율]**
- 보스는 10웨이브마다 순서대로 나온다: 웨이브 10 숯가마 멧돼지왕 "가마등", 20 스승의 허상, 30 포자 여왕 "천 갓", 40 폭풍 수리부엉이 "밤눈", 50 서리 산양 "흰뿔", 60 별밤 구렁이 "밤삼킴". 그 뒤로 반복한다. 보스 웨이브에는 일반 적, 엘리트, 변덕이 없다.
- **첫 보스는 스승의 허상이다 [확정: DECISIONS 1.21].** 프로필이 처음 닿는 웨이브 10에는 가마등 대신 허상이 나온다. 이 첫 만남은 이길 수 없는 싸움이다: 허상의 체력 바는 50%에서 멈추고, 싸움은 최대 45초이며, 어느 쪽으로든 플레이어가 쓰러지는 것으로 끝난다. 그동안 이동, 발사, 비기, 스쳐 피하기는 평소대로 된다.
- 첫 만남에서 쓰러져도 판은 끝나지 않는다. 체력을 회복해 웨이브 11로 간다. 그 웨이브의 점수는 고정값이라 순위에 유불리가 없다. 한 번 치르고 나면 그 프로필의 웨이브 10은 가마등이다. 오프라인 프로필도 똑같이 한 번 치른다.
- 허상은 웨이브 20의 진짜 보스로 다시 나오고, 처음 이기면 "복수" 보상(칭호, 계정에 묶인 꾸미기와 재료)을 받는다. 그 사이에는 화면의 복수 추적기가 목표를 계속 보여 준다. 수치와 절차의 기준은 `monsters.md` 3.9절, 연출은 `effects.md` 15.1절·15.2절, 화면은 `ui-assets.md` 4.26절이다.
- 스승의 허상은 플레이어 지팡이의 컴파일 결과를 복사해 쏜다(4절의 `Execute`를 진영만 바꿔 부른다).
- 체력 배율, 스폰 예산, 동시 예고 상한, 등장 순서, 야생의 변덕은 `monsters.md` 4절. 웨이브가 깊어져도 적의 이동 속도와 예고 시간은 변하지 않는다.
- 웨이브 6(첫날만)을 넘기면 영웅 블록 1장을 받는다. 그 판에서만 쓰는 빌린 블록이고 프로필로 가져갈 수 없다.
- 점수(후계 점수의 무한 웨이브 쪽 재료)는 `monsters.md` 4.8절.

## 12. 경제 (가리키는 줄)

골드, 블록, 강화 재료는 판에서 벌어 프로필에 남는다. 이 문서는 경제의 숫자를 적지 않는다. 숫자는 아래 문서에만 둔다.

| 내용 | 기준 |
|---|---|
| 처치 골드, 웨이브 클리어 골드, 보스 골드 | `monsters.md` 6.1절 |
| 블록 카드와 등급 확률 | `monsters.md` 6.2절 |
| 귀환 가방(판이 끝나고 블록을 몇 개 가져가는가, 영웅 블록 제한) | `monsters.md` 6.2절 |
| 강화석·부적의 드랍 | `monsters.md` 6.3절 |
| 시즌 주화, 한정 드랍, 체력 조각 | `monsters.md` 6.4절 |
| 야영의 회복 값과 다시 뽑기 값 | `monsters.md` 4.6절 |
| 강화 비용(골드 식, 강화석 구간), 슬롯 새기기 | `online.md` 1.3절, 1.5절 |
| 부적의 상점 값과 주간 한도, 변이 제거 값 | `online.md` 2.4절 |
| 시간당 수입, 골드가 사라지는 곳, +13까지의 시간(`monsters.md` 6절의 드랍 표로 돌린 시뮬레이션) | `online.md` 2절 |
| +0 새 지팡이의 값, 여러 자루를 갖는 규칙(개수 제한 없음) | `online.md` 2.4절, 1.6절 |
| 허상과의 첫 만남에서 받는 것, 복수 보상 | `monsters.md` 3.9.3절, 3.9.4절 |
| 거래와 장터의 수수료, 시즌 보상 | `online.md` 5절, 6절 |

드랍 수량이 `monsters.md`와 `online.md`에서 다르면 `monsters.md`가 맞고, `online.md`의 수입·시간 표는 그 값으로 다시 계산한 것이어야 한다.

이 문서에 남는 원칙:

- 판 중에 번 골드는 원정 지갑에 쌓이고, 판 중 지출(체력 회복, 전리품 다시 뽑기)은 원정 지갑에서만 낸다. 정산 때 남은 금액이 프로필로 들어간다.
- 남은 결정은 웨이브가 끝날 때 개당 5골드로 바뀐다.
- 보스를 잡은 뒤의 새벽 야영에서 체력 1칸을 무료로 회복한다.
- 건너뛴 웨이브, 보스의 졸개, 갈라진 개체, 불러낸 개체는 골드·드랍·점수를 주지 않는다.
- 강화 재료의 추첨은 판 씨앗이 아니라 정산 때 한다(서버 프로필은 서버가, 오프라인 프로필은 기기가). 좋은 씨앗을 골라 돌리는 일을 막기 위해서다. 블록 카드와 체력 조각은 판 안에서 바로 쓰므로 판 씨앗으로 뽑는다.
- 결제는 경제 어디에도 닿지 않는다. 전투, 강화, 드랍, 매칭 코드에 결제 여부를 보는 분기가 없다.

- 상단 중앙: "N일째 웨이브 M", 시간대 표식, 시간. 보스 웨이브에는 보스 이름·체력·격노. 복수 중인 프로필(허상과의 첫 만남을 치르고 아직 웨이브 20의 허상을 잡지 못한 프로필)에는 웨이브 11~19에서 "허상까지 n웨이브" 한 줄이 붙고 웨이브 20의 허상 이름 옆에 "복수" 꼬리표가 붙는다(복수 추적기, `monsters.md` 3.9.5절).
- 우상단: 골드(원정 지갑), 점수, 처치 수.
- 캐릭터 주변: 열 링(임계 시작 눈금 포함), 결정 칸(캐릭터에 따라 4~7칸), 콤보 숫자, 최근 입력 5개, "지금 K = 기술명(비용)", 시야 화살표. 그믐은 빚 결정을 보라 테두리의 빈 칸으로 표시하고 기술명 옆에 "외상 N"을 붙인다.
- 하단 중앙: 지팡이 회로. 실행 중인 블록이 순서대로 켜진다.
- 피해 숫자: 흰색(일반), 1.5배 크기 흰색 + 검정 굵은 테 + 느낌표(임계), 1.25배 + ▲ + 속성 문양(약점), 회청색 0.8배 + ▼(저항), 금색 +숫자(골드). 임계에 금색을 쓰지 않는다.
- 선택 표시는 노란 모서리 괄호로 통일.
- 줄일 수 없는 것: 적 예고, 적 탄, 열 링, 피격 표시, 시야 화살표. 옵션 목록은 `effects.md` 18절이 기준이다(내 탄 투명도, 피해 숫자, 연출 줄이기, 지팡이 효과 세 줄, 색각 보조 등).

전투(결투)에 더해지는 것: 상대 체력과 결정, 라운드와 남은 시간, 내 "마감 여유" 표시(초록·노랑·호박색 세 단계. 빨강을 비롯한 위험색은 쓰지 않는다. 그림은 `ui-assets.md` 4.9절), "입력이 회선 때문에 버려짐" 표시, 내 화면에만 보이는 0.5칸 조준선, 강화가 깎여 적용될 때의 이름표("+11 (적용 +9)"). 기준은 `online.md` 4절과 `effects.md` 17절.

야영 화면(3단): 왼쪽 지팡이 슬롯과 컴파일 트리 미리보기, 가운데 [조립 | 비기] 탭, 오른쪽 수치(발사당 열, 임계 사격 가능 횟수, 허수아비 DPS)와 다음 웨이브 정보(시간대, 변덕, 나올 적의 약점·저항 문양, 보스 이름, 확정 재료). 임계 사격 가능 횟수가 0이면 경고를 띄운다. **강화 탭은 없다.**

- 비기 탭: 그 캐릭터의 트라이 그림이 곧 커맨드 목록이자 해금 화면.
- 허수아비 연습: 결정 무한, 입력 간격 표시, 실패 원인 한 줄("K가 0.0x초 늦음" 등), 저스트 게이지. 메인 메뉴의 연습에서도 같은 것을 연다.
- 체력 회복, 전리품 다시 뽑기.

강화 화면 **[확정: 전용 화면]**: 마법진 위의 지팡이 큰 그림, 지팡이 고르기(그 프로필이 가진 지팡이 전부. 같은 캐릭터의 지팡이는 개수 제한이 없으므로 목록은 스크롤하고 정렬과 거르기를 둔다), 제물 칸 5개, 부적 칸, 큰 확률 숫자와 내역, 결과 띠, 기운, 역대 최고 단계와 하락 바닥, 기댓값, 변이 받기·제거, 슬롯 새기기, 흔적 공개 설정, 든 지팡이 정하기, 지팡이 떠나보내기(`online.md` 1.6절). 구성과 연출은 `effects.md` 1절.

그 밖의 화면: 타이틀(지금 어느 프로필인지 항상 표시), 로그인·가입(이메일 포함)·이메일 확인·비밀번호 다시 정하기(`online.md` 7.3절), 메인 메뉴(복수 중이면 복수 추적기), 캐릭터·지팡이 선택과 출발 조립, 시작 웨이브 선택, 서고, 옷장, 골드 상점(메인 메뉴의 "상점". 서버 프로필에서는 광장의 행상 수레도 같은 화면을 연다), 일시정지, 정산과 결과, 기록, 설정과 키 재설정. 서버 프로필에서 열리는 화면(광장, 장터, 거래, 결투 게시판과 방, 순위표, 친구와 채팅, 우편함, 시즌)은 `online.md`가 정한다. 오프라인 프로필에서는 그 메뉴를 흐리게 두지 않고 "서버에 접속하면 열립니다" 한 줄과 함께 묶어 둔다. 유료 상품이 0개면 상점에 유료 재화 탭, 잔액, 구매 버튼이 전혀 나오지 않는다.

튜토리얼: 첫 판 전 허수아비 방에서 5단계(이동·발사, 자세, 임계 사격, 반동 사격, 블록 끼우기). 하급 강화석을 처음 받은 정산(까마귀 보따리, `monsters.md` 표 6.3-A. 그 프로필에서 처음 웨이브 3을 넘긴 판) 뒤 강화 화면을 한 번 안내한다. 시작 재료가 0이므로 첫 판에서 웨이브 3을 넘기지 못하면 안내는 그 판이 나올 때까지 미룬다.

소리: 소리 목록은 `effects.md` 19절(공용)과 지팡이 문서(지팡이별 전용 소리)가 기준이다. 이 문서는 소리의 개수를 정하지 않는다.

이름의 표시: 화면에 찍는 캐릭터 이름, 지팡이 이름, 장소 이름, +13 칭호 같은 문자열은 글자를 박아 넣지 않고 이름 표(`world-characters.md` 0절)에서 id로 읽는다. 지금 캐릭터의 표시 이름은 "제자 1"~"제자 5"다 **[확정]**.

화면 그림: 이 절은 각 화면에 무엇이 어디에 놓이는가만 정한다. 그 화면에 필요한 그림의 목록과 크기(HUD 조각, 블록 아이콘 16종, 트라이 그림, 속성 문양, 리그 휘장, 메뉴와 창의 틀 등)는 `ui-assets.md`가 기준이다.

## 14. 아트

- 도트. 1칸 = 64px, 기준 화면 1920×1080, 그림 1픽셀 = 화면 1픽셀. 캐릭터 캔버스 64×64(dark_wizard 원본 크기), 적과 타일도 같은 배율. **[조율]** 32px 기준으로 적힌 크기가 남아 있으면 전부 2배로 읽는다.
- 플레이어는 3방향(아래, 옆, 위)만 그린다. 옆은 좌우 반전, 대각선은 옆 그림을 쓴다. 정확한 시야는 발밑 화살표가 알려 준다.
- 지팡이는 캐릭터 그림에 굽지 않고 별도 층으로 그려 손 위치에 붙인다. 손에 든 지팡이 캔버스 32×64, 강화 화면용 큰 그림 192×192, 목록과 장터의 아이콘 64×64(공통 규격의 기준은 `world-characters.md` 3.3절). 캐릭터 5 × 강화 14단계의 모양이 전부 다르다.
- `art/player/dark_wizard/`의 그림이 다섯 중 한 명(암흑, 그믐)이다. **[확정]** 원본 그림이 그믐과 그 지팡이의 +0 모습이다. 나머지 네 명은 같은 규격으로 새로 그린다(`art/player/`의 옛 시안 세 장은 32×32라 다시 그린다).
- 바닥은 시간대마다 색이 다르다(낮 탁한 이끼색, 해질녘 자두빛 갈색, 밤 남색). 바닥 명도는 35% 이하를 유지한다. 색 값은 `world-characters.md` 2.4절.
- 적의 색 규칙과 프레임 수는 `monsters.md` 1.4절과 9절.
- 예고 구역과 열 링은 그림이 아니라 셰이더나 도형으로 그린다.
- 그리는 층 순서는 `effects.md` 9.1절, 내 효과가 예고를 덮는 정도의 상한은 9.2절, 입자 예산과 넘쳤을 때의 처리는 9.3절이 유일한 기준이다. 지팡이 문서는 9.3절의 예산 안에서 단계별 몫만 적는다.
- 그림 목록: 캐릭터·전장·광장·돌마당은 `world-characters.md` 10절, 적은 `monsters.md` 9절, 효과는 `effects.md` 20절, 지팡이는 각 지팡이 문서, 화면 그림은 `ui-assets.md`.

결정론 코어 [조율]:

- 전투 규칙(이동, 컴파일러, 과열, 판정기, 적 AI, 스폰, 점수)은 유니티와 분리된 C# 라이브러리 하나에 넣는다. 그림과 소리는 그 밖에 있다.
- 실수 대신 고정소수점 정수로 계산하고 난수는 판 씨앗에서 갈라 낸 난수기만 쓴다. 같은 씨앗과 같은 입력 기록이면 기기와 서버에서 같은 결과와 같은 해시가 나와야 한다.
- 이 성질 하나로 세 가지를 한다: 무한 웨이브 기록을 서버가 다시 돌려 검증한다, 결투를 서버가 판정한다, 다시 보기를 만든다. 세부는 `online.md` 3절과 4.11절.

발표 구도: 지팡이 실행 트리와 입력 트라이, 트리 두 개가 게임의 양 축이다. 잡입력이 섞여도 기술이 인정되는 예(앞, 앞, 앞, K = 꿰뚫는 창)와 캐릭터마다 트라이에 가지가 하나씩 더 붙는 것(앞, 앞, 옆, K = 갈피의 베껴 쓰기)으로 실패 링크를 시연한다.

## 16. 만드는 순서

시간 제한은 두지 않는다. **[확정]** 이 문서들의 범위 전체를 만들며, 삭감은 하지 않는다. 아래는 일정이 아니라 의존 순서다. 1~9단계가 끝나면 서버 없이 완전한 게임이고, 10단계부터가 온라인이다.

1. **결정론 코어 위의 손맛 시제품** (회색 도형, 소리 없음)
   - 유니티 프로젝트와 git 준비, 입력 설정, 한글 입력기 확인
   - 전투 규칙 라이브러리(60틱, 고정소수점), 입력 이벤트 구조체와 순서 규칙, 입력 기록 저장과 다시 돌리기, 상태 해시. "같은 기록을 두 번 돌리면 해시가 같다"와 "같은 오프셋의 방향과 K는 방향이 먼저"를 자동 테스트로 둔다
   - 8방향 이동, 자세와 반전 자세, 시야 화살표 (기준값 캐릭터 = 갈피의 수치)
   - 고정 투사체 2종(마력탄, 화염구)과 3갈래 전환, 과열·임계·잠금·열 링
   - 슬라임 무한 생성, 3갈래 탄 포탑 1개, 체력과 무적, 스쳐 피하기
   - 판정기, 효과가 임시인 기술 3개(①②⑥), 섬 간격을 밀리초로 표시
   - 통과 기준: 두 번 누르는 커맨드 성공률 90% 이상, 10분 연습 후 섬 성공률 30% 이상, 임계 구간 플레이가 꾹 누르기보다 1.4배 이상 강함, 자세 중 이동하다 엉뚱한 기술이 나가는 비율 10% 미만. 통과하지 못한 축은 수치와 규칙을 고친 뒤 다음으로 넘어간다
2. **주문 컴파일러**: 블록 16종, 속성, 실행 트리, 안전장치, 단위 테스트, 트리를 글자로 출력하는 임시 조립기
3. **적과 웨이브의 뼈대**: 원형 4종(늑대 회피, 술사 엄폐 포함), 예고 구역, 웨이브 생성, 약점과 저항, 콤보와 결정, 디버그 메뉴(웨이브 건너뛰기, 무적, 골드·결정·블록 지급, 강화 단계 설정)
4. **야영 화면**: 조립(끌어다 놓기), 컴파일 트리 미리보기, 전리품 선택, 보관함, 허수아비 연습
5. **비기 전체와 캐릭터 5명**: 공용 10종의 실제 효과, 능력치 5벌, 패시브 5종, 고유 비기 5종, 캐릭터별 트라이, 비기 탭(트라이 그림), 연습장의 저스트 게이지와 실패 원인 표시. 1단계의 통과 기준을 캐릭터 다섯 명으로 따로 잰다
6. **프로필과 오프라인 백엔드**: `IBackend`, 규칙 라이브러리(강화·정산·상점), `OfflineBackend`. 이름 표(캐릭터·지팡이·장소·적의 id와 표시 이름을 한 곳에), 프로필, 서고, 지팡이 개체(같은 캐릭터의 여러 자루를 개수 제한 없이 보관, 보관 목록의 정렬·거르기, +0 새 지팡이 구입 포함), 출발 조립, 원정 지갑과 정산, 귀환 가방, 드랍, 비기 해금 저장, 상점
7. **강화 화면**: 제물, 결과 분기, 변이 6종, 부적, 슬롯 새기기, 기댓값 계산과 표시, 하락 흔적, 결과 꾸러미, 공통 연출
8. **무한 웨이브 완성**: 신규 8종, 꼬리표, 엘리트, 보스 6종, 허상과의 첫 만남(쓰러져도 이어지는 웨이브 10)과 복수 보상·복수 추적기, 하루와 시간대, 야생의 변덕, 안전 경로 검사(R5), 시작 웨이브 고르기, 점수, 기기 안의 기록 표

## 17. 조정 방침과 QA에서 먼저 볼 항목

수치는 이 문서들의 값으로 먼저 개발하고, 개발이 된 뒤 QA를 진행하면서 조정한다. **[확정]**

이 문서 범위에서 먼저 볼 항목:

1. 과열 리듬(냉각, 잠금 시간)과 "임계 구간 ÷ 꾹 누르기" 비율. 캐릭터 다섯 명 각각.
2. 비기의 결정당 피해. 공용 10종과 고유 5종을 같은 표로 잰다. 결정 환전 금액(개당 5골드)과 결정이 쌓이는 속도.
3. 커맨드 입력 간격(0.07초 섬, 만개 0.18초, 0.2초 구간들)과 캐릭터별 오입력 비율. 달구의 "뒤, 뒤"와 그믐의 "좌, 우"를 따로 본다.
4. 새 블록 4종: 얼음 송곳·서리의 감속이 회피 보장 규칙과 보스전에 주는 영향, 잠식 +15%와 그림자 계약이 겹쳤을 때의 화력.
5. 강화 배율 ×1.15와 적 체력 곡선의 만남(+13 지팡이가 기준 난이도를 만나는 웨이브).
6. 변이 조합별 허수아비 DPS(초롱은 3개 조합).
7. 비기 해금 속도(두 판이면 공용 8종이 다 모이는 것이 너무 빠른지).
8. 허상과의 첫 만남(`monsters.md` 3.9절): 쓰러지기까지 실제로 걸리는 시간, 45초를 다 버티는 사람의 비율, 진 것이 억울하지 않고 갚고 싶어지는지. 그리고 첫 만남에서 첫 복수까지 걸리는 플레이 시간.

다른 문서의 QA 항목: 강화 경제와 +13까지의 시간은 `online.md` 12절, 회피 검산은 `monsters.md` 8절, 캐릭터 균형과 결투 상성표는 `world-characters.md` 5절, 가독성 판은 `effects.md` 16.4절.

## 19. 온라인 구조 (요약)

기준은 `online.md`다. 핵심 시스템이 지켜야 하는 것만 적는다.

- **프로필 두 가지 [조율]:** 오프라인 프로필(기기 안, 계정 불필요)과 서버 프로필(맥미니의 DB). 서로 섞이지 않는다. 오프라인 진행은 순위와 거래에 반영되지 않고 서버로 옮길 수 없다.
- **오프라인 프로필에서 되는 것:** 무한 웨이브, 조립과 서고, 강화 화면(슬롯 새기기와 변이 제거 포함), 골드 상점, 연습, 개인 기록. 서버 프로필과 같은 규칙, 같은 확률이다. 없는 것: 광장, 거래, 사람 상대 결투, 시즌, 서버 알림.
- **구현 규칙:** 게임 로직과 화면은 `IBackend`만 부른다. `IBackend`에는 "프로필 종류"가 있고 화면은 그것을 보고 메뉴를 정한다. 강화·정산·상점의 규칙 코드는 서버와 오프라인 구현이 같은 소스를 쓴다. `OfflineBackend`를 먼저 만든다.
- **서버 [확정]:** 맥미니 한 대에 직접 올린다. 계정은 자체 계정(아이디와 비밀번호)이다. 스팀 기능에 기대지 않는다. 가입할 때 이메일을 받고, 비밀번호를 잃으면 이메일로 복구한다. 복구 메일은 외부 메일 사업자를 거쳐 보내고, 메일을 연결하지 않아도 게임과 로그인은 그대로 된다(복구만 안 된다. `online.md` 7.3절).
- **무한 웨이브:** 서버 프로필의 판은 판마다 서버가 씨앗을 주고, 끝나면 입력 기록을 올려 서버가 같은 코어로 다시 돌려 확인한다. 모두 같은 씨앗으로 겨루는 "주간 도전"은 후계 점수에 들어가지 않는 별도 순위표다. 오프라인 프로필은 기기가 씨앗을 만든다.
- **결투 [조율]:** 서버가 시뮬레이션하고 판정한다. 클라이언트가 보낸 입력의 시각과 순서를 서버가 검증한다. 결투 체력은 100 × 체력 칸 수이고 "+1칸"은 +100이다. 스쳐 피하기 인정과 피격 벌칙은 1.0초에 1회다. 비기는 판정 뒤 준비 2틱 후 발동한다. 상대 화면에는 내 탄 장식을 가장 단순한 형태로 보여 주고 지팡이 본체는 실제 단계 모양 그대로 보인다. 공통 규칙의 기준은 `online.md` 4절, 캐릭터마다 다른 값의 기준은 `world-characters.md` 5.4절이다.
- **리그 [확정]:** 자동 매치는 소지한 아이템의 레벨로 나눈 리그 3개(새싹, 맹수, 후계)를 쓴다. 실력 기준이 아니다.
- **광장 [확정]:** 만남, 거래, 결투 신청, 친구, 채팅. 서버 전체 채팅 채널은 없다. 강화 장소와 강화 NPC도 없다.
- **거래 [확정]:** 주문 블록, 꾸미기, 강화 재료와 부적, 강화된 지팡이를 거래한다. 후계자 칭호와 전용 겉모습은 계정에 묶인다. 거래로 받은 지팡이는 그 캐릭터의 지팡이로 보관된다. 같은 캐릭터의 지팡이는 개수 제한 없이 가지며, 거래 조건과 장터 등록 한도는 `online.md` 1.6절·5.5절이 정한다.
- **시즌 [확정]:** 후계 점수(무한 웨이브 점수와 결투 점수의 합산) 1위가 후계자다.
- **결제 [확정]:** 지금은 넣지 않는다. 연결만 하면 되는 구조(주문 중심, 제공자 인터페이스)로 두고, 연결하지 않아도 모든 기능이 동작한다. 유료 상품이 0개면 화면에 결제의 흔적이 없다.

## 개발자 확인 필요

모든 문서의 "개발자 확인 필요"를 모아 겹치는 것을 합쳤다. `DECISIONS.md`가 이미 답한 것(64px 배율, 10웨이브 하루, 강화는 전용 화면, 리그는 소지 아이템 기준, 서버 전체 채팅 없음, 후계자 보상 귀속, 스팀 없음, 지팡이는 그 캐릭터만, 그믐 지팡이는 보라 결정에서 시작 등)은 여기에 없다. 아래는 취향이나 방향이라 개발자가 정할 것이고, **각 항목의 "지금 값"이 본문에 이미 적용되어 있다.** 괄호는 그 값이 적힌 문서(그 값의 주인)다. 번호는 바꾸지 않는다(다른 문서가 "GDD 개발자 확인 필요 23번"처럼 번호로 가리킨다). 41~46번은 문서 사이의 충돌을 0절의 주인 규칙으로 정리하면서 나온 것으로, 주인 문서의 값이 "지금 값"이고 반대쪽 안이 대안이다. 47~57번은 주인 문서가 그 뒤에 자기 목록에 올린 것을 옮겨 온 것이고, 58~68번은 마지막 정리에서 문서 사이에 남아 있던 것을 올린 것이다.

**DECISIONS 1.20~1.25로 답이 나서 뺀 항목:** 1번(첫 보스 → 스승의 허상), 5번(고유 비기 → 처음부터 쓴다), 7번(+13까지의 시간 → 지금 설계 그대로 65~90시간), 11번(비밀번호 분실 → 이메일로 복구), 45번(같은 캐릭터의 지팡이 → 개수 제한 없음). 이 다섯 번호에는 "확정되어 뺐다" 한 줄만 남긴다(목록의 번호가 밀리지 않게 하기 위해서다). 이름(1.25)은 이 목록에 항목이 없었다. 그 결정들을 본문에 옮기면서 새로 정한 제안값은 맨 끝의 69번부터 적었다.
