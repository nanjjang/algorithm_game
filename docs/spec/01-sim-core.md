# 01. 결정론 코어 · 입력 · 이동 · 자세 · 과열 · 스쳐 피하기 · 콤보 · 결정 — 구현 명세서

게임: "엄청엄청 위대한 마법사 키우기". 이 명세는 구현자가 원본 기획 문서를 다시 읽지 않고 이 영역을 만들 수 있게 원본의 규칙과 수치를 옮기고, 데이터 구조, 상태 기계, 의사코드, 경계 조건, 테스트 벡터를 더한 것이다.

## 0. 이 문서를 읽는 법

### 0.1 우선순위

1. `docs/DECISIONS.md`가 모든 문서보다 우선한다. 이 명세가 원본끼리의 충돌을 정리한 결과는 15절에 있다.
2. 그다음은 각 내용의 "주인 문서"다(GDD 0절의 문서 지도). 이 영역의 주인은 이렇다.
   - 조작, 과열, 스쳐 피하기, 콤보와 결정, 결정론 코어 원칙: `GDD.md` 3·5·6·7·15절
   - 결정론 코어의 기술 규격(Q32.32, PCG, 입력 이벤트 구조체, 순서 규칙): `online.md` 3.1절
   - 캐릭터별 능력치, 패시브, 외상, 결투 캐릭터 수치: `world-characters.md` 4절·5절(5.4절은 결투 캐릭터 수치의 유일한 기준)
   - 결투 공통 규칙: `online.md` 4.1~4.4절, 4.11절
   - 열 링, 스침, 콤보, 결정의 표시: `effects.md` 10~11절
   - 하루와 웨이브: `DECISIONS.md` 2.3
3. 이 명세 자체가 새로 정한 값은 [임시]로 표시했고, 원본이 정하면 원본이 맞다.

### 0.2 표시

| 표시 | 뜻 |
|---|---|
| [확정] | 개발자가 직접 정한 것(DECISIONS 1절, 원문의 [확정]) |

### 0.3 범위

이 명세가 만드는 것:

- 결정론 코어의 바탕: 시간(틱), 고정소수점, 난수, 결정론 자료구조, 상태 해시, 입력 기록과 다시 돌리기, 틱 처리 순서
- 입력: 논리 키, 입력 이벤트 구조체, 정렬 규칙, 키 상태
- 이동, 시야(8방향), 자세, 반전 자세, 벽 충돌, 이동 속도 배율
- 플레이어 체력, 피격, 무적(이 영역의 상태와 맞물리는 만큼)
- 과열(열, 임계, 잠금, 냉각)과 열에 닿는 모든 예외(밑줄, 불가마, 변이 4종, 방열 폭발, 스침)
- 스쳐 피하기
- 콤보
- 마력 결정, 그믐의 빚, 별똥 결정, 웨이브 종료 환전
- 하루와 웨이브 번호 계산
- 결투 모드에서 위 시스템이 바뀌는 곳(코어 스위치)

이 명세가 만들지 않는 것(다른 명세가 주인이고 여기서는 인터페이스만 정한다): 주문 컴파일러와 피해 공식 전체, 커맨드 판정기(트라이), 비기 효과, 적 AI·스폰·예고, 강화, 경제, 서버, 화면과 그림과 소리.

시각적 요소(GUI, 스프라이트, 이펙트, 소리)는 에셋이 없으므로 구현하지 않는다. 코어는 표시 계층이 구독할 이벤트만 낸다(17절).

## 2. 단위와 수치 표현

### 2.1 시간

- 게임 시간은 고정 60틱이다. 1틱 = 1/60초 ≈ 16.667ms. [조율] (GDD 머리말, GDD 15, online 3.1)
- 입력 시각은 `InputTime = tick × 256 + offset`의 정수다. 1단위 = 1/15,360초. 간격은 정수로 비교한다. [조율] (GDD 8 판정기)
- 실제 시각 표시용 환산: `(tick + offset ÷ 256) × 16.667ms` (online 3.1). 코어 판정에는 쓰지 않는다(15절 충돌 C5).
- 초 → 틱 환산: `ticks = round(sec × 60)`. 원문의 모든 시간 값은 정수 틱으로 떨어진다(아래 표).
- 초 → 입력 시각 환산: `units = round(sec × 15360)`. 원문 값: 0.07초 = 1,075 / 0.18초 = 2,765 / 0.2초 = 3,072 / 0.25초 = 3,840 / 0.3초 = 4,608 (GDD 8). 이 명세가 더한 값: 0.08초 = 1,229, 0.1초 = 1,536, 0.4초 = 6,144.
- 히트스톱, 화면 흔들림, 시간대 색 전환은 표시 계층의 일이고 게임 시간(틱)은 멈추지 않는다. [조율] (GDD 3, online 3.1)
- 틱 번호 `uint`는 60틱에서 약 828일까지 센다. 판 하나가 넘을 일은 없다.

### 2.2 고정소수점 `Fix64` (Q32.32)

[조율] (online 3.1: "실수 대신 고정소수점(Q32.32 정수)") / 연산 규칙 [임시]

```csharp
public readonly struct Fix64 : IComparable<Fix64> {
    public readonly long Raw;          // 값 = Raw / 2^32
    public const int FracBits = 32;
    public static readonly Fix64 One = new Fix64(1L << 32);
    public static Fix64 FromInt(int v) => new Fix64((long)v << 32);
    public static Fix64 FromRatio(long num, long den);   // round-half-away-from-zero, 빌드 때 상수용
    // +, - : Raw 끼리 더하고 뺀다(오버플로는 검사 모드에서 예외, 배포 빌드에서는 래핑하지 않도록 범위를 설계로 보장)
    // * : 64×64→128비트 곱 후 산술 오른쪽 시프트 32 (내림, 음의 무한대 쪽)
    // / : (a.Raw << 32) / b.Raw 를 128비트로 계산, 0 쪽으로 버림
    // Sqrt : 정수 제곱근(비트 단위 이분법). 실수 함수 금지
    // Sin/Cos : 빌드 때 만든 표(각도 단위 1/65536 바퀴, 4096칸 + 선형 보간) — 실행 중 float 금지
}
```

- `float`, `double`, `Mathf`, `System.Math`의 실수 함수는 코어에서 쓰지 않는다. 상수는 빌드 때 유리수에서 Raw로 바꿔 소스에 박는다. [임시]
- Unity가 쓰는 .NET 표준 라이브러리에 `Int128`이 없을 수 있으므로 128비트 곱은 직접 구현한다(`Math.BigMul`이 있으면 그것을 쓴다). [임시]
- 범위: 정수부 ±2,147,483,647. 좌표(0~24), 속도, 피해 배율은 충분하다.
- 자주 쓰는 상수(Raw):

| 상수 | 값 | Raw |
|---|---|---|
| `INV_SQRT2` | 1/√2 | 3,037,000,500 |
| 0.15 (피격 반지름) | | 644,245,094 |
| 0.30 (결투 피격 반지름, 몸 반지름) | | 1,288,490,189 |
| 0.4 (판정 중심 오프셋) | | 1,717,986,918 |

### 2.3 거리와 속도

- 거리는 칸 단위 `Fix64`. 1칸 = 64px (DEC 2.1). 피격 판정, 사거리 같은 게임 수치는 칸 단위 그대로다 [조율] (DEC 2.1).
- 속도는 원문이 칸/초로 적는다. 코어는 **틱당 이동량**을 쓴다.
- 속도 데이터는 소수 둘째 자리까지의 "센티 칸/초" 정수(`SpeedCenti`)로 저장한다. 4.7 → 470. [임시]
- 틱당 이동량(축 방향): `vRaw = round(SpeedCenti × mulPermille × 2^32 / (6000 × 1000))`. `mulPermille`은 배율의 천분율(1.0 → 1000, +20% → 1200, −30% → 700).
- 대각선 한 축의 이동량: `vDiagRaw = (vRaw × INV_SQRT2) >> 32`. 대각선 이동의 실제 속력은 축 이동과 같다(정규화). [임시]

### 2.4 열의 단위 `HeatHu`

[임시] 열은 `Fix64`가 아니라 **정수 `int`, 열 1 = 120 HU**로 든다.

이유: 원문의 모든 열 연산이 이 단위에서 정확히 정수로 떨어진다. 분열 배수 ×1.6, ×2.2, 거울상 ×1.5, 냉각 초당 45·50과 그 절반(탐식), 탐식의 초당 −20이 전부 나머지 없이 계산된다. Q32.32로 초당 50을 60틱으로 나누면(0.8333…) 반올림 오차가 쌓여 임계 경계(정확히 85, 정확히 100) 판정이 원문 검산값과 달라질 수 있다.

### 3.3 난수: PCG32와 갈라 내기

[조율: PCG 계열, 씨앗 하나에서 갈라 낸다] (online 3.1, GDD 9, GDD 15) / [임시: 세부]

- 생성기: PCG32 (XSH-RR, 64비트 상태, 32비트 출력). 곱수 `6364136223846793005`.
- 초기화(`pcg32_srandom_r`과 같다): `inc = (seq << 1) | 1; state = 0; next(); state += seed; next();`
- 출력: `old = state; state = old × M + inc; xs = ((old >> 18) ^ old) >> 27; rot = old >> 59; return (xs >> rot) | (xs << ((−rot) & 31))`
- 갈라 내기: 판 씨앗 `run_seed`(64비트) 하나에서 용도별 생성기를 `new Pcg32(seed: run_seed, seq: StreamId)`로 만든다. 용도마다 다른 `seq`이므로 서로 다른 수열이다.
- 용도 목록과 고정 `StreamId`:

| StreamId | 이름 | 쓰는 곳 | 출처 |
|---|---|---|---|
| 1 | `Waves` | 웨이브 구성, 스폰 | mon 4.4, mon 7 |
| 2 | `Cards` | 전리품 카드 | mon 6.2 |
| 3 | `Mutation` | 변이의 난수(불안정 핵 5%, 뒤틀린 총열 ±25도) | GDD 9 |
| 4 | `EnemyAi` | 적 AI의 무작위 선택 | |
| 5 | `Starfall` | 별똥 결정의 발생과 자리 | wc 2.3 |
| 6 | `Weather` | 소나기·안개 같은 연출 사건(규칙 영향 없음이지만 다시 보기에서 같게) | wc 2.3 |
| 7~31 | 예약 | | |

- 표시 계층(입자, 흔들림)은 코어 생성기를 쓰지 않는다. 표시용 난수가 코어 수열을 소모하면 다시 돌릴 때 결과가 달라진다. [임시]
- 정수 범위 뽑기 `NextInt(n)`: 편향 없는 거부 방식(Lemire 또는 `threshold = (−n) % n` 방식) 하나로 고정한다. 확률 판정 `Chance(permille)`: `NextInt(1000) < permille`. [임시]

### 3.4 상태 해시

[조율: 상태 해시가 있다] (GDD 15, GDD 16 1단계, online 3.2, online 4.11) / [임시: 알고리즘]

- 알고리즘: FNV-1a 64비트. 시작값 `0xcbf29ce484222325`, 곱수 `0x100000001b3`, 바이트마다 `h ^= b; h *= prime`.
- 입력: 시뮬레이션 상태의 정규 직렬화(리틀 엔디언, 필드 순서 고정, 개체는 id 순). 표시 전용 값(그림 프레임 등)은 넣지 않는다.
- 해시에 들어가는 이 영역의 필드: 틱, 플레이어마다 `PlayerState` 전체(3.9절의 표), 키 상태, 난수기 상태 전부, 별똥 상태.
- 언제 계산하는가: 무한 웨이브는 5웨이브마다의 중간 지점과 판 끝(online 3.2). 결투는 30틱마다(online 4.11). 디버그 빌드는 매 틱 남길 수 있게 한다.
- 다시 돌리기 검증: 같은 씨앗과 같은 입력 기록을 두 번 돌리면 모든 해시가 같아야 한다(GDD 16 1단계의 자동 테스트).

### 3.6 입력 기록과 다시 돌리기

[조율: 입력 기록 저장과 다시 돌리기, 상태 해시] (GDD 16 1단계, GDD 15) / [제안] (online 3.2)

- 판 기록 = 판 시작 정보 + 입력 이벤트 열 + (야영 명령 열) + 중간 지점 목록.
- 판 시작 정보: `run_id`, 씨앗, 지팡이·조립 상태, 시작 웨이브, 코어 버전, 이 판의 웨이브 10이 허상과의 첫 만남인지(`phantom_first`), 캐릭터 id. (online 3.2)
- 중간 지점: 5웨이브마다 (틱, 상태 해시, 점수, 원정 지갑, 그때까지의 입력 기록). (online 3.2, GDD 2.2)
- 입력 기록 크기 목표: 1시간에 약 150KB (online 3.2). 저장 형식 [임시]: 틱 차이를 가변 길이 정수(LEB128)로, 이어서 오프셋 1바이트, (키 4비트 + 누름/뗌 1비트) 1바이트. 순번은 저장하지 않고 읽을 때 1부터 다시 매긴다(정렬 규칙상 순번이 기록 순서와 같다, 4.3절).
- 야영 명령(조립 바꾸기, 카드 고르기, 회복, 비기 고르기)은 키 이벤트가 아니므로 별도의 `CampCommand` 열로 기록한다. 형식은 야영 명세의 몫이다. 코어는 "웨이브 n의 야영에서 이 명령들이 이 순서로 적용됐다"만 받는다. [임시]
- 일시정지: 일시정지 중에는 틱이 진행하지 않는다. 일시정지 시작은 `LogicalKey.Pause` 누름 이벤트로 기록하고(커맨드 초기화가 기록에 남아야 하므로, GDD 8) 풀리는 틱에 키 상태 차이를 이벤트로 만든다(일시정지 중에 뗀 키는 풀린 틱의 오프셋 0에 뗌 이벤트). 판당 누적 일시정지 실제 시간은 따로 기록한다(순위 대상 판은 누적 10분까지, online 3.4). [임시: 기록 방식]
- 다시 보기는 같은 기록을 같은 코어로 돌린 것이다.

### 3.8 틱 처리 순서

[임시] 원문은 한 틱 안의 처리 순서를 정하지 않았다. 아래 순서를 코어의 유일한 순서로 고정한다. 다른 명세의 단계(적, 컴파일러, 비기)는 표시한 자리에 끼운다.

```
SimWorld.Step(tick t):
  1. 시간 만료 처리 (t에 끝나는 것들)
     - HeatSystem.ProcessUnlock(t)          // 잠금 풀림 → 열 0  (7.5)
     - 무적, 가속, 결투 벌칙 창, 유리 지팡이 꺼짐 같은 기한 값은 "t >= until"로 읽으므로 따로 할 일 없음
  2. 입력 이벤트 적용: 유효 틱이 t인 이벤트를 4.3의 순서로 하나씩
     - KeyState 갱신 (누름/뗌)
     - StanceSystem.OnKeyEvent(e)           // 자세 진입·해제·반전, 커맨드 초기화 신호 (5.5)
     - FacingSystem.OnKeyEvent(e)           // 시야, 대각 유지 창 (5.3, 5.4)
     - Judge.OnDirectionPress / OnKPress    // 판정기 명세. 시각 = e.InputTime
     - Pause 이벤트
  3. FacingSystem.ResolvePending(t)         // 대각 유지 창 만료 (5.4)
  4. MovementSystem.Integrate(t)            // 이동과 벽 (5.6)
  5. 비기 발동 [판정기·비기 명세]           // 이번 틱에 판정된 K. 결투는 준비 2틱 뒤
  6. HeatSystem.TryFire(t)                  // J 발사, 열, 임계, 잠금 (7.3)
     - Compiler.Execute(...)  → 탄 생성
  7. 적 AI, 적 탄 생성 [적 명세]
  8. 탄·적·구역 이동과 충돌 [컴파일러·적 명세]
     - 플레이어 탄 → 적 적중: ComboSystem.OnPlayerHit (9.2), 피해 계산
     - 적 탄/돌진/접촉 → 플레이어: PlayerHealth.OnHit (6.2)
     - 스침 판정: GrazeSystem.Detect (8.3)  ← 같은 틱의 피격 판정 뒤
     - 예고 구역 폭발: 피격 판정 → 스침 판정
     - 별똥 줍기 (10.5)
  9. 처치 처리 [적 명세] → 탐식 열 감소 (7.6.5)
 10. 틱 끝 갱신
     - HeatSystem.Cool(t)                   // 냉각 (7.4)
     - ComboSystem.TickIdle(t)              // 콤보 끊김 타이머 (9.3)
     - StarfallSystem.Tick(t)               // 별똥 예고·착지·만료 (10.5)
 11. (해시 계산 시점이면) StateHasher
```

## 4. 입력

### 4.1 조작 [확정] (DEC 1.19, GDD 3)

| 키 | 기능 |
|---|---|
| WASD | 이동. 이동 방향 = 시야 = 발사 방향 (8방향) |
| J | 발사. 누르고 있으면 연사 |
| K | 비기 전용 |
| Shift (누르는 동안) | 자세: 시야를 잠그고 느려진 속도로 이동 |
| Space (누르는 동안) | 반전 자세: 시야를 180도 뒤집어 잠금 |

- 전투는 키보드만 쓴다. [확정] (DEC 1.19, GDD 1) 메뉴(야영, 강화 화면, 광장 메뉴)는 마우스를 쓸 수 있고 키보드만으로도 된다. (GDD 1)
- 대체 배치: 방향키 + Z 발사 / X 비기 / C 자세 / V 반전. 전 키 재설정 가능. [제안] (GDD 3)
- 키는 물리 키 기준으로 읽고, 전투 중에는 한글 입력기의 영향을 받지 않아야 한다. 에디터가 아니라 빌드에서 확인한다. [제안] (GDD 3, GDD 16 1단계 "한글 입력기 확인")
- 대시는 없다. [제안] (GDD 3)
- 광장에서는 같은 조작으로 걷고 발사와 비기는 꺼진다. (wc 2.5) → 코어 스위치 `SimConfig.FireEnabled = false`, `SkillEnabled = false`.

### 4.2 논리 키와 물리 키

코어는 **논리 키**만 안다. 물리 키 → 논리 키 변환은 유니티 쪽 `IInputSource`가 한다. [임시]

```csharp
public enum LogicalKey : byte {   // 4비트 (online 3.1: 키 코드 4비트)
    Up = 0, Left = 1, Down = 2, Right = 3,   // W A S D  / 방향키
    Fire = 4,        // J / Z
    Skill = 5,       // K / X
    Stance = 6,      // Shift / C
    Reverse = 7,     // Space / V
    Pause = 8,       // Esc (전투 중 일시정지)
    // 9~15 예약
}
```

- 한 논리 키에 물리 키가 둘 이상 묶여 있으면(예: W와 방향키 위), 묶인 물리 키 중 하나라도 눌려 있으면 논리 키가 눌린 것이다. 논리 키 상태가 **바뀔 때만** 이벤트를 만든다(W를 누른 채 방향키 위를 눌러도 이벤트 없음). [임시]
- 유니티 쪽은 OS 키 이벤트의 하드웨어 시각을 받아 그 시각이 속한 틱과 틱 안 오프셋을 계산한다. 프레임 단위로 읽지 않는다(GDD 8 판정기: "프레임 단위로 읽지 않는다"). 하드웨어 시각을 얻지 못하는 플랫폼에서는 이벤트를 받은 시각을 쓴다. [임시]
- 무한 웨이브에서 유효 틱 = 누른 순간이 속한 틱 + 0. 결투에서는 + D(입력 지연, 2~4틱. online 4.11). 오프셋은 보존한다.

### 4.3 입력 이벤트 구조체 [조율] (GDD 3, online 3.1)

원문: 이벤트 = `(유효 틱, 틱 안 오프셋 8비트(1/256틱), 키 코드 4비트, 누름/뗌 1비트, 플레이어별 순번)`. 한 틱에 최대 8개.

```csharp
public readonly struct InputEvent {
    public readonly uint Tick;        // 유효 틱
    public readonly byte Offset;      // 0~255, 1/256틱
    public readonly LogicalKey Key;   // 4비트
    public readonly bool Down;        // 누름 true / 뗌 false
    public readonly uint Seq;         // 플레이어별 순번. 1부터 1씩 증가
    public long Time => (long)Tick * 256 + Offset;   // InputTime, 1단위 = 1/15,360초
}
```

- 패킷·기록 안의 비트 배치 [임시]: `Key`(4) + `Down`(1) + 예약(3) = 1바이트, `Offset` 1바이트, `Tick`은 패킷 머리의 기준 틱과의 차이(가변 길이), `Seq`는 패킷 머리의 시작 순번 + 목록 안 위치.
- 한 틱에 최대 8개 (online 3.1, 4.11). 결투에서는 넘는 것을 서버가 버린다. 무한 웨이브의 기록기는 9번째부터를 다음 틱의 오프셋 0으로 미루지 않고 **버리고 진단 표시를 남긴다**(사람 손으로는 한 틱 16.7ms에 키 상태 변화 9번이 나오지 않는다). [임시]

**정렬 규칙** [조율] (GDD 3, online 3.1, online 4.11):

- 이벤트는 (유효 틱, 오프셋, 순번) 순으로 처리한다.
- 같은 틱, 같은 오프셋에 방향과 K가 같이 들어오면 **방향이 K보다 먼저**다. 판정기, 판 재실행 검증, 결투가 모두 이 순서를 쓴다. 이 규칙은 코어 안에 있다. (섬은 "방향이 먼저, 0.07초 안에 K"이므로 이 규칙이 없으면 기록을 다시 돌릴 때 다른 기술이 나갈 수 있다.)

두 문장을 한 비교 함수로 합친다 [해석] (15절 C4):

```
정렬 키 = (Tick, Offset, KeyClass, Seq)
KeyClass: Stance·Reverse = 0 [임시], Up·Left·Down·Right = 1, Fire = 2 [임시], Skill = 3, Pause = 4 [임시]
```

- 확정된 것은 "방향(1) < K(3)"뿐이다. 자세 키를 방향보다 앞에 둔 것은, Shift와 앞을 같은 순간에 눌렀을 때 그 앞이 커맨드로 읽히게 하려는 [임시] 값이다(자세 밖의 방향은 커맨드가 아니다, GDD 8).
- 클라이언트는 같은 오프셋 안에서 이 순서로 정렬한 뒤 순번을 매긴다. 그래서 정직한 기록에서는 순번 순서와 정렬 순서가 항상 같다. 서버는 같은 규칙으로 다시 정렬한다(online 4.11 "서버가 같은 규칙으로 다시 정렬한다").
- 서버의 순서 검증: (유효 틱, 오프셋, 순번)이 늘어나는 순서여야 하고 순번은 1씩 는다. 이미 봉인된 틱의 이벤트는 받지 않는다 (online 4.11). 키 상태 검사: 눌린 키의 누름, 안 눌린 키의 뗌은 무시한다 (online 4.11) — 코어의 `KeyState`도 같은 규칙으로 무시한다.

### 4.4 키 상태와 "누른 순간"

- `KeyState`: 논리 키 9개의 눌림 여부 비트 + 키마다 마지막 누름 시각 `long`.
- 커맨드는 키를 **누르는 순간만** 본다. 이미 누르고 있던 방향키는 입력이 아니므로 쓰려면 뗐다가 다시 눌러야 한다. (GDD 8) → 판정기에는 `Down = true` 이벤트만 넘긴다.
- `JPressedThisTick`: 이번 틱에 Fire 누름 이벤트가 있었으면 참. 같은 틱 안에 누르고 뗀 J도 이번 틱의 발사 조건을 만족한다(7.3). [임시]
- 커맨드 초기화 신호(판정기로): 자세 진입, 자세 해제, 반전, 일시정지 (GDD 8). 5.5절의 상태 기계가 `CommandReset(reason)`을 낸다.

### 5.2 방향과 이동 벡터

```csharp
public enum Dir8 : byte { E = 0, NE = 1, N = 2, NW = 3, W = 4, SW = 5, S = 6, SE = 7 }   // 반시계, 45도 단위
```

- 좌표계: 왼쪽 위 (0,0), 오른쪽 아래 (24,14). x는 오른쪽, **y는 아래쪽이 +**. 전장 한가운데 (12.0, 7.0). (wc 2.6의 돌마당 좌표 규약을 무한 웨이브 전장에도 쓴다) [임시: 무한 웨이브 전장 적용]
- `N` = 화면 위 = (0, −1). `Dir8` → 단위 벡터: 축 방향은 (±1, 0), (0, ±1). 대각은 (±INV_SQRT2, ±INV_SQRT2).
- 180도 뒤집기: `Flip(d) = (d + 4) & 7`.
- 이동 입력 → 방향 [임시]:
  - 가로축: Left만 눌림 → −1, Right만 → +1, 둘 다 → **나중에 누른 쪽**(마지막 누름 시각이 큰 쪽), 둘 다 아님 → 0.
  - 세로축: Up/Down도 같은 규칙.
  - (가로, 세로) = (0,0)이면 이동 없음. 그 밖이면 `Dir8`.
- 8방향만 움직인다. 자유 조준은 없다 (GDD 3, mon 1.2, GDD 10.3 "자유 조준이 없으므로").

### 5.3 시야(Facing) 상태 기계

[확정: 이동 방향 = 시야 = 발사 방향 (DEC 1.19)] / [제안: 세부 (GDD 3)]

상태: `Stance ∈ {None, Stance, Reverse}` × `Facing`.

| 상태 | 시야 규칙 |
|---|---|
| `None`, 이동 입력 있음 | `Facing = 이동 방향` (단, 5.4의 대각 유지 창 동안은 대각 유지) |
| `None`, 이동 입력 없음 | `Facing` 그대로 |
| `Stance` / `Reverse` | `Facing = StanceLockedFacing` (상하좌우 4방향 중 하나). 이동 입력은 시야를 바꾸지 않는다 |

- 발사 방향은 항상 `Facing`이다. 자세 중에는 대각 사격이 없다 (GDD 3).
- 결투 한정 예외: J 발사와 방향이 있는 비기는 상대 쪽으로 최대 10도까지 조준 보정 (12절).
- `LastPressedCardinal`: Up/Left/Down/Right 누름 이벤트마다 그 방향으로 갱신한다.
- 시야 화살표는 항상 발밑에 표시한다. 평소 반투명, 자세 중 불투명, 반전 중 다른 색 (GDD 3). → 코어는 `FacingArrowMode {Normal, Stance, Reverse}`를 상태로 낸다(17절).

### 5.4 대각 시야 유지 창 (0.08초)

원문: "대각 이동 중 두 키를 0.08초 안에 차례로 떼면 대각 시야를 유지한다." [제안] (GDD 3)

알고리즘 [해석·임시] (16절 U3):

```
OnKeyEvent(e)  // Stance == None 일 때만
  if PendingDiag.Active and e.Time > PendingDiag.ExpireTime:     // 창이 이미 지났다: 먼저 만료 처리
     Facing = 이 이벤트 직전의 이동 방향 (없으면 Facing 그대로); PendingDiag.Active = false
  if e.Down == false and e.Key 가 방향키:
     prevDir = 이 이벤트 직전의 이동 방향
     newDir  = 이 이벤트 직후의 이동 방향
     if prevDir 가 대각 and newDir 가 prevDir 의 축 성분(상하좌우 중 하나):
         PendingDiag = { Active=true, Diag=prevDir, ExpireTime = e.Time + 1229 }
         // Facing 은 대각 그대로 둔다
         return
     if PendingDiag.Active and newDir == 없음 and e.Time <= PendingDiag.ExpireTime:
         Facing = PendingDiag.Diag; PendingDiag.Active = false   // 대각 유지 확정
         return
  if 방향키 누름 이벤트: PendingDiag.Active = false   // 새 입력이 오면 창 취소, 정상 규칙으로
  (그 밖은 5.3 규칙)

ResolvePending(t):   // 3.8의 3단계
  if PendingDiag.Active and (long)t * 256 > PendingDiag.ExpireTime:
      PendingDiag.Active = false
      Facing = 지금 이동 방향 (없으면 Facing 그대로)
```

- 창이 열려 있는 동안(최대 0.08초) 이동은 남은 한 키 방향으로 이미 바뀌고, 시야와 발사 방향만 대각으로 남는다. "이동 방향 = 시야"가 최대 0.08초 어긋나는 유일한 경우다.
- 경계: 두 번째 뗌이 첫 뗌에서 정확히 1,229단위 뒤면 유지(`<=`).
- 자세에 들어가면 창은 취소된다(5.5에서 시야를 다시 정한다).

### 5.5 자세와 반전 자세 상태 기계

[확정: Shift 자세, Space 반전 자세 (DEC 1.19)] / [제안: 세부 (GDD 3, GDD 8)] / [임시: 표에 표시한 것]

원문 규칙:

- 자세: 시야를 잠그고 느려진 속도로 이동.
- 자세에 들어갈 때 시야가 대각선이면 마지막에 누른 키 방향(상하좌우)으로 맞춘다. 자세 중에는 대각 사격이 없다.
- 반전 자세도 자세다. 자세 속도, 커맨드 인정.
- Space를 떼면 시야는 뒤집힌 방향으로 남고, 이동 키가 눌려 있으면 그 방향으로 바로 바뀐다.
- Shift를 누른 채 Space를 누르면 잠긴 시야만 180도 뒤집는다.
- 방향 입력(앞/뒤/옆)은 자세 중에만 커맨드로 읽힌다. 시야 기준이다. (GDD 8)
- 자세 진입, 해제, 반전 때 커맨드는 처음으로 돌아간다. (GDD 8)

`SnapCardinal(facing)`: `facing`이 축 방향이면 그대로. 대각이면 그 대각을 이루는 두 축 방향 중 `LastPressedCardinal`과 같은 쪽, 둘 다 아니면 두 축 성분 중 마지막 누름 시각이 늦은 쪽 [임시].

전이표(이벤트는 4.3의 정렬 순서대로 하나씩):

### 5.6 전장과 벽

[조율] (DEC 2.3, GDD 2.2, wc 2.1, mon 1.1)

- 전장은 24×14칸, 사방이 막혀 있다. 화면으로는 1536×896px. 가장자리(벽)는 두께 1칸(가시덤불 울타리와 돌무더기). 벽은 탄을 막고 벽 튕김 탄은 튕긴다.
- 전장은 한 곳이고 시간대에 따라 바닥 색만 바뀐다. 플레이어 쪽 판정 있는 장애물은 없다. 적이나 보스가 만드는 것(바위, 기둥)은 적 명세의 몫이다.
- 결투장(돌마당)도 24×14칸, 선돌 기둥 4개(칸 (9,3), (14,3), (9,10), (14,10), 각 1×1칸, 탄을 막고 벽 튕김, 부서지지 않음). 기둥 좌표의 유일한 기준은 `world-characters.md` 2.6절이다. (wc 2.6, online 4.1)
- 플레이어 위치 `Pos`는 **판정 중심**이다. 그림의 발밑 기준점(캔버스 (30, 60))은 판정 중심에서 아래로 0.4칸이다(wc 3.1: "판정 중심은 발밑 기준점에서 위로 0.4칸"). [해석]
- 벽 충돌용 몸 반지름 `BodyRadius = 0.30` [임시]. `Pos`를 `[0.30, 23.70] × [0.30, 13.70]` 안으로 자른다(축별로 따로 자른다. 벽을 따라 미끄러진다). 기둥은 원-사각형 밀어내기(최소 이동 방향)로 처리한다. [임시]
- 플레이어와 적은 서로 밀어내지 않는다(겹칠 수 있고 겹치면 접촉 피해). [임시]
- 이동 적분 [임시]: `Pos += 방향 단위 × 틱당 이동량` 후 벽 자르기. 틱당 이동량은 2.3절. 배율:
  - 자세·반전 자세: 캐릭터의 `StanceSpeedCenti`를 쓴다(배율이 아니라 값 교체).
  - 스침 가속: +20% (`mulPermille` 1200). 중첩 없이 시간만 갱신 (GDD 6).
  - 플레이어를 느리게 하는 것: 흰뿔의 서리밭 −30% 하나뿐이다 (mon 1.2). 적 명세가 `PlayerSlowPermille`을 넣는다.
  - 둘이 겹치면 곱한다: 1200 × 700 / 1000 = 840. [임시]

### 5.7 하루와 웨이브 번호

## 6. 체력, 피격, 무적

### 6.1 체력 단위 [임시]

- `HpPoints`(정수), 1칸 = 100점. 무한 웨이브의 적 공격 피해는 칸 수 × 100.
- 이유: 결투 체력이 100 × 칸이고 "+1칸 피해"가 +100이다 (online 4.1). 같은 단위로 두면 그믐의 +1칸, 결투 피해, 표시를 하나의 코드로 다룬다.

### 6.2 피격 처리 (무한 웨이브)

원문 규칙:

- 피격 판정 반지름 0.15 (GDD 3, GDD 6). 판정 중심은 발밑에서 위로 0.4칸 (wc 3.1).
- 피격 후 무적 1초 (GDD 3).
- 피격 시 콤보 0, 결정 1개 파괴(성에는 파괴 없음, 그믐은 2개) (GDD 7).
- 접촉 피해는 같은 적에게서 1.5초에 1회 (mon 1.1). 그 간격은 적 쪽 값이다.
- 어떤 적 공격도 한 번에 3칸을 넘지 않는다. 이 상한은 공격 쪽 수치에 걸린다 (mon 4.2).
- 그믐: 빚이 있는 동안 받는 피해 +1칸. 3칸 상한 뒤에 더해 한 번에 최대 4칸 (wc 4.5 외상 3번, mon 4.2, GDD 개발자 확인 필요 63 — 지금 값).
- 체력이 0이 되면 판이 끝난다. 예외는 허상과의 첫 만남 (GDD 2.2).
- 허상과의 첫 만남 중에도 맞으면 평소대로 체력 1칸을 잃고 1초 무적이다. 연출용 무적이나 약한 탄을 쓰지 않는다 (mon 3.9.2).

```
PlayerHealth.OnHit(p, attack, t):            // attack.DamageCells 는 이미 3칸 상한이 걸린 값
  if SimConfig.Mode == Duel: DuelOnHit(p, attack.DamagePoints, t); return     // 12.3
  if t < p.InvulnUntil: return                // 무적: 피해도 벌칙도 없음
  dmg = attack.DamageCells * 100
  if p.Character == D5 and p.Debt > 0: dmg += 100
  p.HpPoints = max(0, p.HpPoints - dmg)
  p.InvulnUntil = t + p.Stats.InvulnTicks      // 60
  Combo.BreakByHit(p)                           // 9.4
  Crystal.LoseOnHit(p)                          // 10.4
  WandHooks.OnPlayerHit(p)                      // 유리 지팡이 등, 컴파일러·지팡이 명세
  emit PlayerHit(dmg, hpAfter)
  if p.HpPoints == 0: emit PlayerDowned → 모드가 처리 (6.3)
```

경계:

- 같은 틱에 두 공격이 닿으면 id가 작은 공격 하나만 들어가고 나머지는 무적에 막힌다. [임시]
- 무적 중의 스침은 인정하지 않는다(8.3). [임시]
- 비기의 무적(잔상 걸음 0.15초, 벼락 질주 0.2초)은 비기 명세가 `InvulnUntil`을 늘리는 방식으로 넣는다. 그때의 스침은 비기 명세의 규칙(1회만 인정)을 따른다. [임시]

### 7.2 발사 1회의 열 계산

원문:

- 발사 1회의 열 = 스코프별 (블록 열 합 × 그 스코프의 분열 배수)의 합. 분열 배수는 2갈래 ×1.6, 3갈래 ×2.2. (GDD 5)
- 분열은 한 스코프에 1개만 유효하고, 두 번째는 경고와 함께 무시. (GDD 4) → 열에도 첫 번째 분열의 배수만 쓴다. [해석]
- 밑줄(갈피): 연결 슬롯 맨 끝 칸 블록의 열이 절반(올림)만큼 깎인다. 최대 −5. 분열 블록의 배수는 깎은 뒤의 값에 곱한다. 대성공으로 슬롯이 늘면 깎아 주는 자리도 한 칸 뒤로 밀린다. (GDD 10.1, wc 4.3)
- 거울상 변이: 발사당 열 +50%. (GDD 9)

```
ShotHeatHu(tree, p):
  total = 0
  for scope in tree.ScopesInDfsOrder:              // 트리거 스코프 포함 (아래 [해석])
     sum = 0
     for block in scope.Blocks (분열 블록 제외):
        h = block.Heat                             // 정수 열 (변형의 +3 은 3)
        if p.Passive == Underline and block.SlotIndex == p.Wand.LastLinkSlotIndex:
           h -= min(5, ceil(h / 2))
        sum += h
     mult = scope.FirstSplit switch { null => 10, Split2 => 16, Split3 => 22 }   // 10배 정수
     total += sum * 120 * mult / 10                // HU. 120×1.6 = 192, 120×2.2 = 264 로 항상 정수
  if p.Wand.HasMutation(MirrorImage): total = total * 3 / 2     // 항상 정수 (위 값들이 모두 짝수)
  return total
```

- [해석] 트리거(적중 시 발동) 스코프 안의 블록 열도 **발사할 때 미리** 더한다. 원문의 "스코프별 합"은 트리 전체의 스코프를 말하고, 실제로 적중했는지와 무관하다. 그래야 야영 화면의 "발사당 열"(GDD 13)이 고정값이 된다.
- 밑줄이 분열 블록(배수)이나 적중 시 발동(열 0)에 붙으면 깎을 것이 없다. [임시]
- 맨 끝 칸이 비어 있으면 아무것도 깎지 않는다. "맨 끝 칸"은 끼운 블록 중 마지막이 아니라 **지팡이의 마지막 연결 슬롯 칸**이다 [해석] (확장으로 "한 칸 뒤로 밀린다").
- 밑줄 표(wc 4.3): 변형 +3 → 2 깎아 +1 / 변형 +5 → 3 깎아 +2 / 투사체 8 → 4 깎아 4 / 투사체 14 → 5 깎아 9 / 투사체 18 → 5 깎아 13.

### 7.3 발사 절차 (J)

원문:

- J를 누르고 있으면 연사. 발사 간격은 코어 블록의 간격을 쓴다. (GDD 3, GDD 4)
- 임계: 이번 발사를 더한 뒤의 열이 임계 시작값 이상이면 그 발사는 피해 2배. (GDD 5)
- 잠금: 100을 넘긴 발사는 임계로 나가고, 직후 3초 동안 발사 불가. 풀리면 열 0. (GDD 5)
- 임계 시작값을 바꾸는 효과가 여럿이면 가장 낮은 값을 쓴다. (GDD 9)
- 과열 잠금 중: 마력 방출은 쓸 수 있지만 잠금은 풀리지 않는다. 잠금을 푸는 수단은 스쳐 피하기와 방열 폭발뿐이다. (GDD 8)
- 모든 비기는 열을 올리지 않고, 임계 배율을 받지 않는다. (GDD 8)

```
CritStartHu(p) = 120 * min( p.Stats.CritStart,                   // 달구는 지팡이 특성으로 80
                            p.Wand.Has(Hypersensitive) ? 70 : 100,
                            ...그 밖에 임계 시작을 바꾸는 효과 )

HeatSystem.TryFire(p, t):
  wantFire = KeyState.IsDown(Fire) or JPressedThisTick
  if !wantFire: return
  if p.Locked:
     if JPressedThisTick: emit FireDryWhileLocked     // "J를 누르면 지팡이가 헛돈다" (eff 10)
     return
  if t < p.FireReadyTick: return
  if !SimConfig.FireEnabled: return                   // 광장

  hShot = ShotHeatHu(tree, p)
  h = hShot
  exemptUsed = false
  if p.HeatExemptArmed: h = 0; p.HeatExemptArmed = false; exemptUsed = true      // 8.4
  isCrit = (p.HeatHu + h) >= CritStartHu(p)
  if isCrit and !exemptUsed and KilnActiveAt(p) and p.KilnAbsorbLeftHu > 0:      // 7.6.2
     a = min(p.KilnAbsorbLeftHu, h); p.KilnAbsorbLeftHu -= a; h -= a; emit KilnAbsorbed(a)
  p.HeatHu += h
  willLock = p.HeatHu > 12000
  if willLock: isCrit = true                          // "100을 넘긴 발사는 임계로 나가고"
  unstable = p.Wand.Has(UnstableCore) and SimConfig.Mode != Duel
             and Rng[Mutation].Chance(50)             // 5% = 50‰  (7.6.4)

  shotId = NextShotId()
  Compiler.Execute(tree, p.MuzzlePos, FireDirection(p), dmgMul: 1, heatExempt: false,
                   faction: Player, isCrit, shotId)   // 피해·탄은 컴파일러 명세
  emit ShotFired(shotId, coreBlockId, isCrit, heatAfter: p.HeatHu)

  interval = tree.Core.IntervalTicks
  p.LastFireTick = t; p.LastFireIntervalTicks = interval; p.FireReadyTick = t + interval
  if willLock: EnterLock(p, t, interval, p.Stats.LockTicks + (Hypersensitive ? 90 : 0))
  if unstable: UnstableCoreBlowup(p, t, interval)     // 7.6.4
```

- 정확히 100(12,000 HU)은 잠금이 아니다(">100"). 임계다.
- 열 면제 발사의 임계 판정은 `HeatHu + 0 >= 임계 시작`이다. 스침 직후에는 열이 임계 시작값이므로 임계로 나간다(eff 10: "열 면제 발사 대기"는 임계 링 바깥의 가는 흰 링).
- 이번 틱에 누르고 같은 틱에 뗀 J도 쏜다(`JPressedThisTick`). 쿨다운 중에 눌렀다 뗀 J는 보관하지 않는다(버퍼 없음). [임시]
- 발사는 틱 단위다. J의 틱 안 오프셋은 발사 시각에 쓰지 않는다. [임시]

### 7.4 냉각

원문: "냉각: 발사를 0.2초 멈춘 뒤부터 초당 45." (GDD 5)

[해석] (15절 C8): **발사 1회는 그 발사의 간격만큼 "발사 중"으로 친다.** 냉각 대기 0.2초는 마지막 발사의 간격이 끝난 뒤부터 센다. 이렇게 읽어야 GDD 18절과 wc 5.2절의 검산값(꾹 누르기 6.9초 주기, 임계 유지 `20n ÷ (0.15n + 0.2 + 4n ÷ 냉각)`)과 정확히 맞는다.

```
HeatSystem.Cool(p, t):            // 3.8의 10단계, 틱 끝
  if p.Locked: return
```

### 7.5 잠금

```
EnterLock(p, t, intervalTicks, lockTicks):
  p.Locked = true
  p.UnlockTick = t + intervalTicks + lockTicks      // [해석] 7.4와 같은 이유. 15절 C8
  emit HeatLockEntered(p.UnlockTick)
  if p.Passive == Boilover: emit/execute Boilover(p)   // 달구 끓어넘침 (7.6.6)

ProcessUnlock(p, t):                                 // 3.8의 1단계
  if p.Locked and t >= p.UnlockTick:
     p.Locked = false; p.HeatHu = 0; emit HeatUnlocked(reason: Timeout)

BreakLock(p, reason, heatAfterHu):                   // 스침, 방열 폭발
  p.Locked = false; p.HeatHu = heatAfterHu; emit HeatUnlocked(reason)
```

- 잠금 중에는 콤보 타이머가 멈춘다 (GDD 5, GDD 7). (9.3)
- 잠금 중에는 발사 불가. 마력 방출(비기 ①)은 쓸 수 있고 잠금은 풀리지 않는다 (GDD 8).
- 잠금을 푸는 수단은 스쳐 피하기와 방열 폭발뿐이다 (GDD 8).
- 잠금 중에는 냉각하지 않는다. 열 값은 풀릴 때 0이 된다. 잠금 중 표시는 "남은 시간"이다(eff 10). → `LockRemainTicks = UnlockTick − t`, `LockTotalTicks = interval + lockTicks`를 표시 계층에 준다.
- 꾹 누르기 검산(GDD 18): 마력탄으로 열 0에서 J를 누르고 있으면 26발째(열 104)에 잠긴다(일반 21 + 임계 5). 26발 × 0.15초 + 잠금 3초 = 6.9초 주기, 44.9 DPS.

### 7.6 열의 예외와 변이

#### 7.6.1 스쳐 피하기의 보상 → 8.4절

#### 7.6.2 달구의 불가마 [제안] (GDD 8 고유 비기, GDD 5, wc 4.1)

- 불가마(뒤, 뒤, K / 결정 2)는 발밑 반경 2.5 지대를 4초 동안 깐다. 지대 효과(피해, 감속)는 비기 명세의 몫이다.
- 이 영역의 규칙: 지대 안에서 쏜 **임계 발사**의 열을 합계 16까지 대신 먹는다(마력탄이면 4발). 16을 다 먹으면 그 뒤 발사는 평소대로 열이 오른다. 발사 한 번의 열이 남은 양보다 크면 남은 만큼만 먹고 나머지는 오른다.
- 임계인지는 평소처럼 "이번 발사의 열을 더했을 때 임계 시작값 이상인가"로 먼저 판정하고, 임계로 판정된 발사의 열만 불가마가 먹는다.
- 스쳐 피하기의 "다음 발사 열 면제"가 남아 있으면 그것을 먼저 쓴다(그 발사는 열이 0이라 불가마가 먹을 것이 없다).
- 동시에 1개. 새로 깔면 이전 것은 사라지고 남은 열 흡수량도 이어받지 않는다. → 새 지대를 깔 때 `KilnAbsorbLeftHu = 1920`, 지대가 사라지면 0.
- "지대 안에서 쏜" = 발사 틱에 플레이어 `Pos`가 지대 원 안(거리 ≤ 2.5) [임시: 판정 중심 기준].
- 쓰는 법(원문 예): 열을 80 근처로 올린 뒤 깔면 열 없는 임계 4발에 이어 평소의 임계 6발이 붙어 10발 연속 임계 사격.
- 결투: 열 흡수 16 그대로 (wc 5.4).
- 표시: 고유 능력이 열에 영향을 주는 동안 링 눈금에 그 능력의 작은 표식(8×8) (eff 10).

#### 7.6.3 과민 회로 [제안] (GDD 9)

#### 7.6.4 불안정 핵 [제안] (GDD 9, online 4.2)

- 이득: 폭발 반경 +100%(컴파일러 명세). 대가: 발사 1회당 5% 확률로 내 자리에서 터져 잠금 2초 + 콤보 0. 코어가 폭발 블록일 때만 나온다.

#### 7.6.6 달구의 끓어넘침 [제안] (GDD 10.1, wc 4.1)

- 과열 잠금에 들어가는 순간 내 자리에서 반경 2.5에 1.5T(화염), 넉백 2칸. 탄은 지우지 않는다. 잠금 자체는 그대로 3초다.

- 불안정 핵의 자폭 잠금도 "과열 잠금에 들어가는 순간"으로 칠지는 원문에 없다 → 치지 않는다 [임시].

#### 7.6.7 방열 폭발 (비기 ⑦)과 열 [제안] (GDD 8)

- 피해 = T × (열 ÷ 25). 잠금 중에도 쓸 수 있고(열 100으로 계산) 잠금을 푼다. 열 0.

```
  heat = p.Locked ? 100 : p.HeatHu / 120   [임시: 정수 나눗셈 내림. 피해 명세가 HU를 직접 받아도 된다]
  if p.Locked: BreakLock(p, VentBlast, 0) else p.HeatHu = 0

```

#### 7.6.8 그 밖

- 사본 마법진(갈피 베껴 쓰기)의 실행은 열 없음 (GDD 8). `Execute(..., heatExempt: true)`.
- 피뢰침 벼락은 열을 올리지 않는다 (wc 4.2).
- 유리 지팡이: 임계 배율 +1(컴파일러 명세). 결투에서 피격 후 3초 동안 꺼진다(12절).
- 과열 3배 블록: 임계 배율을 2에서 3으로 교체(컴파일러 명세).
- 임계 배율 = (과열 3배 블록이 있으면 3, 없으면 2) + (유리 지팡이 변이가 있으면 1). 임계가 아니면 1. 비기 배율은 임계 배율과 같이 적용하지 않는다(비기는 임계 판정을 받지 않는다). (GDD 4) — 피해 공식은 컴파일러 명세가 주인이고, 이 영역은 `isCrit`만 넘긴다.

```
CritShotCount(hShotHu, critStartHu):
```

## 8. 스쳐 피하기

### 8.1 원문 규칙 [제안] (GDD 6, mon 1.1, wc 4.2, eff 11.1)

1. 피격 판정 반지름 0.15, 감지 판정 반지름 0.6(초롱 0.75).
2. 인정 대상: 적의 탄, 적의 돌진, 예고 구역이 터지는 순간 경계 바깥 0.6 이내. (2판에서 "술사와 보스의 탄, 늑대의 돌진"이던 것을 "적의 탄과 돌진 전부"로 넓혔다, GDD 20)
3. 탄 하나당 1회, 같은 시전에서 나온 탄은 묶어서 1회만 인정.
4. 보상: 열이 임계 시작값보다 낮으면 임계 시작값으로 올린다. 다음 발사 1회는 열이 오르지 않는다. 잠금 중이면 즉시 해제하고 열을 임계 시작값으로 맞춘다.
5. 이동 속도 +20% 1.5초(초롱 2.0초. 중첩 없이 시간만 갱신), 콤보 +2.
6. 결투에서는 상대 1명당 1.0초에 1회만 인정하고 보상도 줄어든다 (12절).
7. 초롱의 피뢰침 체질: 스쳐 피하기에 성공할 때마다 반경 5 안의 가까운 적 2체에게 각 1T(번개). 열을 올리지 않고 콤보에 넣지 않는다. 늑대 회피를 무시한다. 시전 묶음당 1회 (wc 4.2).
8. 보스의 탄은 모두 스쳐 피하기 대상이다 (mon 3.2). 적의 공격 정의는 `Grazeable` 플래그를 가진다(적 명세). 원문에 "스침 대상"이라고 적힌 공격은 전부 참.
9. 얼음 병풍이 막은 탄은 스쳐 피하기로 치지 않는다 (wc 4.4).
10. 벼락 질주: 길 위에 있던 적 탄은 스쳐 피하기 1회로 인정(피뢰침 체질도 1회 발동) (wc 4.2). 잔상 걸음: 스쳐 피하기 1회만 인정 (GDD 8). — 비기 명세가 `GrazeSystem.AwardOnce(p, source: Skill)`를 부른다.
11. 점수: 스쳐 피하기 1회당 5 × S(w), 일반 웨이브 20회, 보스 웨이브 40회까지 (mon 4.8). 보스 최종 격노(180초) 이후의 스침, 허상과의 첫 만남 중의 스침은 점수 없음. — 이 영역은 `GrazeAwarded` 이벤트만 내고 점수 명세가 센다.

### 8.2 시전 묶음 `CastId`

- 적이 공격 하나를 시전할 때 새 `CastId`를 받는다. 그 시전으로 나온 모든 탄·구역·돌진이 같은 `CastId`를 가진다. [임시: 적 명세와의 계약]
- 분열·고리 탄, 연속 발사라도 "한 번의 시전"이면 하나의 `CastId`.
- `GrazedCasts`에 들어간 `CastId`는 다시 인정하지 않는다. 시전의 모든 탄이 사라지면 목록에서 지운다(목록 크기를 묶어 두려고). [임시]

### 8.3 판정 [임시] (원문은 "감지 반지름"만 정한다)

```
GrazeSystem.Detect(p, t):          // 3.8의 8단계, 같은 틱 피격 판정 뒤
  if t < p.InvulnUntil and !InSkillGrazeWindow(p): return     // 피격 후 무적 중에는 인정 안 함 [임시]
  if p.HitThisTick: return                                    // 이번 틱에 맞았으면 인정 안 함 [임시]
  R = p.Stats.GrazeRadius
  for threat in 적 위협들 (id 순):
     if !threat.Grazeable or GrazedCasts.Contains(threat.CastId): continue
     switch threat.Kind:
       Bullet:  d = |p.Pos - threat.Pos|
                if d <= R + threat.Radius and d > p.HitRadius + threat.Radius: Award(p, threat)
       Dash:    (돌진 상태인 적의 몸 원으로 Bullet과 같게)
       ZoneDetonation:   // 그 구역이 이번 틱에 터졌을 때만
                if !zone.Contains(p, hitRadius) and zone.DistanceToBoundary(p.Pos) <= R: Award(p, threat)
```

- 탄: 감지 원(반지름 R)과 탄 원이 겹치고, 피격 원(0.15)과는 겹치지 않는 첫 틱에 인정한다. 그 탄이 나중에 맞더라도 이미 받은 보상은 그대로다.
- 구역: "경계 바깥 0.6 이내"를 플레이어 판정 중심에서 구역 경계까지의 거리 ≤ R로 읽는다. 원문은 0.6으로 적었지만 초롱도 감지 반지름(0.75)을 쓴다 [해석] (15절 C6).
- 같은 틱에 여러 시전이 동시에 인정 조건을 만족하면 각각 인정한다(시전마다 1회). 보상(열, 가속)은 중복돼도 결과가 같고 콤보는 시전마다 +2. [임시]
- 탄과 몸의 모양이 원이 아닌 것(띠, 부채꼴 구역)은 적 명세가 `DistanceToBoundary`와 `Contains`를 제공한다.

## 9. 콤보

### 9.1 원문 규칙 [확정: 개념 / 제안: 수치] (GDD 7)

1. 적을 맞힐 때마다 콤보 +1, 임계 적중은 +2. 단 발사 1회로 오르는 콤보는 최대 +3.
2. 2초 동안 못 맞히면 0 (잠금 중에는 타이머 정지).
3. 콤보 15마다 마력 결정 1개(초롱은 12마다).
4. 피격 시 콤보 0.
5. 비기로 맞힌 것은 콤보에 넣지 않는다.
6. 스쳐 피하기 콤보 +2 (GDD 6), 결투는 +1 (online 4.3).
7. 사본 마법진의 적중은 콤보에 넣지 않는다 (wc 4.3). 피뢰침 벼락도 넣지 않는다 (wc 4.2).
8. 결투 방 옵션 "야생 난입"의 중립 슬라임을 맞혀도 콤보가 오른다 (online 4.1).
9. 결투에서 피격 벌칙(콤보 0, 결정 파괴)은 1.0초에 1회만 (GDD 7, online 4.3).
10. 불안정 핵 자폭은 콤보 0 (GDD 9).

### 9.2 적중으로 오르는 콤보

```
ComboSystem.OnPlayerProjectileHit(p, shotId, isCrit, sourceKind, t):
  if sourceKind in {Skill, CopyCircle, Passive, Zone}: return    // 5·7번, [임시] 패시브·지대
  p.ComboIdleTicks = 0                                           // 적중했으므로 타이머 다시 참
  gained = p.ShotComboGain[shotId] (없으면 0)
  inc = min(isCrit ? 2 : 1, 3 - gained)
  if inc <= 0: return
  p.ShotComboGain[shotId] = gained + inc
  Add(p, inc, source: Hit)

ComboSystem.Add(p, n, source):
  old = p.Combo; p.Combo += n
  k = p.Stats.ComboPerCrystal
  gainedCrystals = p.Combo / k - old / k                         // +3 이하라 0 또는 1
  for i in 1..gainedCrystals: Crystal.Gain(p, source: Combo)     // 10.2
  emit ComboChanged(p.Combo, n)
```

- "적을 맞힐 때마다"는 적중 이벤트 하나마다다. 한 탄이 여러 적을 맞히거나(관통, 그림자 구체, 폭발, 연쇄 전이) 한 적을 두 번 맞히면(부메랑 왕복) 각각이 적중이고, 모두 같은 `ShotId`의 +3 상한을 나눈다. 트리거 자식 탄도 부모 발사의 `ShotId`를 물려받는다. [해석]
- 임계 적중 = 임계 발사(`isCrit`)가 만든 탄의 적중.
- 상한에 걸린 적중도 타이머는 다시 채운다 [임시].
- 끓어넘침, 불가마 지대의 피해는 비기·패시브 피해이므로 콤보에 넣지 않는다 [임시] (원문은 "비기로 맞힌 것"만 적었다. 불가마는 비기이므로 원문대로, 끓어넘침은 [임시]).
- `ShotComboGain`은 발사 뒤 그 발사의 탄이 모두 사라지면 지운다 [임시].
- 결정을 얻는 기준은 "콤보 15마다", 즉 15, 30, 45…를 지날 때다. 결정이 상한이면 결정은 얻지 못하고 콤보는 계속 오른다 [해석] (10.2).

### 9.3 끊김 타이머

```
ComboSystem.TickIdle(p, t):       // 틱 끝
  if p.Locked: return             // 잠금 중 정지
  if p.Combo == 0: return
  p.ComboIdleTicks += 1
  if p.ComboIdleTicks >= 120: Reset(p, reason: Timeout)
```

- 마지막 적중 틱 t0에서 `ComboIdleTicks = 0`, 틱 끝마다 +1. 잠금이 없으면 t0 + 120틱의 끝에 0이 된다. 그 사이 잠금 틱 수만큼 늦어진다.

- 표시: 숫자 아래 2초짜리 가는 막대(남은 비율 = 1 − `ComboIdleTicks`/120). 잠금 중 막대가 멈추고 자물쇠 점 (eff 11.2).

## 10. 마력 결정

### 10.1 원문 규칙 [확정: 개념 / 제안: 수치] (GDD 7, wc 4)

1. 콤보 15마다 결정 1개(초롱 12마다). 최대 5개(달구 5, 초롱 5, 갈피 4, 성에 6, 그믐 7).
2. 피격 시 결정 1개 파괴(성에는 파괴 없음, 그믐은 2개).
3. 콤보 말고 결정을 얻는 길은 밤 웨이브(하루의 8~9번째)의 돌발 사건 "별똥 결정" 하나다. 떨어진 별똥을 밟으면 결정 +1이고, 결정 상한은 넘지 않는다(상한이 차 있으면 얻지 못한다). 그믐은 이 결정으로도 빚부터 갚는다. 결투에는 없다.
4. 결정의 용도: 비기의 연료. 웨이브가 끝날 때 남은 결정은 개당 5골드로 바뀐다(그믐의 빚이 있으면 빚부터 갚는다).
5. 결정은 판 안에만 있다. 판이 끝나면 사라진다.
6. 결정이 모자라면 비기 불발(판정기 명세). 예외: 고유 비기는 부모 기술로, 그믐은 외상 (GDD 8).
7. 그믐의 그림자 계약: 가진 결정 1개당 모든 피해 +3%(7개에서 +21%). J 발사와 비기 모두. 비기에는 그 비기가 결정을 쓴 뒤 남은 개수로 계산. 빚 결정은 0개로 센다 (wc 4.5).
8. 만개의 최대 반복은 결정 상한과 같다: 갈피 4회, 달구·초롱 5회, 성에 6회, 그믐 7회 (GDD 8).

### 10.2 얻기

```
CrystalSystem.Gain(p, source):              // source: Combo, Starfall, RoundStart
  if p.Debt > 0: p.Debt -= 1; emit DebtRepaid(p.Debt); return     // 그믐: 빚부터
  if p.Crystals >= p.Stats.CrystalCap: emit CrystalGainBlocked(source); return
  p.Crystals += 1
  emit CrystalGained(index: p.Crystals, source)
  if p.Crystals == cap: emit CrystalsFull
```

- 빚이 있으면 `Crystals`는 항상 0이다(빚을 갚기 전에는 결정이 늘지 않으므로). 불변식: `Debt > 0 ⇒ Crystals == 0`.

### 10.3 그믐의 외상과 빚 [제안] (GDD 8, GDD 10.1, wc 4.5)

- 결정이 모자라도 비기가 나가고 모자란 만큼 빚 결정이 생긴다(최대 2개). 만개는 외상으로 쓸 수 없다.
- 판정 순서(판정기 명세가 실행): 1) 그믐이면 외상을 먼저 적용(빚이 2개를 넘지 않는 범위에서, 만개 제외), 2) 그래도 모자라고 고른 노드가 고유 비기면 부모 노드의 기술로 한 번만 내려간다(외상 포함해 다시 본다), 3) 그 밖에는 불발.
- 이 영역이 제공하는 함수:

```
bool CrystalSystem.CanAfford(p, cost, allowCredit)
  have = p.Crystals
  if have >= cost: return true
  if allowCredit and p.Character == D5 and p.Debt + (cost - have) <= 2: return true
  return false

void CrystalSystem.Spend(p, cost, allowCredit)       // CanAfford 참일 때만 부른다
  use = min(p.Crystals, cost); p.Crystals -= use
  short = cost - use
  if short > 0: p.Debt += short; emit DebtCreated(p.Debt)
  emit CrystalsSpent(use, short)

int CrystalSystem.SpendAll(p)                        // 만개: 전부(최소 3), 외상 불가
```

- 외상 세부 다섯(wc 4.5):
  1. 빚은 판이 끝날 때까지 남는다. 웨이브가 끝나도, 야영을 해도 지워지지 않는다. 결투에서는 라운드가 바뀌어도 남는다. (예외: 허상과의 첫 만남 일어남에서 0, 6.3)
  2. 이후에 얻는 결정은 빚부터 갚는다. 별똥 결정도, 결투 라운드 시작 결정도. 웨이브 종료 환전은 빚을 갚고 남은 결정에만 한다.
  3. 빚이 있는 동안 받는 피해 +1칸(6.2).
  4. 빚이 있을 때 맞으면(결정이 0개이므로) 결정 파괴 대신 빚이 1개 늘어난다. 빚은 2개를 넘지 않는다.
  5. 빚이 2개면 외상으로 더 쓸 수 없다. 결정 0개에 빚 1개인 상태에서 2개짜리 고유 비기를 누르면 양익 사격(1개)이 외상으로 나가고 빚이 2개가 된다.
- 표시: 빚 결정은 결정 칸에 보라 테두리의 빈 칸, "지금 K = 기술명(비용)" 옆에 "외상 N" (GDD 8, GDD 13, wc 4.5).

### 10.4 피격으로 잃기 (무한 웨이브)

```
CrystalSystem.LoseOnHit(p):
  switch p.Character:
    D4 (성에): if p.Crystals > 0: emit CrystalProtected; return        // 얼린 결정
    D5 (그믐): if p.Debt > 0: p.Debt = min(2, p.Debt + 1); emit DebtCreated(p.Debt); return
               lost = min(2, p.Crystals)
    default:   lost = min(p.Stats.CrystalLossOnHit, p.Crystals)
  p.Crystals -= lost
  if lost > 0: emit CrystalsShattered(lost)
```

- 그믐이 결정 1개일 때 맞으면 0개가 되고 빚은 생기지 않는다(결정 파괴는 빚을 만들지 않는다). 결정 0개·빚 0개에서 맞으면 아무것도 잃지 않는다. [해석]
- 결투는 12절.

### 10.5 별똥 결정 [제안] (GDD 7, wc 2.3, eff 11.3)

원문: 밤(웨이브 8~9), 웨이브당 1회 이하. 1.5초 예고 뒤 빈 바닥에 별똥이 떨어진다. 8초 안에 밟으면 마력 결정 1개. 피해 없음. 예고는 위험색이 아니라 흰 금빛 고리(eff: 금색 점선 원, 차오르지 않고 점선이 돈다). 8초 동안 반짝이다 마지막 2초에 깜빡인다. 결투에는 없다. 결정 상한은 넘지 않는다(상한이 차 있으면 얻지 못한다).

### 12.2 결투 스침

```
DuelGraze(p, t):
  if t < p.DuelGrazeReadyTick: emit GrazeCosmeticOnly; return      // 연출만, 보상 없음
  p.DuelGrazeReadyTick = t + 60
  c = CritStartHu(p); if !p.Locked and p.HeatHu < c: p.HeatHu = c   // 열을 임계 시작값으로 올림
  Combo.Add(p, 1, source: Graze)
  // 다음 발사 열 면제, 잠금 해제, 가속은 없다
  if p.Passive == LightningRod: 결투 피뢰침(wc 5.4: 0.5T, 2초에 1회, 반경 5, 0.25초 조준 표시)
  emit GrazeAwarded(...)
```

- 사본 마법진·분열 탄: 같은 발사에서 나온 탄은 본체와 한 묶음이다. 묶음당 스침 1회 (online 4.3). → 상대 플레이어의 발사 하나가 `CastId` 하나다.
- 스침에 걸린 능력(피뢰침 체질 등)은 인정된 스침에서만 발동한다 (online 4.5).
- [해석] 잠금 중 결투 스침: 잠금은 풀리지 않는다("잠금 해제는 없다"). 열은 잠금이 풀릴 때 0이 되므로 바꾸지 않는다.

### 12.3 결투 피격과 벌칙

```
DuelOnHit(p, dmgPoints, t):
  isPenalty = t >= p.DuelPenaltyUntil
  if isPenalty and p.Character == D5 and p.Debt > 0: dmgPoints += 100      // 빚의 +1칸은 벌칙 피격에만
  allowed = p.MaxHpPoints * 300 / 1000 - p.DuelDamageWindow.SumLast30(t)    // 0.5초 30% 상한
  applied = clamp(dmgPoints, 0, max(0, allowed))
  p.HpPoints = max(0, p.HpPoints - applied); p.DuelDamageWindow.Add(t, applied)
  if p.Wand.Has(Glass): p.GlassCritOffUntil = t + 180
  if isPenalty:
     p.DuelPenaltyUntil = t + 60
     Combo.Reset(p, Hit)
     schedule at t + 3: DuelCrystalPenalty(p)                                // 결정 파괴는 3틱 뒤 적용
  emit PlayerHit(...)
```

- 피격 피해는 맞을 때마다 들어간다(순간 피해 상한 안에서). 벌칙(콤보 0, 결정 파괴)은 1.0초에 1회. 벌칙이 발동하면 1.0초의 벌칙 창이 열리고 그동안의 피격은 피해만 준다 (online 4.3).
- 벌칙 1회의 결정 손실 = 캐릭터의 "피격 시 결정 손실"(기본 1, 그믐 2) (online 4.3, wc 5.4).
- 성에의 얼린 결정(결투) (wc 5.4): 금(0 또는 1). 금 0에서 벌칙 → 결정 그대로, 금 1. 금 1에서 벌칙 → 결정 1개 파괴(0개면 잃는 것 없이) 금 0. 금은 시간이 지나도 지워지지 않고 라운드가 바뀌면 0. 벌칙 창 안의 피격은 금을 올리지 않는다. 가장 빨라도 2.0초에 1개.
- 그믐의 외상(결투) (wc 5.4): 빚은 라운드가 바뀌어도 남는다(최대 2). 라운드 시작 결정 1개는 빚부터 갚는다. 빚이 있으면 벌칙 때 결정 파괴 대신 빚 +1(최대 2). 빚의 +1칸(+100)은 벌칙 피격에만. 만개는 외상 불가, 판정 순서는 무한 웨이브와 같다.
- 개발자 확인 필요 43·44(성에·그믐 결투 벌칙)는 지금 값이 위 규칙이다 (GDD 개발자 확인 필요).
- [임시] 순간 피해 상한을 넘겨 잘린 피해도 벌칙 판정에는 영향이 없다(벌칙은 "피격"에 걸린다).

### 12.4 되감기와의 관계

- 결투 클라이언트는 상대 입력을 "직전 키 상태 유지"로 예측하고, 확정 입력이 예측과 다르면 그 틱으로 되감아 다시 돌린다. 되감기 한도 8틱. (online 4.11)
- 그러려면 `SimWorld`는 **틱 단위 스냅숏과 복원**을 지원해야 한다: `Snapshot Save()`, `void Load(Snapshot)`. 최근 9틱의 스냅숏을 고리 버퍼에 둔다. [임시]
- 이 영역의 상태(3.9의 표)는 전부 값 복사로 저장할 수 있게 만든다(참조 공유 금지). [임시]
- 커맨드 해석은 되감기지 않는다(내 입력의 시각과 순서만 본다). 발동은 되감길 수 있다 (online 4.11).
- 표시 이벤트는 "예측" 표시를 달고 내보내고, 확정된 틱의 이벤트만 소리·피격 연출을 낸다(online 4.11). → `SimEvent.IsConfirmed`.
- 30틱마다 상태 해시를 서버와 비교. 어긋나면 서버 상태로 덮어쓴다 (online 4.11).

### 12.5 조준 보정 [제안] (GDD 3, online 4.4, GDD 개발자 확인 필요 8)

- J 발사와 방향이 있는 비기는 발사 방향을 8방향 기준에서 상대 쪽으로 최대 10도 꺾는다. 상대가 그 10도 안에 있으면 정확히 향하고, 밖이면 10도까지만.
- 뒤틀린 총열의 흔들림은 이 보정 뒤에 더한다.
- 보정이 없는 것: 3갈래·부채·팔방의 곁가지 탄(가운데 탄만 보정), 폭발 지점, 벽 튕김 뒤의 탄.
- 무한 웨이브에는 없다. "이동 방향 = 발사 방향"의 유일한 예외.
- 통과 기준(로컬 2인 시제품): 마력탄만 낀 조립끼리 붙였을 때 적중률 15% 이상, 시간 종료로 끝나는 라운드 20% 이하. 못 미치면 보정각을 15도까지 올린다. → `AimAssistDeg`는 데이터 값이다.
- 이 영역이 제공: `Fix64Angle FireDirection(p)` = `Facing`의 각도에서 보정을 더한 값. 각도 계산은 2.2의 표 기반 `Atan2`(정수)로 한다. [임시]

## 17. 시각/소리 연결점

코어는 아래 이벤트와 상태만 내보낸다. 그림·이펙트·소리는 구현하지 않는다. 이벤트 이름은 `SimEvent`의 종류 이름으로 쓴다. 괄호는 원문의 연출(`effects.md`)과 소리 번호(`effects.md` 19.2)다. 결투에서는 `IsConfirmed`가 참인 이벤트만 소리·피격 연출을 낸다 (online 4.11).
