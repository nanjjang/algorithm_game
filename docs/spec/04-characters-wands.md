# 04. 캐릭터 5명 · 전용 지팡이 · 변이 — 구현 명세

이 문서는 "엄청엄청 위대한 마법사 키우기"의 **캐릭터 5명(능력치, 패시브, 고유 비기, 지팡이 특성)**, **전용 지팡이 5종의 전투 특성과 강화 단계별 게임플레이 효과**, **변이 6종**을 구현자가 원본을 다시 읽지 않고 만들 수 있게 옮긴 것이다.

- 최우선 문서는 `docs/DECISIONS.md`다. 이 문서와 원본이 다르면 DECISIONS가 맞고, 그다음은 각 값의 "주인 문서"(아래 0.2)가 맞다.
- 그림·이펙트·소리는 구현하지 않는다. 대신 **식별자, 자료 구조, 코어가 내보내는 이벤트**를 정해 나중에 에셋을 꽂을 수 있게 한다(18절).
- 일정·범위 삭감은 다루지 않는다(DECISIONS 1.16). 순서는 의존 관계로만 적는다(0.6).

### 0.4 T(트리 1회 피해)

원문의 "T"는 "지팡이 트리 1회 실행의 피해"다(W 머리말, G 8). 패시브와 고유 비기의 피해가 "nT"로 적혀 있으므로 코어는 T를 계산하는 함수가 필요하다. 원문은 계산식을 주지 않는다 → 17절 Q-01의 [임시] 정의를 쓴다. 마력탄 하나만 낀 +0 지팡이에서 T = 10이다(W 5.2 "마력탄(피해 10)").

### 0.5 이 문서가 다루지 않는 것

주문 컴파일러 본체, 판정기 본체, 강화 확률·비용 계산, 적 AI, 화면. 이 문서는 그 시스템에 **캐릭터·지팡이별 값과 예외를 꽂는 자리**를 정한다.

### 0.6 의존 순서

1. 코어 공통(틱, 고정소수점, 난수기, 입력 이벤트) → 2. 컴파일러 `Execute(...)`(G 4) → 3. 과열·스쳐 피하기·콤보·결정(G 5~7) → 4. **이 문서 2~8절**(능력치, 패시브, 고유 비기, 꼬리표 반응, 지팡이 특성) → 5. 판정기 캐릭터별 트라이(G 8, 이 문서 5.1) → 6. **9~11절**(지팡이 개체, 단계 효과, 변이) — 강화 화면 명세와 맞물림 → 7. **12절**(겉모습 자료, 뷰 모델) — 에셋이 오면 → 8. **8절 결투 값** — 결투 시뮬레이션 뒤.

## 1. 식별자와 이름 표

### 1.1 이름 규칙 [확정]

- 화면에 찍는 이름은 **이름 표 한 곳**(id → 문자열)에만 둔다. 전투 코어, 저장 파일, 서버 DB, 통신, 자료 파일의 열쇠, 그림 파일 이름은 번호나 id로만 가리킨다. (D 1.25, W 0)
- 캐릭터 표시 이름은 임시로 "제자 1" ~ "제자 5". 그 밖의 항목은 정해질 때까지 작업용 이름을 그대로 넣는다. (D 1.25, W 0, G 개발자 확인 77) [확정 / 제안: 범위]
- 이름이 들어가는 문구는 틀로 쓴다. 예: +13 칭호 `엄청엄청 위대한 {char.N}` → "엄청엄청 위대한 제자 5". (W 0) [확정]
- 틀은 조사를 스스로 고른다(`{char.N}{이/가}`, `{wand.N}{을/를}`). 숫자로 끝나는 임시 이름은 숫자를 읽은 소리(1 일, 2 이, 3 삼, 4 사, 5 오)로 받침을 본다. (W 0) [제안]
- 표시 이름은 한글 8자 이내. (W 0) [제안]

### 2.1 기준값 (G 3, G 5~7, W 3.2) [제안]

## 3. 캐릭터 값이 들어가는 공통 규칙

공통 규칙 본체는 다른 명세의 것이다. 여기서는 캐릭터 값을 쓰는 자리만 정확히 적는다.

### 3.1 과열 (G 5) [제안]

- 발사 1회의 열 = Σ스코프 (그 스코프 블록 열 합 × 그 스코프의 분열 배수). 분열 배수 2갈래 ×1.6, 3갈래 ×2.2. 밑줄(4.3)은 곱하기 **전에** 블록 열을 깎는다.
- 냉각: 마지막 발사 후 `coolDelay`(12틱)가 지난 다음 틱부터 매 틱 `CoolHuPerTick`만큼 내린다(0 아래로는 내려가지 않는다).
- 임계 판정: `heatAfter = heat + shotHeat`, `heatAfter ≥ critStart`면 그 발사는 임계(피해 ×임계 배율).
- 잠금: `heatAfter > 100열(12,000hu)`이면 그 발사는 임계로 나가고, 직후 `lockDuration` 동안 발사 불가. 풀리면 열 0.
- 잠금 중 콤보 타이머 정지.
- 임계 시작값을 바꾸는 효과가 여럿이면 **가장 낮은 값**을 쓴다(G 9).
- 열의 예외는 둘: 밑줄(4.3), 불가마의 열 흡수(5.2). 그 밖에 변이(과민 회로, 탐식, 거울상)와 스쳐 피하기 면제.
- 열 링 표시 반지름 44px, 그 캐릭터의 임계 시작값 눈금(G 5). → 뷰 모델 `HeatView{heatHu, critStartHu, locked, lockRemainTicks}`.

### 3.2 스쳐 피하기 (G 6) [제안]

- 감지 반지름 = `grazeRadius`(초롱 0.75). 피격 판정 0.15.
- 인정 대상: 적의 탄, 적의 돌진, 예고 구역이 터지는 순간 경계 바깥 0.6 이내. 탄 하나당 1회, 같은 시전에서 나온 탄은 묶어서 1회.
- 보상: 열 < 임계 시작이면 임계 시작으로 올림 / 다음 발사 1회 열 면제 / 잠금 중이면 즉시 해제 + 열을 임계 시작값으로 / 이동 속도 +20% `grazeHasteDuration`(초롱 2.0초, 중첩 없이 시간만 갱신) / 콤보 +2.
- 초롱의 피뢰침 체질은 이 인정 사건(`GrazeAccepted`)에 붙는다(4.2).

### 3.3 콤보와 결정 (G 7) [제안]

- 적중 +1, 임계 적중 +2, 발사 1회로 오르는 콤보 최대 +3. 2초(120틱) 동안 못 맞히면 0(잠금 중 타이머 정지). 비기로 맞힌 것은 콤보에 넣지 않는다.
- 콤보가 `comboPerCrystal`의 배수에 닿을 때마다 결정 +1(초롱 12, 나머지 15). 상한 `crystalCap`.
- 피격 시 콤보 0, 결정 `crystalLossOnHit`개 파괴(성에 0, 그믐 2 — 빚 규칙 7.5가 우선).
- 그 밖의 결정 획득: 밤 웨이브(하루의 8~9번째) 돌발 사건 "별똥 결정" +1(상한 넘지 않음, 결투 없음).
- 웨이브 종료 시 남은 결정 개당 5골드(그믐은 빚부터 갚고 남은 것만). 결정은 판 안에만 있다.

결정 증가 공통 함수(빚 상환 포함):

```
GainCrystal(n):                       // 콤보, 별똥, 결투 라운드 시작 지급 모두 이 함수
  while n > 0:

    else if crystals < crystalCap: crystals += 1
```

### 4.3 밑줄 `passive.underline` (갈피) (W 4.3, G 5, G 10.1) [제안]

- 연결 슬롯 **맨 끝 칸**에 끼운 블록은 열이 깎인다. 깎는 양 = `min(5, ceil(블록 열 / 2))`.
- 분열 블록의 배수는 깎은 **뒤**의 값에 곱한다.
- 대성공·슬롯 새기기로 슬롯이 늘면 깎아 주는 자리도 한 칸 뒤로 밀린다(맨 끝 = 가장 큰 인덱스).
- 적의 종류와 무관(내 쪽 수치만).
- 결투: 그대로(W 5.4).

| 맨 끝 칸 블록 | 원래 열 | 깎이는 양 | 실제 열 | 코어(hu) |
|---|---|---|---|---|
| 변형 +3 | 3 | 2 | 1 | 120 |
| 변형 +5 | 5 | 3 | 2 | 240 |
| 투사체 열 8 | 8 | 4 | 4 | 480 |
| 투사체 열 14 | 14 | 5 | 9 | 1,080 |
| 투사체 열 18 | 18 | 5 | 13 | 1,560 |

```
BlockHeat(block, slotIndex, wand, char):        // 정수 열 점수
  h = block.heat                                 // 투사체 열, 변형 +n. 분열·트리거는 아래
  if block.kind == Split: return 0               // 분열은 배수로 다룬다 (G 5). 밑줄 대상 아님 [임시]
  if char.passive == underline && slotIndex == LastUsableLinkSlot(wand):
       h -= min(5, (h + 1) / 2)                  // ceil(h/2)
  return h
```

- `LastUsableLinkSlot`: 결투에서 리그 제한으로 확장 칸을 못 쓰면 쓸 수 있는 칸 중 마지막 [임시: Q-05]. 맨 끝 칸이 비어 있으면 효과 없음 [임시: Q-05].
- 맨 끝 칸 표시: 지팡이 그림이 아니라 **하단 지팡이 회로 UI의 맨 끝 칸 아래 청록 밑줄**. 슬롯이 늘면 한 칸 뒤로(Wg 6.6). → 뷰 이벤트 `UnderlineSlotChanged(slotIndex)`.

### 4.4 살얼음 `passive.thin_ice` (성에) (W 4.4, W 3.6, W 5.4) [제안]

적마다 상태를 갖는다.

꼬리표별 결과(W 3.6):

| 꼬리표 | 결과 |
|---|---|
| 일반 | 1.0초 빙결, 예고 취소 |

- 빙결 표시 그림은 지팡이 단계와 무관하게 같다(Ws 3.2).

### 4.5 그림자 계약 `passive.shadow_pact` (그믐) (W 4.5, G 4, G 10.1) [제안]

- 캐릭터 배율 = `1 + 0.03 × k` (덧셈. 7개에서 +21%). `k` = 가진 결정 수. **빚 결정은 0개로 센다.** J 발사와 비기 모두, 블록을 거치지 않는 피해(그림자 손)에도 적용(G 4 "모든 피해").
- 비기에는 **그 비기가 결정을 쓴 뒤 남은 개수**로 센다. 결정 5개에서 2개짜리 → k=3 → +9%. 만개는 전부 쓰므로 +0%. 외상으로 나간 비기는 남은 결정 0 → +0%.
- 결투: 그대로(W 5.4).
- 분수: `(100 + 3k) / 100`. k=0..7 → 1.00, 1.03, 1.06, 1.09, 1.12, 1.15, 1.18, 1.21.
- 검산: 임계 유지 화력 결정 0개 69.2, 4개 77.5, 7개 83.8. 결정 3개부터 달구(73.5)를 넘는다(3개: 75.46). (W 4.5, W 5.2)
- 결정 수는 시전·발사 **시점**의 값으로 고정하고, 탄이 날아가는 동안 결정이 바뀌어도 그 탄의 배율은 바뀌지 않는다 [임시: Q-06].
- 표시: 그믐의 눈빛과 지팡이 구슬 밝기 = 결정 0개 60%, 7개 100%(Wm 3.2) → 뷰 모델 `CrystalView{count, cap, debt}`.

## 5. 고유 비기 5종

### 5.1 공통 규칙 (G 8, W 3.5) [확정: 처음부터 쓴다 / 제안: 수치]

- 각 캐릭터는 공용 비기 10종 + 고유 비기 1종 = 11종. 트라이는 판 시작 때 캐릭터별로 만든다. 다른 캐릭터의 고유 노드는 트라이에 없다. 결투에서도 공용 10 + 고유 1. (G 8, W 3.5)
- 고유 비기는 **처음부터 쓸 수 있다**(새 프로필 첫 판부터 해금, 부모 기술 보유 조건 없음). 시작 비기 = 마력 방출, 반동 사격, 그 캐릭터의 고유 비기(3종). (D 1.23 [확정], G 8, W 3.5)
- 공통: K로 끝남, 자세 중에만(시야 기준 방향), 열을 올리지 않음, 임계 배율 없음, 강화 배율 적용, 공통 재사용 대기 0.4초(24틱), 대기 끝나기 0.1초 전부터 누른 K는 보관 후 처리. (G 8)
- 전부 **결정 2개, 난이도 3**. 값 범위: 허수아비 한 마리에게 결정 2개로 주는 피해 **3T 이상 6T 이하**(아래 기준 꿰뚫는 창 3T, 위 기준 뇌광창 두 번 12T의 절반). (W 3.5) [제안]
- 블록을 거치지 않는 고유 비기 피해의 속성 = 캐릭터 속성(불가마 지대, 벼락 질주, 병풍 파편, 그림자 손). 트리를 실행하는 고유 비기(베껴 쓰기의 사본)는 맞힌 투사체 블록의 속성. (G 8, W 3.4)
- 자세 중에는 시야가 상하좌우로 잠기므로(G 3 "자세 중에는 대각 사격이 없다") 방향이 있는 고유 비기는 **항상 4방향** 중 하나다. [조율: 이 명세의 해석]
- 넉백·당김·경직은 꼬리표에 따라(6절).

트라이 배치(W 3.5, G 8):

| 고유 비기 | 캐릭터 | 커맨드 | 붙는 자리(부모 노드) | 들어오는 간선 허용 간격 | 결정 | 부모 대체 기술 |
|---|---|---|---|---|---|---|
| 불가마 | 1 | 뒤, 뒤, K | ② 반동 사격 노드의 "뒤" 자식 | 0.2초 = 3,072 | 2 | 반동 사격(1) |
| 벼락 질주 | 2 | 옆, 앞, K | ④ 양익 사격 노드의 "앞" 자식(좌·우 양쪽) | 0.2초 = 3,072 | 2 | 양익 사격(1) |
| 베껴 쓰기 | 3 | 앞, 옆, K | ③ 부채 전개 노드의 "옆" 자식(좌·우 양쪽) | 0.2초 = 3,072 | 2 | 부채 전개(1) |
| 얼음 병풍 | 4 | 뒤, 옆, K | ② 반동 사격 노드의 "옆" 자식(좌·우 양쪽) | **0.3초 = 4,608** | 2 | 반동 사격(1) |
| 그림자 손 | 5 | 옆, 반대쪽 옆, K | ④ 양익 사격 노드의 반대쪽 "옆" 자식(좌→우, 우→좌) | 0.2초 = 3,072 | 2 | 양익 사격(1) |

- 노드 자료: `TrieNode{ children[4](F,B,L,R), kArt, justArt, edgeGapSubticks, failLink, unlocked, parentFallback }`. 고유 비기 노드만 `parentFallback = true`. (G 8 판정기)
- "좌, 좌"(잔상 걸음, 같은 쪽 0.25초)와 "좌, 우"(그림자 손)는 서로 다른 노드다. (G 8, W 3.5)
- 마지막 방향 입력 → K 간격은 0.3초(섬 0.07초). (G 8)
- 옆→앞, 앞→옆, 좌→우, 달구의 뒤→뒤를 0.2초로 잡은 이유: 자세 중 움직이다 누른 K가 고유 비기로 읽히는 오입력을 줄이려고. 같은 방향 두 번 0.25초는 잔상 걸음에만 남는다. (W 3.5)

결정이 모자랄 때(G 8 판정기, W 3.5):

```
ResolveArtCost(node, art):                         // K 판정으로 고른 노드·기술
  need = art.cost                                   // 만개는 "전부(최소 3)"
  have = crystals
  if char.wandTrait == credit && art != full_bloom:  // 1. 그믐: 외상 먼저
      if have + (2 - debt) >= need: return Fire(art, payCrystals=have.min(need), newDebt = debt + max(0, need-have))
  if have >= need: return Fire(art, pay=need)
  if node.parentFallback:                           // 2. 고유 비기만 부모로 한 번
      p = node.parent.kArt                          // 결정 1개 기술
      (외상 포함해 다시 본다: 그믐이면 have + (2 - debt) >= 1)
      if 가능: return Fire(p, ...)
  return Misfire(noCost)                            // 3. 불발. 더 내려가지 않는다
```

- 발동하거나 불발하면 커서와 입력 기록을 비운다(G 8).
- 화면의 "지금 K = 기술명(비용)"은 같은 판정 함수로 매 프레임 표시. 부모로 내려갈 자리에서는 내려간 기술명을, 그믐은 "외상 N"을 붙인다. → 뷰 모델 `ArtPreview{artId, cost, debtUse, justArtId?}`. (G 8, Wm 4.4)
- 판정기 단위 테스트 행은 15.4절.

### 5.2 불가마 `art.kiln` (달구) (W 4.1, G 8, W 3.6, W 5.4, Wd 4.4) [제안]

| 필드 | 값 | 코어 |
|---|---|---|
| 위치 | 시전 순간 **내 발밑**에 고정 | 중심 `castPos` |
| 반경 | 2.5칸 | 15,000u |
| 지속 | 4초 | 240틱 |
| 지대 안의 적 | 0.5초마다 0.25T(총 2T, 화염), 이동 −20% | 30틱마다, 8회 |
| 열 흡수 | 지대 안에서 쏜 **임계 발사**의 열을 합계 16까지 대신 먹는다(마력탄 4발) | `absorbLeftHu = 1,920` |
| 동시 개수 | 1. 새로 깔면 이전 것은 사라지고 남은 흡수량도 이어받지 않는다 | |
| 감속 꼬리표 | 일반·엘리트·중량 −20%, 보스 −10%, 뿌리 해당 없음, 비행 −20% | |
| 결투 | 상대 감속 −10%. 지대 피해(총 2T)와 열 흡수 16 그대로. 상대 화면에도 지대 표시 | |

발사 처리(과열 계산 안에 끼운다):

```
OnFire(shot):
  shotHeat = ComputeShotHeat(shot)                     // 밑줄·거울상 포함
  if graze.nextShotHeatFree: graze.nextShotHeatFree = false; shotHeat_effective = 0  // 스쳐 피하기 면제가 먼저 (W 4.1)
  else:
    heatAfter = heat + shotHeat
    crit = heatAfter >= critStart                      // 임계는 평소대로 먼저 판정
    if crit && kiln.active && Dist(self.pos, kiln.center) <= 15000u && kiln.absorbLeft > 0:
        eaten = min(shotHeat, kiln.absorbLeft)         // 남은 만큼만 먹고 나머지는 오른다
        kiln.absorbLeft -= eaten
        shotHeat_effective = shotHeat - eaten
    else shotHeat_effective = shotHeat
  heat += shotHeat_effective
  lock = heat > 12000hu                                // [임시: 흡수 뒤 열로 잠금 판정, Q-07]
```

- "지대 안에서 쏜" = 발사 순간 내 판정 중심이 지대 원 안(경계 포함) [임시].
- 스쳐 피하기 면제가 적용된 발사는 흡수량을 쓰지 않는다(면제가 먼저).
- 임계로 판정되지 않은 발사의 열은 먹지 않는다.
- 지대 피해 틱: 시전 뒤 30, 60, …, 240틱(8회) [임시: Q-08]. 그 틱에 지대 안(적 중심 거리 ≤ 15,000u)인 적에게만.
- 감속은 지대 안에 있는 동안 유지하고, 다른 감속과 더하지 않는다(가장 큰 값). 나간 뒤 남는 시간 없음 [임시: Q-09].
- 예고 공격은 그대로 들어온다(지대에 계속 서 있을 수 없다).
- 값: 지대 2T + 열 흡수 약 3.6T = 5.6T. 3.6T = 열 없는 임계 4발 8T − 그 0.6초 동안 평소에도 냈을 4.4T(임계 유지 73.5 × 0.6초). (W 3.5)
- 쓰는 법 검산: 열 80 근처에서 깔면 열 없는 임계 4발 + 평소 임계 6발 = 10발 연속 임계(W 4.1) → 15.7 테스트.
- 표시: 지대 안에 있는 동안 지팡이 밑동으로 주황 빛 한 줄(Wd 4.4) → 뷰 모델 `InKilnZone: bool`.

### 5.4 베껴 쓰기 `art.transcribe` (갈피) (W 4.3, G 4, G 8, W 5.4, Wg 4.1) [제안]

| 필드 | 값 | 코어 |
|---|---|---|
| 생성 | 내 자리에 사본 마법진. 움직이지 않고 맞지 않는다 | `circle.pos = castPos` |
| 지속 | 6초 | 360틱 |
| 따라 쏘기 | 내가 **J로** 쏘면 마법진도 내 시야와 같은 방향으로 지팡이 트리를 1회 실행 | |
| 피해 / 열 / 콤보 | 50% / 없음 / 넣지 않음 | `dmgMul = 1/2`, `heatExempt = true` |
| 간격 | 0.3초에 한 번까지만 | 18틱 |
| 횟수 | 모두 12번 쏘면 6초가 남아 있어도 사라진다 | `shotsLeft = 12` |
| 동시 개수 | 1. 새로 깔면 이전 것은 사라지고 남은 횟수 이어받지 않음 | |
| 탄 상한 | 트리 실행 1회당 64개 상한은 사본에 따로, 화면 300개 상한에는 함께 센다 | |
| 결투 | 최대 8번(4T). 지속 6초·0.3초 간격·50% 그대로. 사본 탄은 그 사람의 150 상한에 같이 센다. 같은 발사의 사본 탄은 본체와 한 스침 묶음 | |

```
OnPlayerJFire(shot):                        // 마력 방출 등 비기의 트리 실행에는 따라 쏘지 않는다 [원문 "J로"]
  c = transcribeCircle
  if c == null: return
  if now - c.lastCopyTick < 18: return       // 0.3초 간격: 그 발사는 따라 쏘지 않는다
  Execute(tree=wand.tree, pos=c.pos, dir=self.facing8, dmgMul=1/2, heatExempt=true, side=Player)
                                             // G 4의 Execute를 위치만 바꿔 한 번 더 부른다
  c.lastCopyTick = now; c.shotsLeft -= 1
  if c.shotsLeft == 0: Remove(c)
```

- 검산: 마력탄(0.15초)이면 내 발사 2번에 1번꼴, 3.6초(12회)에 다 쓴다. 간격 0.5초 코어는 6초 동안 12번. 값 12 × 50% = 6T(결투 8 × 50% = 4T). (W 4.3, W 3.5, W 5.4)
- 사본 탄은 임계 배율을 받지 않는다 [임시: Q-11]. 그림자 계약·속성·잠식 배율은 받는다(G 4 공식).
- 쓰는 법: 깔고 옆으로 이동해 두 지점 교차 사격.
- 사본 마법진 그림은 지팡이 단계와 무관한 1벌(96×96, 4프레임). 사본 탄 꾸밈은 지팡이 단계 꾸밈을 50% 투명도로(Wg 4.1, G 확인 66). → 이벤트 `TranscribeCircleSpawned/Copied/Expired`.

## 6. 적 꼬리표별 군중 제어 (W 3.6, G 8) [제안]

이 표가 넉백·당김·빙결·경직·기절·감속의 꼬리표별 수치의 유일한 기준이다(W 3.6). 어느 적이 어느 꼬리표인지는 monsters 2.6.

공통 규칙:

1. **피해는 누구에게나 그대로** 들어간다. 단 **땅속에 있는 동안은 어떤 효과도 받지 않는다(피해 포함)**. 살얼음 적중 횟수는 지워지지 않는다.
2. 경직·기절은 플레이어가 거는 것만 뜻한다. 적이 스스로 멈추는 빈틈은 monsters가 정하고 꼬리표와 무관.
3. 엘리트: 밀림·끌림 거리 절반, 빙결·경직·기절 시간 절반, 감속 그대로, 예고 중인 공격 취소되지 않음. 바탕 종의 꼬리표도 그대로 갖는다.
4. 꼬리표가 겹치면 효과마다 **더 강한 면역** 쪽.
5. 중량·보스: 밀리지 않고 끌리지 않고 얼지 않고 경직·기절하지 않는다. 예외: 보스는 ⑨ 뇌광창 기절을 0.3초 동작 멈춤으로 받는다. 살얼음은 감속으로 바뀐다(중량 −30%, 보스 −15%). 불가마 감속은 중량 그대로, 보스 절반(−10%).
6. 뿌리: 밀리지 않고 끌리지 않는다. 얼리기·경직·기절은 일반과 같다.
7. 비행: 얼음 병풍을 넘어간다(돌진으로 적힌 급강하·활강은 부딪힘). 나머지 일반과 같다.
8. 감속(얼음 송곳, 서리, 불가마, 감속이 된 살얼음)은 더하지 않고 가장 큰 값 하나. 보스에게 블록 감속은 절반(−30%→−15%, −20%→−10%), 엘리트·중량에는 그대로(G 10.3).
9. ② 반동 사격의 돌진 예고 취소는 꼬리표 없는 일반 적에게만.
10. 밑줄, 베껴 쓰기, 그림자 계약, 외상은 내 쪽 수치만 바꾸므로 꼬리표와 무관.

자료 구조와 함수:

```csharp
[Flags] public enum EnemyTag : ushort { None=0, Elite=1, Heavy=2, Boss=4, Flying=8, Burrowed=16, Rooted=32 }
public enum CcKind { Knockback, Pull, Freeze, Stagger, Stun, Slow }

// 반환: 적용할 크기(u 또는 틱 또는 ‰). 0이면 면역. 감속은 ‰(200 = −20%)
int ResolveCc(CcKind kind, EnemyTag tags, int baseAmount, CcSource src)
{
  if (tags.Has(Burrowed)) return 0;                                  // 규칙 1
  bool heavyOrBoss = tags.Has(Heavy) || tags.Has(Boss);
  switch (kind) {
    case Knockback: case Pull:
      if (heavyOrBoss || tags.Has(Rooted)) return 0;
      return tags.Has(Elite) ? baseAmount / 2 : baseAmount;
    case Freeze:                  // 살얼음 전용 → 중량/보스는 Slow로 바꿔 호출측에서 처리
    case Stagger: case Stun:
      if (heavyOrBoss) return (kind==Stun && src==ThunderLance && tags.Has(Boss)) ? 18 /*0.3초 동작 멈춤*/ : 0;
      return tags.Has(Elite) ? baseAmount / 2 : baseAmount;
    case Slow:
      if (tags.Has(Boss) && (src==BlockSlow || src==Kiln)) return baseAmount / 2;
      return baseAmount;
  }
}
```

- 정수 나눗셈 절반: 2칸 12,000u→6,000u, 3칸→9,000u(1.5칸), 0.6초 36틱→18틱, 0.5초 30→15, 1.0초 60→30, 1.5초 90→45. 모두 정수.
- 뇌광창 기절의 보스 처리(0.3초 동작 멈춤)는 monsters 3.2가 주인.

### 7.4 외상(빚) 상태 (W 4.5, G 8, G 10.1) [제안]

| 필드 | 값 |
|---|---|
| `debt` | int 0..2 |
| 생성 | 결정이 모자란 비기를 쓸 때 모자란 만큼. 빚이 2개를 넘지 않는 범위에서만 |
| 수명 | **판이 끝날 때까지**. 웨이브 종료·야영에도 남음. 결투에서는 라운드가 바뀌어도 남음 |
| 상환 | 이후 얻는 결정은 빚부터(콤보, 별똥, 결투 라운드 시작 1개). 웨이브 끝 환전(개당 5골드)은 빚을 갚고 남은 결정에만 |
| 패널티 | 빚 > 0인 동안 받는 피해 +1칸(공격 쪽 한 번 3칸 상한 뒤에 더함 → 최대 4칸. 체력 5칸이라 가득 찬 체력에서 한 방에 죽지 않음) [G 확인 63] |
| 피격 | 빚 > 0일 때 맞으면 결정 파괴 대신 빚 +1(최대 2) |
| 한도 | 빚이 2개면 외상 불가 |
| 만개 | 외상으로 쓸 수 없음 |
| 그림자 계약 | 빚은 0개로 센다 |
| 예 | 결정 0, 빚 1에서 2개짜리 고유 비기 → 외상으로 2개 못 채움 → 부모 양익 사격(1개)이 외상으로 나가고 빚 2 |

- 결정 칸 표시: 빚 결정은 보라 테두리의 빈 칸. "지금 K" 옆 "외상 N". 지팡이에도 빚 1개당 속 빈 연보라 고리(최대 2), +13에서는 발밑 별 중 빚만큼 속 빈 고리(Wm 4.4) → `CrystalView.debt`.

### 7.5 결투에서의 결정 손실 (W 5.4, O 4.3) [제안 / G 확인 43·44]

공통: 피격 벌칙(콤보 0, 결정 파괴)은 1.0초(60틱)에 1회. 발동하면 60틱 벌칙 창이 열리고, 창 안의 피격은 피해만 준다. 결정은 라운드마다 1개로 시작.

성에의 금(crack):

```
state: crack ∈ {0,1}, 라운드 시작 시 0. 시간으로 지워지지 않는다
OnDuelPenalty(seonge):
  combo = 0
  if crack == 0: crack = 1                    // 결정 그대로
  else: crystals = max(0, crystals - 1); crack = 0
// 벌칙 창 안의 피격은 crack을 올리지 않는다. 가장 빨라도 2.0초에 1개
```

그믐의 외상(결투): 4.5의 다섯 규칙을 "맞으면" → "벌칙이 발동하면"으로 읽는다.

```
OnDuelPenalty(geumeum):
  combo = 0
  if debt > 0: debt = min(2, debt + 1); extraDamage = 100     // +1칸 = +100, 벌칙 발동 피격에만
  else: crystals = max(0, crystals - 2)
OnDuelRoundStart: crystals = 0; GainCrystal(1)                // 빚부터 갚는다
```

- 그 밖의 캐릭터: 벌칙 1회에 결정 1개.
- 결정을 잃는 속도: 다른 캐릭터 1.0초에 1개, 그믐 1.0초에 2개, 성에 2.0초에 1개.
- 표시: 성에의 금이 1인 동안 결정 칸 맨 끝 결정에 금 간 표시 → `CrystalView.crack`.

### 9.1 지팡이 개체 (O 1.1, O 1.6, O 5.5, O 7.9, G 9) [확정: 개체·개수 제한 없음 / 제안: 열]

```csharp

  public long OwnerId;

  public int  DropCount;                       // 하락 횟수(거래해도 유지)
```

불변식:

- `Stage ≤ 13`, `FloorPeak ≥ Stage`(거래 직후 같음), `RecordPeak ≥ FloorPeak`, `SlotsExtra ≤ 3`, `Mutations.Length ≤ (Character==2 ? 3 : 2)`, `Aura ≤ 3`.
- 연결 슬롯 수 = `BaseLinkSlots(캐릭터)`(4, 갈피 5) + `SlotsExtra`. 코어 슬롯 1개는 따로. (G 4, O 1.1)
- 캐릭터마다 손에 있는 지팡이가 1자루는 남아야 한다(마지막 한 자루는 팔기·주기·떠나보내기 불가). 장터 등록 중·우편 미수령은 이 1자루로 치지 않는다. (O 1.6) [제안 / 개수 제한 없음은 D 1.22 확정]
- 새 지팡이: 캐릭터마다 +0 한 자루로 시작(역대 최고 +0, 하락 0, 변이 없음, 확장 0, 기운 0, 출발 조립 = 코어 마력탄 1개). 골드 상점에서 +0을 500골드에 산다(빈 조립). (O 1.1, O 1.6) [제안]
- 판에는 그 캐릭터의 지팡이 한 자루를 들고 나가고 판 중에는 바꾸지 않는다(그 한 자루만 "원정 중" 잠금). 결투도 입장 때 든 지팡이로 고정. (G 10.1, O 1.6)
- 강화 단계는 판 중에 변하지 않는다(유리 지팡이 임시 하락은 9.5). (O 1.1)
- 강화 규칙은 자루마다 따로 돈다. 기운·역대 최고가 다른 자루로 넘어가지 않는다. (G 9, G 10.1)

### 9.2 강화 배율 (G 4, G 9, O 4.2) [제안]

- 무한 웨이브: `1.15^단계`(+13 ≈ 6.2배). 결투: `1 + 0.03 × 단계`(+13 = 1.39배).
- 모든 비기도 강화 배율을 받는다(G 8). 패시브·고유 비기의 nT도 T가 강화 배율을 포함하므로 받는다(0.4).
- 실수 pow 대신 아래 표를 자료로 둔다(Q16.16, 반올림).

피해 공식에서의 자리(G 4):

`기본 × 강화 배율 × (1 + 변형 보너스 합) × 변이 배율 × 임계 배율 × 비기 배율 × 감쇠^깊이 × 속성 배율 × 대상 상태 배율 × 캐릭터 배율`

- 임계 배율 = (과열 3배 블록 있으면 3, 없으면 2) + (유리 지팡이 변이 있으면 1). 임계가 아니면 1. 비기 배율과 같이 적용하지 않는다.
- 감쇠 = 0.85(갈피 0.92). 속성 = 약점 1.25 / 저항 0.8 / 그 밖 1(결투는 1). 대상 상태 = 잠식 1.15(결투 +8%). 캐릭터 배율 = 그믐 1+0.03k, 다른 캐릭터 1.
- 변이 배율 = 뒤틀린 총열 있으면 ×1.6, 없으면 1 [조율: G 9 표의 "변이 배율 ×1.6"].

### 9.3 단계가 바꾸는 것과 바꾸지 않는 것 [확정: 14단계 모양과 효과 / 제안: 그 밖]

### 9.5 유리 지팡이의 판 안 임시 하락 (G 9, O 1.3, Wd 7.1) [제안]

```
RunGlassState { int tempDrops; int lastDropWave = -1; }
EffectiveStage(run) = (wand.Stage > 3) ? max(3, wand.Stage - tempDrops) : wand.Stage
OnHit (무한 웨이브, mut.glass_wand 보유):
```

### 10.1 하락 흔적 (D 1.15 [확정], E 1.3 [개발자], O 1.3)

```
ScarCount(wand) = min(2, wand.RecordPeak - wand.Stage)      // 0이면 흔적 없음
```

- 강화로 생기는 차이는 하락 바닥 때문에 2가 끝이지만, 거래로 받은 지팡이는 바닥이 다시 잡혀 차이가 2보다 커질 수 있다. 그래도 흔적은 2개까지 그리고, 정확한 차이는 "역대 최고 +N, 지금 +M" 글자가 알린다. (Wc 4.3)
- 흔적이 생길 수 있는 가장 낮은 단계는 +3이다(하락은 +4 이상에서만 일어나므로 하락으로 닿는 가장 낮은 단계가 +3). (Wd 7.1) [제안]
- 역대 최고 단계까지 다시 올리면 흔적 조각이 하나씩 떨어져 나간다(성공 연출 0.40초 시점). (E 1.3)

보이는 곳(E 1.3이 주인. 다섯 지팡이 공통):

| 보는 사람 | 흔적·"역대 최고 +N"·하락 횟수·이력 꼬리표 |
|---|---|
| 본인(강화 화면, 손 그림, 보관함, 자기 살펴보기) | 항상 보임. `ShowScars == false`면 흔적 옆에 가림 표시 |
| 남(광장, 결투, 살펴보기, 순위표 프로필) | `ShowScars == true`일 때만. 끔이면 흔적 없는 현재 단계 그림과 현재 단계 숫자만 |
| 거래(직접 거래 창, 최종 확인, 장터 목록·미리보기·상세) | **설정과 무관하게 항상**: 흔적 + "역대 최고 +N, 지금 +M" + 하락 횟수. 거래 창에 올리는 순간 주인 화면에 "거래 상대에게는 흔적이 보인다" |

```
bool ScarVisibleTo(viewer, wand, context) =
   viewer == wand.OwnerId || context ∈ {TradeWindow, TradeConfirm, MarketList, MarketDetail} || wand.ShowScars
```

- 설정 이름은 다섯 지팡이 모두 "흔적 공개" 하나, 강화 화면 왼쪽 칸에서만 바꾼다(설정 화면에 없음), 지팡이마다 따로, 기본 끔. (E 1.3) [기본값: G 확인 23]
- 고드름 홀의 "녹은 횟수 N번"과 "한 번도 녹지 않은"(하락 0번인 +10 이상) 꼬리표도 같은 설정을 따른다(Ws 5.4) [G 확인 24].
- 하락 직후 결과 카드에 "흔적이 남았다 · 지금은 [비공개]" 한 줄과 바꾸는 단추(E 1.3).

## 11. 변이 6종 (G 9, O 4.2, O 1.3) [제안]

- 변이는 강화 실패로만 생긴다(O 1.1). 보유 수 2(초롱 3), 넘치면 가장 오래된 것을 밀어냄(7.2).
- 같은 변이를 두 번 가질 수 있는지: 원문 없음 → [임시] 이미 가진 변이는 후보에서 뺀다(Q-17).
- 변이의 난수(불안정 핵, 뒤틀린 총열)는 **판 씨앗에서 갈라 낸 난수기**를 쓴다(G 9). 변이 제거는 강화 화면에서(1개 3,000골드, O 1.6).
- 결투에서 발동하지 않는 변이는 표식만 보이고 전투 연출 없음(Wd 7.2).

| id | 이득(무한 웨이브) | 대가(무한 웨이브) | 결투 | 코어 값 |
|---|---|---|---|---|
| `mut.twisted_barrel` 뒤틀린 총열 | 변이 배율 ×1.6 | 탄도 ±25도 흔들림 | 동일. 조준 보정(10도) **뒤에** 흔들림을 더한다(O 4.4) | `mutMul = 8/5`, 흔들림 각 = 난수 균등 [−25°, +25°] [임시: 분포 Q-18] |

| `mut.mirror_image` 거울상 | 뒤로도 동시 발사(J 발사와 마력 방출에만, 64개 상한에 포함) | 발사당 열 +50% | 동일 | 열 `× 3/2`, 뒤 방향 = 시야 + 180° |

결합 규칙:

- 임계 시작을 바꾸는 효과는 가장 낮은 값(9.4). 예: 달구(80) + 과민 회로 → 70.
- 과민 회로 잠금 +1.5초는 캐릭터 잠금에 더한다: 달구 4.5초, 초롱 4.0초, 갈피 5.0초, 성에·그믐 4.5초 [조율: 덧셈 해석].
- 탐식의 냉각 절반과 다른 냉각 값: `CoolHuPerTick`(캐릭터) / 2 → 초롱 25/초(50hu/틱), 그 밖 22.5/초(45hu/틱).
- 거울상 열 +50%는 발사 1회 총열(밑줄 적용 뒤, 분열 배수 적용 뒤)에 곱한다 [임시: Q-20]. 불가마 흡수는 곱한 뒤의 열에서.
- 불안정 핵 자폭은 "과열 잠금"이다 → 잠금 길이는 2초 고정(캐릭터 잠금이나 과민 회로를 더하지 않는다) [임시: Q-04]. 자폭은 플레이어에게 피해를 주지 않는다 [임시: Q-04].
- 유리 지팡이 + 과열 3배 블록 → 임계 배율 4.
- 조립 화면 경고: 효과 없는 조합(예: 그림자 구체 + 관통 +2)처럼 불안정 핵이 붙은 지팡이에서 코어를 폭발 블록이 아닌 것으로 바꾸면 이득이 없다 → 경고 [임시].

### 12.3 겉모습 묶음 자료 구조 [조율: 다섯 문서의 구조를 하나로 합침, C-10]

```csharp
public readonly record struct AppearanceKey(byte WandKind, int? SkinId, byte Stage);

public sealed class StageAppearance {         // (종류, 단계)마다 1개. 코드에 단계별 분기를 쓰지 않는다 (Wc 8, Wm 7.4)
  public string HandSpriteSet;               // 3방향(성에 2벌) × 2자세 × 대기 프레임
  public string BigSpriteSet, IconSprite;
  public AnchorTable Anchors;                // 방향별: head, muzzle, mutationSites[], slotMarker, extra sockets
  public string IdleFx, TrailFx, MuzzleFx, HitFx, CritHitFx, KillFx, SoundSet;
  public ParticleRequest Particles;          // 12.5
  public int TrailLengthPx;                  // 12.5
}
public sealed class SkinOverride {            // 덧씌움 0..1개 (O 7.9 `skin_id`)
  public int SkinId; public byte WandKind;
  public SkinSource Source;                  // Record | Season | Trade | Shop(항목 0개로 출시) | Default
  public bool AccountBound;                  // 후계자 전용 = true
  public PaletteSwap? Palette;               // 색 바꿈
  public string? Ornament, TrailOverride, EnhanceFxOverride, SoundTimbre;
  public Dictionary<byte,StageAppearancePatch>? PerStage;   // 없는 단계는 기본으로 되돌아감 (Wm 7.4)
}
StageAppearance Resolve(AppearanceKey k) => Base[k.WandKind][k.Stage].With(Skin(k.SkinId)?.PatchFor(k.Stage));
```

덧씌움이 지켜야 할 것(검사 함수로 자료 등록 시 자동 검사, Ws 7.3):

1. 실루엣·단계 표식을 바꾸지 못함: 윤곽이 기본 그림에서 2px 넘게 벗어나지 않음(Wg 8.4). 변이 표식·슬롯 표식·흔적·봉인 끈·빚 고리는 어떤 덧씌움 위에도 같은 자리에 그린다.
2. 위험색(색상각 330~15°이면서 채도 70% 이상, 명도 70% 이상) 금지(D 2.2).
3. 입자 요청량과 꼬리 길이·불투명도 상한(12.5)을 넘지 않음. 탄의 속성색은 못 바꾼다(꼬리 그림만).
4. 능력치·판정·강화 확률을 바꾸지 않는다. 지팡이 코드에서 겉모습 id를 읽는 곳은 "어떤 그림 묶음을 불러올지" 한 곳.
5. 출처 "상점"은 값만 정의, 항목 0개. 덧씌움이 없을 때 빈 칸·자물쇠·"준비 중" 표시 없음(장착 칸은 덧씌움을 하나라도 가진 사람에게만). 서버가 소유를 확인하지 못하면 기본 겉모습. (D 1.14 [확정], O 9)
6. 후계자 전용은 계정 귀속, 그 밖의 시즌 한정은 거래 가능(D 2.7 [확정]). 거래 시 지팡이의 덧씌움은 벗겨져 주는 쪽 옷장으로(O 5.5).

| 5 | 머리 | 손 위 막대(총열), 구슬 겉(핵), 막대+눈꺼풀(회로), 금테 아래(탐식), 막대 아래 끝(거울상), 막대 재질(유리) | 손 아래 막대 금 가락지(4px 간격, 틈보다 위) | 뜬 조각마다 소켓 1점, 달 겹그림 자리, 부적 묶는 자리 | 단계 × 3방향 |

- 변이가 윤곽을 바꾸는 것(뒤틀린 총열, 거울상)은 단계 표식(머리·몸통 윤곽, 등·침·고리 수, 머리 팔 수 등)을 건드리지 않는 자리에만 붙는다(Wd 7.2, Wc 4.4, Ws 5.5). 변이 덧그림은 단계 실루엣을 4px 넘게 바꾸지 않는다(Wg 6.5).
- 그리는 순서(갈피): 본체 → 유리 → 탐식 마스크 → 끝·가운데·밑 덧그림 → 슬롯 꼬리표 → 지운 자국(Wg 6.5).
- 변이 아이콘 6종과 변이 표식 고리는 다섯 지팡이 공용(E 20.1). 살펴보기·거래 확인은 변이 아이콘 + 이름 + 이득·대가 한 줄을 글자로 따로 보여 준다(그림만으로 판별하게 두지 않는다).

## 13. 판 사이에 남는 캐릭터 성장 (W 6) [제안]

### 13.1 칭호 (W 6.1)

지팡이 강화 단계 칭호(닉네임 앞, 그 캐릭터의 든 지팡이 기준 [임시: Q-25]). 단계가 떨어지면 내려가고 최고 기록은 프로필에 남는다.

### 13.3 치장 (W 6.3)

## 18. 시각/소리 연결점 (이벤트 이름만, 구현 안 함)

코어는 아래 이벤트를 틱 순서대로 내보낸다. 그림·소리 쪽은 `(이벤트, 지팡이 종류, 단계 묶음 또는 단계, 덧씌움)`으로 에셋을 찾는다. 이벤트 이름은 PascalCase, 에셋 열쇠는 `fx.{wand|char}.{N}.{event}.{tier|stage}` / `sfx.…` 형식 [제안].

### 18.1 캐릭터·패시브·고유 비기
