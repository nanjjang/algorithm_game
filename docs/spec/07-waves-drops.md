## 1. 영역 요약

이 영역의 코어 기능(모두 `Wizard.Sim` 결정론 코어 안, 단 재료 추첨은 정산기 안):

1. 웨이브 번호 → 날, 하루 속 순번, 시간대, 보스 종류 계산.
2. 웨이브 번호 → 체력 배율, 스폰 예산, 묶음 수, 동시 예고 상한, 엘리트 수, 피해 보정.
3. 웨이브 구성 생성(1~12 고정 각본, 13부터 틀) + 묶음 방출 + 지체 방지.
4. 변덕 선택과 적용.
5. 웨이브 종료 → 드랍 회수 → 전리품 카드 → 야영 → 출발의 상태 기계.
6. 시작 웨이브 고르기.
7. 점수(정수) 계산과 서버 즉시 검사용 상한.
8. 판 중 드랍(골드, 카드, 체력 조각, 주화)과 기회 목록(재료·부적·한정 드랍) 기록.
9. 정산: 귀환 가방, 골드 환전, 재료 추첨.
10. 씨앗 분기와 재실행 결정론.

## 3. 하루와 웨이브 번호

### 3.1 함수 [M4.1, M6 낱말] [확정]

```
// w ≥ 1 (누적 웨이브 번호). 기록과 모든 곡선은 누적 웨이브를 쓴다.
int Day(int w)        => (w + 9) / 10;            // ceil(w/10). 웨이브 1~10 = 1일째
int LocalWave(int w)  => (w - 1) % 10 + 1;        // 하루 속 순번 1..10
Tod TimeOfDay(int w)  => LocalWave(w) switch { 1..4 => Day, 5..7 => Dusk, 8..9 => Night, 10 => Boss };
bool IsBossWave(int w)=> w % 10 == 0;
bool IsFifthWave(int w)=> w % 10 == 5;            // 웨이브 5, 15, 25 … (= 10d − 5)
string RecordLabel(int w) => $"{Day(w)}일째 웨이브 {w}"; // 예: "3일째 웨이브 23"
```

- 시간대는 실제 시간이 아니라 웨이브 번호로 정한다. 같은 웨이브면 누구에게나 같은 시간대다 [M4.1].
- 보스를 잡으면 해가 뜨고 다음 날의 낮이 시작된다 [M4.1].
- 밤에도 예고 구역, 탄, 플레이어, 적의 밝기는 낮과 같다. 시야를 가리는 어둠은 없다 [M4.1, G2.2] [확정].
- 밤에만 있는 것은 스폰 가중치와 돌발 사건 "별똥 결정"뿐이다 [G2.2, W2.3] (별똥 결정: 밤 웨이브 8~9, 웨이브당 1회 이하, 1.5초 예고 뒤 빈 바닥에 떨어지고 8초 안에 밟으면 마력 결정 +1. 이 명세의 범위 밖이지만 발생 판정에 판 씨앗 분기 `rng.event`를 쓴다 — 14.2절).
- 시간대 전환 연출: 야영 중 4초(240틱)에 걸쳐 색이 바뀐다. 웨이브 4 뒤, 7 뒤, 9 뒤, 10 뒤의 야영. 9 뒤에는 달이 뜬다 [M4.1, W2.2]. 표시 계층 일이며 게임 시간에 영향 없음 [O3.1].
- 전투 중에는 바닥 색이 바뀌지 않는다 [G2.2].
- 화면 표기: "3일째 · 웨이브 27 (해질녘)" [W2.2].
- 날이 바뀔 때마다 풀밭 무늬와 소품 배치를 6벌 중 다음 것으로 돌린다(겉모습만) [W2.2] → 표시 계층 이벤트 `day.changed`.

### 3.2 전장 [G2.2, D2.3] [확정]

- 24×14칸, 사방이 막혀 있다. 전장은 한 곳.
- 적은 네 변 중 **플레이어에게서 먼 두 변**에서 나온다.
  - 구현 [임시]: 스폰 순간 플레이어 위치 (px, py) 기준. 가로 변: `py < 7칸`이면 위 변(y=14 쪽), 아니면 아래 변. 세로 변: `px < 12칸`이면 오른쪽 변, 아니면 왼쪽 변. 두 변 위에서 각 개체 위치를 `rng.wave_spawn`으로 고르며, 모서리 1칸과 다른 개체 1칸 이내는 피한다. 정확히 가운데(7칸, 12칸)면 위·오른쪽.

## 4. 판 전체 상태 기계

### 4.1 상태

```
enum RunPhase {
  StartCamp,       // 시작 웨이브를 골라 건너뛴 경우의 출발 새벽 야영 (카드 없음)
  WavePrelude,     // 출발 직후. 좁은 들의 3초 예고 구간(없으면 0틱)
  BossIntro,       // 보스 웨이브 시작 1.2초(72틱): 화면 멈춤 + 이름 띠. 플레이어 무적, 이동 가능
  WaveCombat,      // 전투
  PhantomFinale,   // 첫 만남 마무리 "되비침" 180틱, 입력 무시
  PhantomDowned,   // 첫 만남 "쓰러짐" 240틱
  WaveClearing,    // 마지막 적 사망 후 드랍 빨아들이기 60틱
  LootPick,        // 전리품 카드 고르기
  Camp,            // 야영
  RunEnded         // 정상 종료(체력 0 / 판 포기). 비정상 종료는 코어 밖(서버/기기)에서 처리
}
```

### 4.2 전이

| 현재 | 조건 | 다음 | 동작 |
|---|---|---|---|
| (시작) | `start_skip == 0` | WavePrelude(w=1) | 체력 가득, 결정 0, 원정 지갑 0 |
| (시작) | `start_skip ∈ {10,20,…}` | StartCamp | w_next = skip+1. 건너뛴 점수 합산(10.4절). 건너뛴 구간에 비기 해금 차례가 있었다면 여기서 차례대로 고른다 [M4.7] |
| StartCamp | 출발 | WavePrelude(w_next) | |
| WavePrelude | 남은 예고 틱 0 | 보스면 BossIntro, 아니면 WaveCombat | wave_tick = 0 시작(좁은 들 예고 구간은 시간에 넣지 않음 [임시]) |
| BossIntro | 72틱 경과 | WaveCombat | 보스 웨이브의 `wave_tick`은 BossIntro 시작부터 센다 [임시] |
| WaveCombat | 일반 웨이브: 웨이브의 모든 적(묶음 전부 방출 + 생존 0) | WaveClearing | 클리어 처리(11.1절) |

| PhantomDowned | 240틱 경과 | WaveClearing → LootPick | "일어남": 체력 가득, 열 0·잠금 해제, 콤보 0, 결정 유지(웨이브 종료 환전 평소대로), 그믐의 빚 0. 웨이브 10을 "직접 넘김"으로 기록. 새벽 야영 무료 회복 1칸은 이 회복에 포함 |

| LootPick | 2장 확정 | Camp | |
| Camp | 출발 표식 위에서 J 60틱 유지, 또는 화면의 출발 | WavePrelude(w+1) | |
| 어느 상태든 | 일시정지 메뉴 "판 포기" | RunEnded(abandon) | 정상 종료. 그때까지 직접 넘긴 웨이브 전부 정산 [O3.2] |

### 4.3 정상 / 비정상 종료 [O3.2] [확정: 절차는 제안]

| 종류 | 원인 | 정산 범위 |
|---|---|---|
| 정상 종료 | 체력 0, 판 포기 | 그때까지 **직접 넘긴** 웨이브 전부 |
| 비정상 종료 | 강제 종료·기기 고장으로 종료 요약 미제출 → "원정 정리" | 마지막 중간 지점(5웨이브마다)까지. 중간 지점이 없으면 보상 없이 잠금만 품. 가방은 등급 높은 것부터 자동. 순위 미반영 |

- 중간 지점: 웨이브 `w`를 넘겼고 `w % 5 == 0`일 때 기록(틱, 상태 해시, 점수, 원정 지갑, 입력 기록). **지급이 아니라 기록**이다 [O3.2, M6.3].
- 원정 잠금은 이 셋으로만 풀린다(시간으로 풀지 않는다) [O3.2].

## 5. 웨이브 진행 상수 함수

### 5.1 스폰 예산 B(w) [M4.3] [제안]

```
int Budget(int w) => w <= 12 ? 10 + 6*w : Math.Min(200, 82 + 4*(w - 12));
```
- 상한 200은 웨이브 42에서 처음 적용(41: 198, 42: 202 → 200) [M4.3].
- 보스 웨이브에는 예산이 없다 [M4.3, M3.2]. `Budget`은 보스 웨이브에서 호출하지 않는다(호출 시 0 반환 [임시]).

### 5.2 묶음 수와 간격 [M4.3]

```
int BundleCount(int w) => w <= 12 ? 4 : Math.Min(8, 4 + (w - 12) / 8);
```
- 간격 420틱(7초), "몰려옴"이면 240틱(4초). 또는 살아 있는 적이 3마리 이하가 되면 즉시 다음 묶음 [GDD].
- 전장 동시 개체 상한 40. 넘으면 다음 묶음이 기다린다.
- "살아 있는 적" 수에는 갈라진 슬라임·불러낸 박쥐도 포함 [임시].

### 5.3 동시 예고 상한 [M4.3] [제안]

```
int TelegraphCap(int w) => w <= 4 ? 2 : w <= 8 ? 3 : w <= 12 ? 4 : w <= 29 ? 5 : 6;
```
- 상한 안에서도 R5(전장 0.5칸 격자 48×28, 0.05초=3틱 단위 BFS, 정수 계산, 탄 제외)를 통과해야 새 예고를 시작한다 [M1.2].
- 예고 상한이나 R5에 걸린 적은 예고를 시작하지 않고 같은 대기 줄에 선다. 2초(120틱) 넘게 기다리면 가장 오래 기다린 적부터 다시 검사한다 [M1.2].
- 예고가 없는 적(박쥐·슬라임)은 상한과 무관 [M4.3].
- R5 자체의 구현은 적 AI 명세 몫이다. 이 영역은 상한 값과 대기 줄 순서만 준다.

### 5.4 엘리트 수 [M4.3] [제안]

```
int EliteCount(int w, bool chiefMarch) {
  if (IsBossWave(w) || w < 12) return 0;
  int n = w <= 19 ? 1 : w <= 29 ? 2 : w <= 39 ? 3 : 4;
  return n + (chiefMarch ? 2 : 0);
}
```
- 엘리트는 예산에서 비용 ×3으로 지불 [M4.3]. "우두머리 행차"의 +2는 예산 밖에서 더한다 [조율: 18절 C-07의 점수 상한식 +36이 예산 밖 엘리트 2마리(최대 비용 6×3×2)를 뜻함].
- 엘리트 공통: 체력 ×3, 비용 ×3, 처치 골드 ×3. 속도·예고 시간·약점·저항은 바탕 종과 같다 [M3.1].

### 5.5 종 상한 [M4.3]

선돌지기 3, 가시덩굴 4, 북두꺼비 2, 엄니 멧돼지 3, 솔침 고슴도치 4, 도깨비불 4(긴 밤이면 6). 한 웨이브 **구성 전체**에 대한 상한이다 [임시: "동시"가 아니라 구성 기준으로 해석. 엘리트도 바탕 종 수에 포함].

### 5.6 지체 방지 [M4.3] [제안]

- 일반 웨이브가 `wave_tick ≥ 7200`(120초)이 되면 남은 묶음을 한꺼번에 낸다. 그 뒤 처치 점수는 절반(`cost × 5`).

- 보스 웨이브에는 적용하지 않는다(보스는 최종 격노 180초가 같은 역할) [임시].

## 6. 체력과 피해의 성장

### 6.1 체력 배율 H(w) [M4.2] [제안]

- 웨이브 1~12: `1 + 0.12 × (w − 1)`
- 웨이브 13 이상: `2.32 × 1.06^(w − 12)`

정수 구현 [임시: 표현 방식. 값은 원본 식과 소수 넷째 자리까지 같다]:

```
long HMicro(int w) {
  if (w <= 12) return 1_000_000 + 120_000L * (w - 1);
  long h = 2_320_000;
  for (int i = 0; i < w - 12; i++) h = h * 106 / 100;   // 매 단계 내림
  return h;     // 코어 시작 시 표로 미리 계산해 둔다
}
```
- 오버플로 경계: `h`는 int64 안에서 w ≈ 500 근처까지 안전하다. 체력 계산은 `Int128`(또는 `Math.BigMul`)로 하고 결과 HP는 `int.MaxValue`로 포화시킨다 [임시]. (선돌지기 기준 포화는 w ≈ 268. 6%씩 늘어 그 전에 판이 끝난다는 설계 [M4.2]이므로 실제로는 닿지 않는다.)

### 6.2 적 체력 계산 [M2.1, M3.1, M3.2, M4.5]

```
int EnemyHp(int baseHp, int w, bool elite, bool thickHide) =
  clamp( baseHp * HMicro(w) * (elite ? 3 : 1) * (thickHide ? 130 : 100) / (1_000_000 * 100), 1, int.MaxValue );

int BossHp(int baseHp, int w) = baseHp * HMicro(w) / HMicro(10);   // 웨이브 10에서 배율 1
```
- 보스 체력 = 기본 체력 × `H(w) ÷ H(10)` [M3.2] [제안]. 허상 첫 만남은 웨이브 10이므로 4000 [M3.9.2]. 웨이브 20 허상 ≈ 7,100(정수 7,111) [M3.9.4].
- 보스 웨이브에는 변덕이 없으므로 두꺼운 가죽은 보스에 걸리지 않는다.
- 유폭·돌진 경로 피해처럼 "체력 배율 적용" 피해(꽈리 유폭 20, 멧돼지 경로 10, 북두꺼비 울음 끊기 30 등)도 같은 `HMicro(w)`를 곱한다 [M2.3] (값 자체는 적 명세 몫).

### 6.3 피해 성장 [M4.2] [제안 / 3칸 상한은 확정: G11]

| 구간 | 접촉·탄 | 예고 공격(일반 적) | 예고 공격(엘리트·보스) |
|---|---|---|---|
| 웨이브 1~30 | 1 | 종별 값(1 또는 2) | 종별 값(1 또는 2) |
| 웨이브 31~60 | 1 | 종별 값 | 종별 값 +1 |
| 웨이브 61 이상 | 1 | 종별 값 +1 | 종별 값 +1 |

```
int AttackDamage(AttackKind kind, int speciesValue, bool eliteOrBoss, int w, bool finalRage) {
  int d = kind == Telegraph ? speciesValue : 1;                       // 접촉·탄은 1
  if (kind == Telegraph) {
    if (w >= 61) d += 1;
    else if (w >= 31 && eliteOrBoss) d += 1;
  }
  if (finalRage) d += 1;                                               // 보스 180초 뒤 모든 공격 +1 [M3.2]
  return Math.Min(d, 3);                                               // 어떤 공격도 한 번에 3칸을 넘지 않는다 [확정]
}
int DamageTaken(int attackDamage, bool geumeumDebt) => attackDamage + (geumeumDebt ? 1 : 0);   // 최대 4 [W4.5]
```
- 3칸 상한은 공격 쪽 수치에 걸린다. 빚이 있는 그믐의 +1칸은 그 뒤에 더해 최대 4칸 [M4.2, G11, GDD 확인 63].
- 가장 센 공격(3칸)을 버티는 횟수(가득 찬 체력에서): 달구(8칸) 3회째 사망, 성에(7) 3회째, 갈피(6) 2회째, 그믐(5) 2회째, 초롱(4) 2회째. 접촉과 탄은 끝까지 1칸 [M4.2].
- 속도와 예고 시간은 웨이브가 깊어져도 변하지 않는다 [M1.2, M4.2, G11] [확정 성격].
- 압박은 수, 동시 예고 수, 엘리트, 변덕으로 올린다 [M4.2].
- 기준점(설명용): GDD 기준 빌드는 웨이브 11에 +5(강화 배율 2.01). +13(배율 약 6.2)은 웨이브 31 근처에서 같은 체감 난이도. 그 뒤로는 웨이브마다 처치 시간이 6%씩 늘어 판은 반드시 끝난다 [M4.2].

### 7.3 틀 선택 (웨이브 13 이상의 일반 웨이브, 13·15 제외) [M4.4] [제안 / 임시: 확률]

FrameId PickFrame(int w, FrameId prevFrame, Rng rng) {

  var cand = AllFrames.Where(f => f != prevFrame && PrimaryGroupAvailable(f, w)).ToList(); // 순서 고정

}
```
- `prevFrame`은 직전 **일반** 웨이브의 틀(보스 웨이브는 틀이 없으므로 건너뛰고 그 앞을 본다) [임시].
- `PrimaryGroupAvailable`: 주 묶음에 가용 종이 하나도 없는 틀은 후보에서 뺀다(혼합은 항상 가능) [임시].

### 7.4 예산 배분 절차 (공통) [임시: 원본은 비율만 정함]

```
WavePlan BuildNormalWave(int w, ...) {
  int B = Budget(w);
  int extra = mods.Has(big_herd) ? B * 25 / 100 : 0;          // 큰 무리: 비용 1~2짜리로만 [M4.5]
  var avail = SpeciesAvailable(w, tod, mods);                 // 3.1·2.3 규칙, 긴 밤 반영
  var weights = avail.ToDictionary(s => s, s => s.base_weight * TodMul(tod, s) * LongNightMul(s) / 100);
  int remaining = B;

  // 1) 엘리트 (예산 안)
  for (i < EliteCount(w, false)) {
     s = WeightedPick(avail where cost*3 <= remaining && underCap(s), weights, rng);
     add Elite(s); remaining -= s.cost * 3;
  }
  // 2) 각본/틀의 고정 개수 (예: 사냥대 toad 1, 포대 golem 1~2(rng), 각본의 shaman 1 …)
  // 3) 주 묶음 몫: target = B * share / 100 (내림). 그룹 안 가용 종만, 가중치 추첨,
  //    cost <= 그룹 남은 몫 && 종 상한 미만인 종이 없을 때까지 반복. 남은 몫은 혼합으로 이월
  // 4) 나머지(혼합): 주 묶음 밖의 가용 종 전체로 같은 방식
  // 5) 끝까지 남은 예산(1 이상)은 slime_moss로 채운다 (slime은 상한 없음, 항상 가용, 비용 1)
  //    → 일반 웨이브의 비용 합 = B (정확히). 단 밤의 slime 가중치 50%는 4)에만 적용
  // 6) 큰 무리 추가분: cost ∈ {1,2} 가용 종으로 같은 방식, 남으면 slime
  // 7) 우두머리 행차: 엘리트 2마리 추가(OutsideBudget = true), 종 선택은 1)과 같다(예산 조건 없음)
  // 8) 박쥐는 고를 때마다 무리 k∈[6,8](rng)마리, 남은 몫이 모자라면 남은 몫만큼(최소 1)
}
```
- 가중치 추첨은 정수 가중치 누적합으로 하고 종 순서는 2.2 표 순서로 고정한다(결정론).
- 묶음 나누기 [임시]: 엔트리를 `rng.wave_comp`로 섞은 뒤, 각 묶음의 비용 합이 `ceil(총비용 ÷ 묶음 수)`를 넘지 않게 앞에서부터 채운다. 박쥐 무리는 한 묶음에 함께 둔다. 엘리트는 마지막 묶음부터 거꾸로 하나씩 놓는다.
- 첫 묶음은 웨이브 0틱에 나온다 [임시].

### 7.5 보스 웨이브 [M3.2] [확정: 10웨이브마다, 순서대로]

- 일반 적 예산 없음, 엘리트 없음, 변덕 없음 [M3.2, M4.5, G11].
- 보스가 부르는 졸개만 나온다. 졸개는 점수·골드·드랍 없음.
- 보스 선택: 2.6절. `PhantomFirst` 판정은 8.2절.
- 등장 연출 1.2초(72틱): 화면이 멈추고 이름 띠. 그동안 플레이어는 무적이고 움직일 수 있다 [M3.2].

- 2회차 이상(웨이브 70+): 체력 증가 외에 패턴 하나가 강화된다 [M3.2] (보스 명세 몫).

## 9. 야생의 변덕 선택 [M4.5]

```
ModifierId[] PickModifiers(int w, Tod tod, Rng rngMod) {
  if (IsBossWave(w)) return [];
  int n = w >= 41 ? 2 : w >= 21 ? 1 : 0;
  var pool = AllModifiers.Where(m => m != long_night || tod == Night).ToList();   // 데이터 순서 고정
  return DistinctPick(pool, n, rngMod);    // 균등, 중복 없음 [임시]
}
```
- 다음 웨이브의 변덕은 야영 화면에 미리 보여 준다(조립을 맞출 수 있게) [M4.5].
- 변덕의 효과 적용 순서 [임시]: 큰 무리(예산) → 우두머리 행차(엘리트) → 긴 밤(가중치·상한) → 구성 생성 → 두꺼운 가죽(체력) → 몰려옴(간격) → 느린 탄막(적 탄) → 마지막 숨(사망 시) → 좁은 들(WavePrelude).
- 좁은 들 [임시 세부]: 가장자리 2칸 띠(바깥 테두리에서 안쪽 2칸, Q32.32 = 8,589,934,592)를 가시밭(접촉 규칙: 같은 가시밭에서 1.5초에 1회, 피해 1)으로 깐다. 예고는 WavePrelude 180틱. R5에서 지나갈 수 없는 칸으로 본다. 가시덩굴의 "가시밭 동시 3개" 한도에 세지 않는다. 적 스폰 위치는 가시밭 바로 안쪽(가장자리에서 2칸)으로 옮긴다.
- 마지막 숨 [임시 세부]: 갈라진 슬라임·불러낸 개체의 죽음에도 생긴다("모든 적"). 웨이브가 클리어되면(마지막 적 사망) 아직 터지지 않은 원은 바로 사라진다(4.6절 2번과 같은 처리).
- 느린 탄막의 탄 수: `floor(n × 3 / 2)` [임시], 퍼짐 각은 R3의 1.0칸 간격을 지키도록 적 명세가 넓힌다.

## 10. 시작 웨이브 고르기 [M4.7] [제안, GDD 확인 3번 / online 확인 2번]

### 10.1 규칙

| 항목 | 규칙 |
|---|---|
| 고를 수 있는 값 | 건너뛰는 웨이브 수 `skip ∈ {0, 10, 20, 30, …}`. 그 보스를 막 잡은 새벽 야영에서 판이 시작되고 첫 웨이브는 `skip + 1` |
| 한도 | `skip ≤ (그 캐릭터로 넘긴 최고 웨이브) × 0.7` → 정수: `maxSkip = (best * 7 / 100) * 10` |
| 열림 | `maxSkip ≥ 10` ⇔ `best ≥ 15`. 그 전에는 선택지 자체를 보이지 않는다 [조율: 18절 C-03] |
| 기록의 범위 | 프로필마다 따로. 서버 프로필은 **이번 시즌 그 캐릭터의 최고 웨이브**(서버가 확인), 오프라인은 기기 기록 |
| 주간 도전 | 웨이브 1 출발 고정 |
| 건너뛴 웨이브의 점수 | 10.4절 |
| 건너뛴 웨이브의 보상 | 없다. 골드, 블록, 재료, 시즌 주화, 귀환 가방 칸 모두 직접 넘긴 웨이브만 센다 |
| 출발 상태 | 체력 가득, 결정 0, 출발 조립 그대로. 건너뛴 구간의 비기 해금 차례는 출발 야영에서 차례대로 고른다 |
| 표시 | 순위표와 기록에 "웨이브 21에서 출발"을 같이 적는다 |

- 건너뛴 점수는 식으로만 계산하므로 서버가 그대로 다시 계산해 확인한다 [M4.7].
- 첫 만남(웨이브 10)은 건너뛸 수 없고, 복수 전에는 웨이브 20도 건너뛸 수 없다 — 위 한도에서 자동으로 성립 [M4.7, M3.9].
- 새 프로필은 최고 웨이브 0, 시작 웨이브 선택 없음 [O1.1].

### 10.2 출발 야영 (StartCamp)

- 열리는 탭: 조립, 비기. 체력이 가득이므로 회복은 의미 없음. 전리품 카드 없음(건너뛴 보상 없음). 원정 지갑 0이므로 회복·다시 뽑기 불가 [임시: 원본 규칙에서 유도].
- 다음 웨이브 미리보기는 평소 야영과 같다.

### 10.3 기대 크기 (참고) [M4.7]

| 건너뛴 웨이브 수 | 10 | 20 | 30 | 40 | 50 |
|---|---|---|---|---|---|
| 받는 점수(60%) | 8,398 | 28,859 | 64,764 | 120,409 | 195,829 |
| 직접 넘겼을 때의 기본값(보너스 제외) | 14,000 | 48,104 | 107,948 | 200,692 | 326,392 |

- 60웨이브까지 가는 판에서 20웨이브를 건너뛰면 전체 점수의 약 5~6%를 덜 받는다 [M4.7] (설명용).

### 10.4 건너뛴 점수 식 [M4.7, M4.8, sim:mon_calc]

```
long SkippedScore(int skip) {
  long sum = 0;
  for (int w = 1; w <= skip; w++) {
    long baseRaw = IsBossWave(w) ? 3200 : Budget(w) * 10 + 200;    // "처치 + 클리어" 기본값
    sum += baseRaw * S10(w) * 6 / 100;                               // 웨이브마다 내림
  }
  return sum;
}
```
- 빠른 처리·무피격·스침·변덕 배율은 없다.
- 보스 웨이브 기본값 3200 = 보스 처치 3000 + 클리어 200.

## 11. 웨이브 종료와 야영 [M4.6] [확정: 조립·회복·비기 선택만, 강화 없음 / 절차는 제안]

### 11.1 웨이브 클리어 처리 순서 (코어, 같은 틱 안에서)

1. 클리어 틱 확정 → 걸린 틱 `elapsed = clear_tick − wave_start_tick`.
2. 남은 결정 환전: 개당 5골드(그믐의 빚이 있으면 빚부터 갚고 남은 결정만) [M6.1, O1.1, W4.5].
3. 웨이브 클리어 골드 20(보스 웨이브에도), 보스 웨이브면 보스 처치 골드 [M6.1].
4. 시즌 주화(시즌 켜짐 + 서버 프로필) [M6.4].
5. 기회 목록 추가(다섯 번째 웨이브, 보스 처치, 첫 웨이브 3의 까마귀 보따리, 첫 만남) [M6.3].
6. 웨이브 점수 확정(12.1절).
7. `cleared_direct += 1`. `w % 5 == 0`이면 중간 지점 기록.
8. 남은 예고 구역·가시밭·마지막 숨 원 제거. 체력 조각·골드 등 바닥 드랍은 모두 회수(골드는 처치 때 이미 지갑에 들어갔다 — 13.1절).

### 11.2 야영 절차 [M4.6]

1. 웨이브의 마지막 적이 죽으면 드랍이 플레이어에게 빨려 온다(1.0초 = 60틱, WaveClearing).
2. 전장 가운데에 모닥불이 피어난다. 남은 예고 구역과 가시밭은 모두 사라진다.
3. 전리품 선택(13.2절)이 먼저 뜬다. 고른 블록은 판 중 보관함(12칸)에 들어간다.
4. 모닥불 옆에서 J를 누르면 야영 화면이 열린다. 탭은 [조립 | 비기] 둘이고, 체력 회복과 허수아비 연습이 있다. **강화 탭은 없다** [확정]. (전리품 다시 뽑기의 자리는 18절 C-08.)
5. 시간 제한은 없고, 야영 중에는 점수의 시간 계산이 멈춘다(`wave_tick`이 흐르지 않는다).
6. 야영 화면에 다음 웨이브의 시간대, 틀 이름, 변덕, 나올 종의 약점·저항 문양, (보스 웨이브면) 보스 이름, 그 웨이브에서 확정으로 받는 재료(표 6.3-B, 6.3-C)를 보여 준다. 화면 한쪽에 "지금 판을 끝내면 가져가는 귀환 가방 칸수와 영웅 한도"를 항상 적는다.
7. 모닥불 반대편의 "출발" 표식 위에서 J를 1초(60틱) 누르면 다음 웨이브가 시작된다. 야영을 건너뛰고 바로 출발해도 된다.

- 보스를 잡은 뒤의 야영은 "새벽 야영": 체력 1칸 무료 회복(GDD의 웨이브 11 뒤 무료 회복을 옮긴 것) [M4.6, G12].
- 첫 만남 직후 야영은 새벽 야영이고 체력은 이미 가득(무료 회복 포함) [M3.9.2].
- 첫 만남 전의 웨이브 9 뒤 야영: 다음 웨이브 칸에 보스 이름 "스승의 허상"이 평소대로 뜬다(이길 수 없다는 것은 미리 알리지 않는다) [M3.9.2, U4.11].
- 야영에서 가방에 담을 블록은 고르지 않는다. 고르는 곳은 판이 끝난 뒤의 정산 화면 [M4.6].
- 비기: 해금은 계정에 캐릭터별로 남는다 [확정: D2.8]. 해금 차례(GDD 8절 [제안]): 웨이브 1~6을 넘길 때마다 그 캐릭터가 해금하지 못한 공용 비기 후보 2개에서 1개 무료 선택(공용 8종 다 해금하면 차례 없음, 부모 기술이 있어야 후보, 뇌광창은 꿰뚫는 창 + 웨이브 4 이후, 만개는 팔방 전개 + 웨이브 6 이후). 이 차례의 판정은 비기 명세 몫이며, 이 영역은 "야영에 들어올 때 차례가 있는가"를 알려 주는 훅 `camp.skill_unlock_due`만 둔다.

### 11.3 야영 비용 [M4.6, M6.2.1] [제안]

```
int HealCost(int wJustCleared, int healsThisCamp) {
  int baseCost = 30 + 5 * wJustCleared;                      // "30 + 5 × 웨이브" — 방금 넘긴 웨이브 [임시]
  return healsThisCamp == 0 ? baseCost : baseCost * 3 / 2;   // 같은 야영에서 두 번째부터 1.5배 (누적 아님)

- 판 중에 번 골드(원정 지갑)에서만 낸다. 지갑이 모자라면 불가 [M4.6, G12].
- 야영 행동(조립 변경, 회복 구매, 카드 선택, 다시 뽑기, 출발)은 재실행을 위해 입력 기록에 `CampCommand`로 남긴다 [임시: 19절 U-15].

## 12. 점수 [M4.8] [제안]

### 12.1 항목 (원본 식)

웨이브 계수 `S(w) = 1 + 0.1 × (w − 1)`, 정수로는 `S10(w) = 9 + w`.

| 항목 | 점수 | 정수 원점수(raw) |
|---|---|---|
| 처치 | 비용 × 10 × S(w). 엘리트는 비용이 이미 3배 | `cost × 10` (엘리트 `cost×3×10`). 지체(120초) 뒤에는 `cost × 5` |
| 보스 처치 | 3000 × S(w) | 3000 |
| 웨이브 클리어 | 200 × S(w) | 200 |
| 빠른 처리 | `max(0, 목표 시간 − 걸린 시간(초)) × 2 × S(w)`. 목표 일반 60초, 보스 120초 | 틱으로: `max(0, 목표틱 − 걸린틱) × 2 ÷ 60` (목표틱 3,600 / 7,200) |
| 무피격 웨이브 | 100 × S(w) | 100 |
| 스쳐 피하기 | 1회당 5 × S(w). 일반 웨이브 20회, 보스 웨이브 40회까지 | `5 × min(graze, cap)` |
| 허상과의 첫 만남 | 고정 `3200 × S(10) × 0.6 = 3,648`. 다른 항목 없음 | 고정 |

- 점수가 없는 것: 보스가 부른 졸개, 엘리트가 낳은 개체(갈라진 슬라임, 불러낸 박쥐), 120초를 넘긴 뒤 처치의 절반, 최종 격노(180초) 이후의 스침, 첫 만남 중의 스침과 입힌 피해 [M4.8].
- 야영 시간은 점수에 영향이 없다 [M4.8].
- "무피격": 웨이브 동안 체력이 한 번도 줄지 않음 [임시: 정의].
- 보스 웨이브의 "걸린 시간"은 BossIntro 시작부터 보스 사망까지 [임시].

### 12.2 정수 계산 [M4.8 정수 규칙 + 임시: 내림 위치]

```
long WaveScore(WaveTally t) {
  if (t.PhantomFirst) return 3648;
  // 빠른 처리의 ÷60까지 한 번에 내림하기 위해 raw를 60배 단위로 든다
  long raw60 = 60L * (t.KillRaw + (t.Boss ? 3000 : 0) + 200 + (t.NoHit ? 100 : 0)
                      + 5L * Math.Min(t.Grazes, t.Boss ? 40 : 20))
             + 2L * Math.Max(0, (t.Boss ? 7200 : 3600) - t.ElapsedTicks);
  long baseScore = raw60 * S10(t.Wave) / 600;                     // S(w)의 ÷10과 빠른 처리 ÷60을 한 번에 내림
  foreach (var m in t.Modifiers) baseScore = baseScore * m.ScorePct / 100;   // 변덕마다 곱하고 내림
  return baseScore;
}
long RunScore = Σ WaveScore(직접 넘긴 웨이브) + SkippedScore(skip);
```
- 원본 정수 규칙: S(w)는 10배 정수 `9 + w`로 들고 웨이브 점수를 낼 때 한 번만 10으로 나눠 내림. 걸린 시간은 틱(60/초). 변덕 배율은 100배 정수(115, 120, 125)로 곱하고 100으로 나눠 내림 [M4.8]. 내림 위치를 하나로 합친 것과 변덕 2개의 순차 내림은 [임시].
- 마지막 웨이브(죽은 웨이브)는 넘기지 않았으므로 점수에 넣지 않는다 [임시: "직접 넘긴 웨이브 점수의 합"에서 유도]. 그 웨이브에서 잡은 적의 처치 점수도 버린다 [임시].
- 계산은 정수로만 한다(서버 재실행이 같은 숫자를 얻어야 함) [M4.8, M7] [확정 성격].

### 12.3 서버 즉시 검사 상한 [M4.8, M7] [제안 / 조율: 18절 C-07]

```
long WaveScoreCap(int w, ModifierId[] mods) {
  if (IsBossWave(w)) return (w == 10 && phantomFirst) ? 3648 : (3000 + 200 + 240 + 100 + 200) * S10(w) / 10;
  long b = Budget(w) + (mods.Has(big_herd) ? Budget(w) * 25 / 100 : 0);
  long raw = (b + (mods.Has(chief_march) ? 36 : 0)) * 10 + 200 + 60 * 2 + 100 + 20 * 5;
  long cap = raw * S10(w) / 10;
  foreach (m in mods) cap = cap * m.ScorePct / 100;
  return cap;
}
long WaveGoldCap(int w, ModifierId[] mods) {          // 결정 환전·버린 블록 골드 제외
  if (IsBossWave(w)) return (w == 10 && phantomFirst) ? 20 : 20 * (9 + w) + 20;   // 200×S(w) + 20
  long b = Budget(w) + (mods.Has(big_herd) ? Budget(w) * 25 / 100 : 0);
  return 2 * b + (mods.Has(chief_march) ? 72 * 3 : 0) + 20;
}
```
- 원본 식(점수): `[(B(w) × 1.25 + 36) × 10 + 200 + 목표 시간 × 2 + 100 + 스침 상한 × 5] × S(w) × 변덕 배율 최댓값`. 보스: `(3000 + 200 + 240 + 100 + 200) × S(w)`. 예: 웨이브 29(변덕 없음) 7,676점, 웨이브 30 보스 14,586점 [M4.8].
- 원본 식(골드): `2 × B(w) × 1.25 + 72 × 3 + 20`, 보스 웨이브 `200 × S(w) + 20` [M7].
- 서버는 판 씨앗으로 `rng.modifier` 분기만 돌려 그 웨이브의 변덕을 계산할 수 있다(14.2절) — 상한을 변덕에 따라 조건부로 거는 근거.

### 12.4 기록 [M4.8]

- 판 점수와 함께 도달 웨이브, 출발 웨이브, 캐릭터, 지팡이 단계, 웨이브별 점수 내역을 남긴다.
- 참고 크기(보너스 없이 처치·클리어·무피격만, 웨이브 10을 가마등으로 계산): 웨이브 9까지 약 9천(9,180), 14까지 약 2만 5천(25,234), 30까지 약 11만 5천(115,298), 60까지 약 50만(498,892) [M4.8, sim:mon_calc].
- PvP 점수와 합친 시즌 순위는 이 명세의 범위 밖(`online.md` 6.3절).

## 13. 드랍 [M6] [제안, 원칙은 아래]

원칙 [M6]:
1. 입문자도 재료를 얻는다. 첫 판에서 하급 강화석이 나오고, 엘리트를 못 만나는 깊이에서도 판마다 나온다.
2. 시간당 보상은 깊을수록 크다.
3. **직접 넘긴 웨이브만 센다.** 건너뛴 구간에서는 골드, 블록, 재료, 주화, 가방 칸이 하나도 나오지 않는다.
4. 보스의 졸개, 엘리트가 낳은 개체, 갈라진 슬라임은 아무것도 주지 않는다.

서버 프로필과 오프라인 프로필은 같은 표를 쓴다. 다른 점은 시즌 주화와 한정 드랍이 오프라인에서 나오지 않는다는 것뿐이다 [M6, M7]. 결제 여부를 보는 분기는 어디에도 없다 [M7, G12] [확정: D1.14].

### 13.0 언제부터 무엇이 나오는가 (요약) [M6.0]

| 물건 | 처음 나올 수 있는 곳 | 처음 확정으로 나오는 곳 | 나오는 길 | 뽑는 때 |
|---|---|---|---|---|
| 골드 | 웨이브 1 | 웨이브 1 | 처치, 웨이브 클리어, 보스 처치 | 그 자리 |
| 블록 카드: 일반·희귀 | 웨이브 1 | 웨이브 1 (희귀 확정 1장은 웨이브 10 보스) | 웨이브 클리어의 전리품 카드 | 판 씨앗 |
| 블록 카드: 영웅 | 웨이브 11 (카드 한 장에 2%) | 웨이브 30 보스 | 같음. 웨이브 6의 영웅 1장은 빌린 블록 | 판 씨앗 |
| 하급 강화석 | 웨이브 3 (프로필 첫 번째만, 3개) | 웨이브 5 | 다섯 번째 웨이브, 보스, 엘리트. **웨이브 21부터는 나오지 않는다** | 정산 |
| 중급 강화석 | 웨이브 10 보스 (50%) | 웨이브 15 | 다섯 번째 웨이브, 보스, 엘리트 | 정산 |
| 상급 강화석 | 웨이브 20 보스 (20%) | 웨이브 30 보스 | 다섯 번째 웨이브, 보스, 엘리트 | 정산 |
| 하락 방지 부적 | 웨이브 10 보스 (2%) | 없음 | 보스, 3일째 이후의 엘리트 | 정산 |
| 시즌 주화 | 웨이브 1 | 웨이브 1 | 넘긴 웨이브마다 | 그 자리 |
| 한정 드랍 | 웨이브 20 보스 (2%) | 없음 | 보스 | 정산 |
| 체력 조각 | 웨이브 1 | 없음 | 일반 적, 엘리트 | 판 씨앗 |
| 귀환 가방 칸 | 웨이브 3을 넘기면 1칸 | | 넘긴 웨이브 3개당 1칸, 최대 12칸 | 정산 |

- "웨이브 10 보스"는 가마등을 잡았을 때다. 프로필의 첫 웨이브 10은 8.3절 [M6.0].
- 복수 보상은 이 드랍 표와 별개로 프로필마다 한 번 [M6.0].

### 13.1 골드 [M6.1]

| 출처 | 금액 |
|---|---|
| 일반 적 처치 | 비용 × 2 (슬라임 2, 박쥐 2, 꽈리 벌레 4, 늑대 6, 족제비 6, 술사 8, 고슴도치 8, 도깨비불 8, 가시덩굴 8, 멧돼지 10, 북두꺼비 10, 선돌지기 12) |
| 엘리트 처치 | 바탕 종의 3배 (비용 × 2 × 3) |
| 웨이브 클리어 | 20. 보스 웨이브에도 붙는다 |
| 보스 처치 | `200 × S(w)` = 정수 `20 × (9 + w)` (웨이브 10: 380, 20: 580, 30: 780, 50: 1,180) |
| 남은 결정 환전 | 개당 5 (웨이브가 끝날 때) |
| 가져가지 못한 야생 블록 | 일반 5, 희귀 15, 영웅 50 (판이 끝날 때. 빌린 블록도 50) |
| 졸개, 갈라진 개체, 불러낸 개체 | 0 |

- 일반 웨이브 하나의 처치 + 클리어 수입 = `2 × B(w) + 20` (웨이브 12까지 `40 + 12w`, 웨이브 42부터 420 고정). 보스 웨이브 `200 × S(w) + 20`. 큰 무리·우두머리 행차는 적이 는 만큼 골드도 는다 [M6.1, O2.1].
- 원정 지갑: 판 중 골드는 지갑에 쌓이고, 야영의 회복·다시 뽑기에 쓴 만큼 줄어든 뒤 정산 때 프로필로 [M6.1, G12, O1.1].
- 코어 처리 [임시]: 처치 골드는 **처치 틱에 지갑에 넣는다**. 동전이 튀고 2칸 안이면 빨려 오고 웨이브 끝에 전부 회수되는 것은 표시 계층 연출이다(줍지 못해 잃는 골드는 없다) [M5.4].
- 보관함이 가득 차서 버린 블록은 그 자리에서 위 "가져가지 못한 야생 블록" 금액이 된다 [M6.2.1].

### 13.2 전리품 카드 [M6.2.1]

블록은 적이 직접 떨구지 않는다. 웨이브를 넘긴 뒤의 카드로만 나온다. 판 씨앗(`rng.loot`)으로 뽑는다 [M6.2].

| 때 | 보여 주는 카드 | 고르는 수 |
|---|---|---|
| 일반 웨이브를 넘겼을 때 | 4장 | 2장 |
| 엘리트를 한 마리라도 잡은 웨이브 | 5장 | 2장 |
| 보스 처치 | 5장. 그중 1장은 희귀 이상 확정. **웨이브 30부터의 보스는 그 1장이 영웅 확정** | 2장 |
| 허상과의 첫 만남 | 4장. 확정 등급 칸 없음 | 2장 |
| 웨이브 6 (1일째의 웨이브 6만) | 위에 더해 영웅 블록 1장을 그냥 받는다. **빌린 블록** | — |

```
struct LootOffer { int Wave; BlockId[] Cards; int GuaranteedSlot /* -1 없음 */; int RerollCount; }
LootOffer MakeOffer(int w, bool eliteKilled, bool bossKilled, bool phantomFirst, int rerollIndex) {
  var rng = Rng.Derive(seed, "loot", w, rerollIndex);          // 다시 뽑기마다 독립 분기 [임시]
  int n = (bossKilled || eliteKilled) && !phantomFirst ? 5 : 4;
  for i in 0..n-1: grade[i] = DrawGrade(Day(w), rng);
  if (bossKilled) grade[n-1] = w >= 30 ? Hero : DrawGradeNoCommon(Day(w), rng);    // 확정 칸은 마지막 [임시]
  card[i] = UniformInGrade(grade[i], rng);                     // 등급 안에서는 종류가 고르게
}
```

카드 한 장의 등급 확률(%) [M6.2.2]:

| 날 | 일반 | 희귀 | 영웅 | 정수 추첨 (0..99) |
|---|---|---|---|---|
| 1일째 (웨이브 1~10) | 78 | 22 | 0 | <78 일반, <100 희귀 |
| 2일째 (11~20) | 73 | 25 | 2 | <73, <98, <100 |
| 3일째 (21~30) | 70 | 26 | 4 | <70, <96, <100 |
| 4일째 이후 (31~) | 70 | 25 | 5 | <70, <95, <100 |

- "희귀 이상 확정" 칸은 일반을 뺀 나머지 비율로 뽑는다(1일째 희귀 100%, 2일째 희귀 25 : 영웅 2 → `NextInt(27) < 25`이면 희귀). 실제로 쓰이는 곳은 웨이브 10(희귀 100%)과 20(25:2)뿐이고 30부터는 영웅 확정 [M6.2.2].
- 등급 안 종류(16종, 기준 GDD 10.3절): 일반 6(마력탄, 2갈래 분열, 벽 튕김, 탄환 크기 2배, 관통 +2, 서리), 희귀 6(거대 화염구, 부메랑, 3갈래 분열, 적중 시 발동, 얼음 송곳, 그림자 구체), 영웅 4(연쇄 번개, 유도, 과열 3배, 잠식) [M6.2.2]. 균등 추첨(`NextInt(6)`, `NextInt(4)`), 순서는 0.3절 표 순서.
- 같은 제시 안의 중복 카드: 허용(독립 추첨) [임시].
- 다시 뽑기(30골드)는 같은 등급 확률로 카드를 전부 새로 뽑는다. 확정 등급 칸은 다시 뽑아도 확정 [M6.2.1]. 횟수 제한 없음, 값 고정 30 [임시].
- 고른 블록은 판 중 보관함(12칸)에 들어간다. 보관함이 가득 차면 버릴 블록을 고른다(버린 블록은 그 자리에서 13.1절 골드) [M6.2.1, U4.10].
- 확인 버튼은 고르는 수(2장)를 채워야 켜진다 [U4.10].

### 13.3 빌린 블록 [M6.2.3] [제안, GDD 확인 4번]

- 웨이브 6(1일째만)의 확정 영웅 블록. 종류는 영웅 4종 중 균등(`rng.loot`, w=6, 별도 태그 "borrowed") [임시].
- 그 판에서만 쓴다. 프로필로 가져갈 수 없고 판이 끝나면 50골드. 카드에 "빌림" 꼬리표와 점선 테두리.
- 다른 문서의 "야생 전용 블록"이 이것이다.
- 보관함에서 버리면 50골드 [임시: 판 끝 값과 같게].

```
struct WildBlock { BlockId Id; Grade Grade; bool Borrowed; int AcquiredWave; int Uid; }  // Uid는 판 안 순번
```

### 13.4 귀환 가방 [M6.2.4] [제안, GDD 확인 41번 (가)안]

| 항목 | 규칙 |
|---|---|
| 칸수 | `min(12, cleared ÷ 3)` (몫). 기본 칸 없음. 최대 12칸(36웨이브에서 도달, 보관함 크기와 같다) |
| 영웅 한도 | 가방에 담는 것 중 영웅은 `cleared ÷ 10` (몫)개까지. 따로 둔 상한은 없다(칸수 안에서) |
| 담을 수 있는 것 | 판이 끝날 때 들고 있는 야생 블록(보관함 + 지팡이에 끼워 둔 야생 블록). 빌린 블록은 불가 |
| 고르는 사람 | 정산 화면에서 플레이어. 고르지 못하고 끝난 판(접속 끊김 등)은 등급 높은 것부터 자동 |
| 세는 웨이브 `cleared` | 이번 판에서 직접 넘긴 웨이브만. 건너뛴 웨이브는 세지 않는다. 비정상 종료는 마지막 중간 지점까지 넘긴 수 |
| 남은 것 | 골드(13.1절) |
| 가방 칸을 쓰지 않는 것 | 강화석, 부적, 시즌 주화, 한정 드랍, 골드 |

```
int BagSlots(int cleared) => Math.Min(12, cleared / 3);
int BagHeroLimit(int cleared) => cleared / 10;
List<WildBlock> AutoPick(List<WildBlock> held, int cleared) {
  // 빌린 블록 제외 → 정렬: 등급(영웅>희귀>일반) 내림, 같은 등급은 BlockId 표 순서, 그다음 Uid 오름 [임시]
  // 앞에서부터 담되 영웅은 한도까지만, 칸이 차면 멈춤
}
```
- 죽어서 끝난 판, 판 포기, 끝까지 간 판 모두 같은 식 [M6.2.4].
- **유일한 예외**: 주간 도전 판은 그 주의 넷째 판부터 야생 블록을 가방에 담지 못하고 전부 골드 [M6.2.4, M7, O2.2, GDD 확인 60].
- 출발 조립에 쓴 프로필의 블록(서고 블록)은 야생 블록이 아니다. 가방과 상관없이 죽어도 잃지 않는다 [M6.2.4, O1.2].
- 서고 한도(블록 개수 100에서 시작, 50개당 2,000골드 확장)가 차면 가방에 담지 못한 것으로 보고 13.1절 골드로 바뀐다 [O2.4, GDD 확인 61].
- 서버는 `monsters.md` 규칙으로 칸수와 한도를 다시 계산해 확인한 뒤 서고에 넣는다 [O1.2].
- 버린 식(쓰지 않음): "판마다 기본 2칸 + 10웨이브당 1칸, 최대 6칸"((나)안). 한 웨이브만 넘기고 끝내는 판이 웨이브당 가장 많이 가져가기 때문 [M6.2.4].

### 13.5 강화 재료와 부적 [M6.3] [제안]

강화석 하급·중급·상급, 부적은 하락 방지 부적 하나. 전부 거래 가능 [확정: D1.10]. 어느 강화석이 어느 단계에 쓰이는지와 강화 비용은 `online.md` 1.3절.

- 재료는 세 군데에서만 나온다: **하루의 다섯 번째 웨이브를 넘겼을 때, 보스를 잡았을 때, 엘리트를 잡았을 때**(엘리트는 웨이브 12부터). 여기에 프로필마다 한 번뿐인 까마귀 보따리. 일반 적과 그 밖의 웨이브에서는 나오지 않는다.
- "확정"은 추첨 없이 그 수량을 받는다. "N%"는 그 줄마다 따로 한 번 뽑아 맞으면 **1개**. 한 기회에서 여러 줄이 함께 맞을 수 있다.
- 엘리트 줄은 엘리트 **한 마리마다** 한 번씩(우두머리 행차로 늘어난 엘리트도 포함).

**표 6.3-A 까마귀 보따리** (프로필마다 한 번): 그 프로필에서 처음으로 웨이브 3을 넘겼을 때 하급 3 확정 (느루가 까마귀 편에 던져 준다).

**표 6.3-B 하루의 다섯 번째 웨이브를 넘겼을 때** (웨이브 5, 15, 25 …)

| 날 d | 웨이브 | 하급 | 중급 | 상급 |
|---|---|---|---|---|
| 1 | 5 | 확정 1 | | |
| 2 | 15 | 확정 1 | 확정 1 | |
| 3 | 25 | | 확정 1 | 5% (500bp) |
| 4 | 35 | | 확정 1 | 10% |
| 5 | 45 | | 확정 1 | 15% |
| 6 | 55 | | 확정 1 | 20% |
| 7 이후 | 65 … | | 확정 1 | 25% |

식: d ≥ 3 상급 `5% × (d − 2)`, 최대 25% → `bp = min(2500, 500 × (d − 2))`. 부적 없음.

**표 6.3-C 보스를 잡았을 때** (웨이브 10, 20, 30 …)

| 날 d | 웨이브 | 하급 | 중급 | 상급 | 부적 |
|---|---|---|---|---|---|
| 1 | 10 | 확정 1 | 50% | | 2% |
| 2 | 20 | | 확정 1 | 20% | 4% |
| 3 | 30 | | 확정 1 | 확정 1 | 6% |
| 4 | 40 | | 확정 1 | 확정 1 + 10%로 1개 더 | 8% |
| 5 | 50 | | 확정 1 | 확정 1 + 20%로 1개 더 | 10% |
| 6 | 60 | | 확정 1 | 확정 1 + 30%로 1개 더 | 10% |
| 7 | 70 | | 확정 1 | 확정 1 + 40%로 1개 더 | 10% |
| 8 이후 | 80 … | | 확정 1 | 확정 1 + 50%로 1개 더 | 10% |

식: 부적 `2% × d`, 최대 10% → `bp = min(1000, 200 × d)`. d ≥ 3 상급 추가 1개 `10% × (d − 3)`, 최대 50% → `bp = min(5000, 1000 × (d − 3))` (d = 3이면 0 → 추첨 생략).
첫 만남(프로필 첫 웨이브 10)은 1일째 줄의 확정분(하급 1)만, 추첨 없음 [M6.3-C, M3.9.3].

**표 6.3-D 엘리트 한 마리를 잡았을 때** (웨이브 12부터)

| 날 d | 웨이브 | 하급 | 중급 | 상급 | 부적 |
|---|---|---|---|---|---|
| 1 | 1~10 | 엘리트 없음 | | | |
| 2 | 12~19 | 10% | 8% | | |
| 3 | 21~29 | | 5% | 2% | 0.5% |
| 4 | 31~39 | | 5% | 2.5% | 0.5% |
| 5 | 41~49 | | 5% | 3% | 0.5% |
| 6 | 51~59 | | 5% | 3.5% | 0.5% |
| 7 | 61~69 | | 5% | 4% | 0.5% |
| 8 | 71~79 | | 5% | 4.5% | 0.5% |
| 9 이후 | 81 … | | 5% | 5% | 0.5% |

식: d ≥ 3 상급 `2% + 0.5% × (d − 3)`, 최대 5% → `bp = min(500, 200 + 50 × (d − 3))`. 부적 50bp.

**뽑는 때와 화면** [M6.3]:
- 추첨은 **정산 때** 한다. 전투 중에는 기회 목록(넘긴 웨이브 번호, 잡은 엘리트 수, 잡은 보스)만 기록하고, 정산 때 서버가 자기 난수로 한 번 뽑는다. 오프라인 프로필은 기기가 뽑는다. 판 씨앗으로는 뽑지 않는다(좋은 재료가 나오는 씨앗을 골라 되풀이할 수 없게) [M6.3, M7, O2.2, G12].
- 중간 지점(5웨이브마다)은 기록일 뿐이고 그때 뽑지도 지급하지도 않는다. `run_id`당 한 번, 종료 요약이 1차 검사를 통과한 때(또는 원정 정리 때) 뽑는다 [O3.2].
- 확정 수량도 같은 때에 프로필로 들어간다. 다만 수량이 정해져 있으므로 야영 화면에 바로 보여 준다.
- 화면: 기회가 생기면 재료 꾸러미가 떨어진다. 추첨분은 정산 화면에서 꾸러미를 여는 연출로 보여 준다.
- 판 포기·사망(정상 종료)도 그때까지의 확정 보상과 추첨 기회가 남는다. 비정상 종료는 마지막 중간 지점까지의 기회만 정산한다. "원정 정리"는 종료 요약을 내지 못한 판의 잠금을 푸는 절차이고 마지막 중간 지점까지를 정산한다(중간 지점이 없을 때만 보상 없음). 보상 없이 잠금만 푸는 "원정 포기"는 따로 없다 [M6.3, O3.2].
- 건너뛴 웨이브는 기회 목록에 넣지 않는다 [O2.2].
- 서버 지급은 1차 검사 뒤 "검증 대기"로, 재실행 검증 뒤 확정 [O2.2, O3.2].

### 13.6 시즌 주화, 한정 드랍, 체력 조각 [M6.4]

| 물건 | 규칙 |
|---|---|
| 시즌 주화 | 직접 넘긴 일반 웨이브마다 `min(d, 5)`개. 보스 웨이브는 그 5배(1일째 5개, 5일째 이후 25개). 확정 수량, 추첨 없음. 서버가 시즌을 켜 두었을 때만. 오프라인 프로필 없음. 첫 만남 웨이브는 일반 몫(1개) |
| 한정 드랍(시즌 꾸미기 조각) | 웨이브 20부터의 보스 처치에서 2%(200bp). 드랍 표의 `시즌 태그` 줄. 서버가 태그를 켰을 때만 정산 때 서버가 뽑는다. 오프라인 없음 |
| 체력 조각 | 엘리트 처치 시 10%(1000bp), 일반 적 처치 시 `0.3% × 비용`(30bp × cost). 체력이 가득이면 나오지 않는다. 주우면 체력 1칸 회복. 웨이브당 1개까지. 판 씨앗으로 뽑는다. 프로필에 남지 않는다 |

체력 조각 코어 [임시 세부]:
```
OnEnemyKilled(e):
  if (e.IsMinionOrSpawned) return;                  // 졸개·갈라진 것·불러낸 것은 없음
  if (wave.HpShardDropped || player.Hp == player.MaxHp) return;   // 추첨 자체를 하지 않는다(난수 소비 없음)
  int bp = e.Elite ? 1000 : 30 * e.Species.cost;
  if (rng.hp_shard.NextInt(10000) < bp) { spawn shard at e.pos; wave.HpShardDropped = true; }
// 줍기: 플레이어 원과 겹치면 체력 +1(최대치까지). 웨이브 클리어 때 바닥에 남아 있으면 자동 회수(체력 +1) [임시]
```

### 13.7 대상별 구분 [M6.5]

| 대상 | 골드 | 블록 | 재료 | 주화 | 그 밖 |
|---|---|---|---|---|---|
| 일반 적 | 비용 × 2 | 없음(카드로만) | 없음 | 없음 | 체력 조각 `0.3% × 비용` |
| 엘리트 | 바탕 종의 3배 | 그 웨이브의 카드가 5장 | 표 6.3-D를 한 마리마다 | 없음 | 체력 조각 10% |
| 보스 | `200 × S(w)` | 카드 5장, 등급 확정 1장 | 표 6.3-C | 일반 웨이브의 5배 | 한정 드랍 2%(웨이브 20부터), 새벽 야영 체력 1칸 |
| 웨이브를 넘김 | 20 | 카드 4장(또는 5장) 중 2장 | 다섯 번째 웨이브면 표 6.3-B | `min(d, 5)` | 가방 칸 |
| 졸개, 갈라진 개체, 불러낸 개체 | 0 | 0 | 0 | 0 | 점수도 0 |

### 13.8 기회 목록과 정산 자료구조

```
enum ChanceSource : byte { CrowBundle, FifthWave, BossKill, EliteKill, PhantomFirst, BossKillLimited }
struct DropChance { ChanceSource Source; int Wave; int Count /* EliteKill: 마리 수, 그 밖 1 */; }
// 서버: run.drop_chances(json) [O7.9]

SettlementInput {
  RunId; ProfileKind(Server|Offline); RunKind(Normal|Weekly); int WeeklyRunIndexThisWeek;
  EndKind(Death|Abandon|Cleanup|Stale14d); int ClearedDirect; int ClearedAtLastCheckpoint;
  long WalletGold; List<WildBlock> HeldWild; List<int> BagChoiceUids /* 자동이면 null */;
  List<DropChance> Chances; bool SeasonOn; bool SeasonLimitedTagOn;
}
SettlementResult {
  long GoldToProfile;               // 지갑 + 가방에 못 담은 블록 골드
  List<WildBlock> ToLibrary;        // 가방
  Dictionary<MatId,int> Materials;  // 확정 + 추첨
  int SeasonCoins;                  // 판 중 누적(서버+시즌)
  int LimitedDrops;
  bool PhantomMetSet; bool RevengeGranted;
  Status = Pending(서버) | Final(오프라인)
}
```

정산 절차:
```
Settle(input):
  cleared = input.EndKind in {Cleanup, Stale14d} ? input.ClearedAtLastCheckpoint : input.ClearedDirect;
  chances = input.EndKind in {Cleanup, Stale14d} ? 마지막 중간 지점 이하 웨이브의 기회만 : 전부;
  // 1) 가방
  slots = BagSlots(cleared); heroCap = BagHeroLimit(cleared);
  if (input.RunKind == Weekly && input.WeeklyRunIndexThisWeek >= 4) slots = 0;
  bag = input.BagChoiceUids != null ? Validate(choice, slots, heroCap, no borrowed) : AutoPick(...);
  bag = ApplyLibraryCapacity(bag);                 // 넘치면 골드로
  gold = input.WalletGold + Σ GoldOf(held \ bag)   // 일반 5 / 희귀 15 / 영웅 50 / 빌림 50
  // 2) 재료: 확정분 합산 + 줄마다 독립 추첨(서버 난수 또는 기기 난수). 줄 순서 고정: 하급, 중급, 상급, 상급 추가, 부적, 한정
  // 3) 첫 만남 표시 끄기(cleared ≥ 10 이고 run.PhantomFirst), 복수 보상(웨이브 20 허상 처치 기록 && !RevengeDone)
```
- 서버 정산 규칙: `run_id`당 한 번(멱등 키). 같은 제출이 다시 오면 처음 결과를 돌려준다 [O3.2].
- 대기 중 골드·물건은 강화와 조립에 쓸 수 있지만 거래·장터·선물에는 못 쓴다 [O3.2].
- 재실행 검증 워커는 씨앗과 입력 기록으로 판을 다시 돌려 점수, 골드, 드랍 기회, 가방 내용이 요약과 같은지 본다 [O3.2].

## 14. 씨앗, 난수 분기, 결정론, 서버 검증 [M7, O3.1~3.3]

### 14.1 씨앗의 출처

| 판의 종류 | 씨앗 | 순위 반영 |
|---|---|---|
| 일반 판(서버 프로필) | 판마다 서버가 준다(`run_id`와 함께). 클라이언트는 고를 수 없다 | 시즌 순위표, 후계 점수 |
| 주간 도전(서버) | 그 주의 공용 씨앗, 웨이브 1 출발 고정 | 주간 도전 순위표만. 그 주가 끝날 때까지 다시 보기 비공개 |
| 오프라인 프로필의 판 | 판을 시작할 때 기기가 만든다 | 기기 안의 개인 기록 |
| 주간 도전(오프라인) | 게임에 든 씨앗 목록에서 주마다 하나(기기 시계 기준) | 기기 기록. 주간 보상 없음 |

- 순위에 들어가는 판은 판마다 다른 서버 씨앗만 쓴다(공용 씨앗 + 공개 다시 보기면 입력 복제 가능) [M7, O3.3] [제안, GDD 확인 2번].
- 주간 도전 보상(서버, [제안]): 상위 10% 시즌 주화 60 + 그 주의 칭호, 상위 50% 30, 참가(1판 이상) 10. 판 자체의 골드·블록·재료는 일반 판과 같은 표, 넷째 판부터 가방 0 [O2.2].
- 판 밖 수입(참고, online 기준): 자동 매치 승리 80골드 + 주화 6, 패배 30골드 + 주화 3, 하루 첫 10판까지. 시즌 끝 남은 주화 개당 10골드 [O2.2].

### 14.2 난수 분기 [확정: 판 씨앗에서 갈라 낸 PCG 계열만 / 임시: 태그와 파생법]

```
// 같은 (seed, tag, wave, sub)는 언제나 같은 수열. 웨이브마다 독립이므로 앞 웨이브의 소비량이 뒤에 번지지 않는다.
Rng Derive(ulong seed, StreamTag tag, int wave, int sub = 0) => Pcg32(SplitMix64(seed ^ ((ulong)tag << 48) ^ ((ulong)wave << 16) ^ (ulong)sub), stream: (ulong)tag);
enum StreamTag : ushort {
  WaveComp = 1,   // 틀, 종, 엘리트 종, 개수(2~3, 6~8, 1~2), 묶음 나누기
  WaveSpawn = 2,  // 스폰 위치
  Modifier = 3,   // 변덕 선택 (서버가 상한 계산 때 이 분기만 돌린다)
  Loot = 4,       // 카드, 다시 뽑기(sub = reroll 횟수), 빌린 블록(sub = 0xFFFF)
  HpShard = 5,    // 체력 조각
  Event = 6,      // 별똥 결정 등 돌발 사건
  Ai = 7          // 적·보스 AI (적 명세 몫)
}
```
- 재료·부적·한정 드랍은 판 씨앗을 쓰지 않는다: 서버는 서버 자체 난수(CSPRNG), 오프라인은 기기 난수 [M6.3, M7].
- 틀의 "직전과 다름" 규칙 때문에 틀은 웨이브 13부터 순서대로 계산해야 한다(이전 결과에 의존). 변덕은 의존이 없다.

### 14.3 결정론 요구 [M7, O3.1] [확정]

- 고정 60틱, Q32.32, 자체 PCG, 반복 순서가 정해진 자료구조만(배열, 정렬된 목록). 유니티 물리 미사용.
- 스폰, 적 AI, R5, 점수는 같은 씨앗과 같은 입력이면 같은 결과.
- 히트스톱과 느린 연출(보스 사망 1.0초 등)은 그림만 멈추고 게임 시간은 멈추지 않는다.
- 수치는 데이터 파일(종별 ID, 수치, 시간대 가중치, 틀, 드랍 표)로 읽는다.
- 서버가 없을 때 빈 화면이나 오류가 나오는 곳이 없어야 한다. 데이터 내려받기 실패 시 기본 데이터.
- 코어 버전 해시가 다르면 순위 제출을 막는다 [O3.1].

### 14.4 서버 프로필에서 이 영역의 항목 [M7]

| 항목 | 서버 프로필 | 오프라인 프로필 |
|---|---|---|
| 판 씨앗 | 판마다 서버가 준다 | 기기가 만든다 |
| 웨이브 구성, 블록 카드, 체력 조각 | 판 씨앗 분기 | 같음 |
| 재료·부적·한정 드랍 추첨 | 정산 때 서버 난수. 전투는 기회 목록만 올린다 | 정산 때 기기 |
| 점수 | 클라이언트 계산 + 입력 기록 → 서버가 같은 코어로 다시 돌려 확인. 다르면 기록과 보상 삭제 | 기기 저장 |
| 시작 웨이브 | 서버의 "이번 시즌 그 캐릭터 최고 웨이브"로 한도 확인 | 기기 기록 |
| 첫 만남 | 서버가 판 정보에 넣는다. 웨이브 10 점수·골드 고정값 확인(3,648점, 20골드) | 저장 파일 |
| 복수 보상·추적기 | 서버 정산, 검증 대기 → 통과 뒤 확정 | 기기 |
| 적·보스·변덕 정의 | 게임 데이터 + 서버가 내려 주면 덮어쓰기. 판마다 데이터 판 번호 기록 | 게임 데이터 |
| 시즌 주화, 한정 드랍 | 시즌 태그가 켜졌을 때만 | 없음 |
| 결제 | 어디에도 분기 없음 | 같음 |

서버 1차 검사(즉시) [O3.2]: 토큰 유효·1회 사용, 코어 버전, 경과 실제 시간 ≥ 틱 수에 해당하는 시간(짧으면 가속), 골드와 점수 ≤ 웨이브별 이론 상한(12.3절)의 합.
접속이 끊긴 채 끝난 판은 다시 접속하면 제출. 순위에는 종료 후 10분 안에 제출된 판만 [O3.2]. 순위 대상 판의 일시정지 누적은 10분까지 인정 [O3.4].

## 15. 주간 도전 (이 영역 관련만) [M7, O3.3, O2.2]

- 첫 만남을 치른 프로필에만 열린다. 그 전에는 메뉴에 "첫 밤을 넘기면 열린다".

- 후계자 점수에 들어가지 않는다. 그 주가 끝날 때까지 다른 사람의 다시 보기 비공개.
- 그 주의 넷째 판부터 귀환 가방 0칸(전부 골드). "넷째 판"의 셈: 그 주(월요일 시작 [O3.5])에 **시작한** 주간 도전 판 순번(비정상 종료 판 포함) [임시].
- 오프라인: 게임에 든 씨앗 목록에서 주마다 하나, 혼자 기록.
