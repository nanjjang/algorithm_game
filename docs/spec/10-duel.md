# 10. 결투(PvP) 구현 명세서

게임: 엄청엄청 위대한 마법사 키우기. 대상: Unity 2D URP 클라이언트(C#), 결정론 코어 `Wizard.Sim`(C#), 서버 `wizard-api`·`wizard-duel`(C# ASP.NET Core + PostgreSQL, 맥미니 한 대).

이 문서 하나만 보고 결투를 구현할 수 있게 원본의 규칙과 수치를 옮기고, 데이터 구조·상태 기계·의사코드·경계 조건·테스트 벡터를 붙였다. 원본을 고치지 않는다. 원본과 이 문서가 다르면 원본이 맞고, 원본끼리 다르면 `DECISIONS.md`가 맞다(21절 "충돌").

### 0.3 단위와 환산 규칙 (이 문서 전체)

- 거리: 칸. 1칸 = 64px (D 2.1). 게임 수치는 칸 그대로다.
- 시간: 1초 = 60틱 (G 0; O 3.1). 1틱 = 16.667ms.
- 틱 안 시각: 1틱 = 256 단위(1/256틱). 1초 = 15,360 단위 (G 8 판정기; O 3.1). 이 단위를 **서브틱(subtick)** 이라 부른다.
- 고정소수점: Q32.32(64비트 정수, 하위 32비트가 소수) (O 3.1). 표의 "Q32.32 원시값"은 `round(값 × 2^32)`이다.
- 각도: [임시] 코어에서는 한 바퀴 = 2^32인 부호 없는 32비트 정수(BAM32)로 둔다. 1도 = 11,930,464.7. 표의 각도 원시값은 `round(도 ÷ 360 × 2^32)`.
- 좌표: 돌마당 안쪽 왼쪽 위가 (0,0), 오른쪽 아래가 (24,14)의 실수 좌표. y는 아래로 는다 (W 2.6). 각도 0은 +x(오른쪽), 양의 각은 화면에서 시계 방향(y 아래 기준)이다 [임시].
- 초 → 틱 환산은 정확히 나누어떨어지면 그 값, 아니면 서브틱으로 적는다(반올림. G 8의 값과 같다. 예: 0.07초 = 4.2틱 = 1,075 서브틱(1,075.2), 0.18초 = 2,765(2,764.8)).
- 퍼센트·배율은 정수 비율로 계산한다 [임시]: 예 `1 + 0.03 × 단계` = `(100 + 3 × 단계) / 100`.

### 0.4 이 문서가 다루지 않는 것

- 그림, 이펙트, 소리, UI 배치의 구현. 이벤트 이름만 23절에 둔다.
- 무한 웨이브의 규칙 자체(G·M·W의 몫). 결투가 바꾸는 부분만 적는다.
- 광장, 거래, 시즌 정산의 구현(다른 명세서의 몫). 결투와 맞닿는 규칙만 적는다.
- 일정, 범위 삭감 (D 1.16). 19절은 의존 순서만 적는다.

### 3.2 형식과 라운드 (O 4.1)

- 인원 1 대 1, 3판 2선승 [제안]. 방은 1/3/5판(선승 1/2/3) [제안].
- 라운드 시간 90초(방 60/90/120초) [제안].
- 라운드 시작: 3초 카운트다운, 열 0, 결정 1개, 체력 가득 [제안].
- 카운트다운 동안 키 상태는 추적하지만 이동·발사·비기는 막는다. 커맨드 커서는 카운트다운이 끝나는 틱에 비운다 [임시].
- 라운드가 바뀔 때 초기화하는 것 [임시: 원문이 "체력 가득, 열 0, 결정 1"만 적었으므로 나머지 판 안 상태도 같이 비운다]: 체력, 열, 잠금, 콤보와 콤보 타이머, 결정(1로), 성에의 금(0, W 5.4-4 [제안]), 상태 효과(감속·잠식·기절·경직·유리 지팡이 꺼짐), 지대·벽·사본·탄, 스침 인정 타이머, 벌칙 창, 순간 피해 기록, 비기 대기, 커맨드 커서, 피뢰침 벼락 대기.
- 라운드가 바뀌어도 남는 것: 그믐의 빚 결정(최대 2) [제안] (O 4.1; W 4.5-1, 5.4). 라운드 시작 결정 1개는 빚부터 갚는다 [제안] (W 5.4 외상-1).
- 지팡이와 조립: 그 캐릭터의 "든 지팡이"(O 1.6)와 그 지팡이의 출발 조립. 입장할 때 고정, 라운드 사이에 못 바꾼다 [제안] (O 4.1). 코어가 빈 지팡이로는 결투를 시작할 수 없다 [제안] (O 1.1 끝).
- 비기: 공용 10 + 그 캐릭터 고유 1. 해금과 무관하게 전부 [제안] (O 4.1; G 8 해금).

### 3.3 승패 판정 (O 4.1)

라운드 승자:

1. 상대 체력 0 → 이긴다 [제안].
2. 시간 종료 → (1) 남은 체력 비율이 높은 쪽 (2) 같으면 그 라운드에 준 피해 합이 큰 쪽 [제안].
3. 둘 다 같으면 30초 연장. 연장 중 받는 피해 2배 [제안].
4. 연장이 끝나도 같으면 무승부 [제안].

```
// 정수로만 비교한다(나눗셈 없음)
CompareTimeout(a, b):
    lhs = a.hp * b.maxHp ; rhs = b.hp * a.maxHp       // 체력 비율 비교
    if lhs != rhs: return lhs > rhs ? A : B
    if a.damageDealtThisRound != b.damageDealtThisRound:
        return a.damageDealtThisRound > b.damageDealtThisRound ? A : B
    return Tie
```

- "준 피해 합"은 상한(3.6, 8.3절)을 거친 뒤 실제로 깎인 체력의 합이다 [임시]. 상대에게 준 것만 센다(슬라임 피해, 가시밭 피해는 넣지 않는다) [임시].
- 연장 끝의 판정은 2번의 (1)(2)를 그 시점에 다시 한다. 피해 합은 본 라운드와 연장을 더한다 [임시].
- 같은 틱에 둘 다 체력 0: 그 라운드에 준 피해 합이 큰 쪽이 이긴다. 같으면 무승부 라운드 [임시].
- 무승부 라운드: 누구의 승수도 오르지 않고 라운드를 하나 더 한다. 라운드 수 상한은 `2 × 선승 수 + 1`(3판 2선승이면 5라운드)이고 상한에 닿아도 승수가 같으면 경기 무승부 [임시]. 경기 무승부는 Glicko-2에서 0.5다 [임시].

### 3.4 가시밭 (O 4.1)

- 60초부터 가장자리에서 가시밭이 5초에 1칸씩 안으로 들어온다. 가시밭 위에서는 0.5초마다 최대 체력의 4% 피해. 목적: 축을 피해 도망만 다니는 교착을 끊는다 [제안].
- 방 옵션 "가시밭 끄기"로 끈다 [제안] (O 4.6).

구현 정의 [임시: 원문은 "가장자리에서 1칸씩"만 적었다]:

```
ring(t_round):        // t_round = 라운드 경과 틱(카운트다운 제외), 연장 포함 누적
    if !thornEnabled or t_round < thornStart: return 0
    return min(1 + (t_round - thornStart) / 300, THORN_RING_MAX)

THORN_RING_MAX = 6                         // [임시] 안쪽 12×2칸(x 6~18, y 6~8)이 남는다
thornStart     = roundLength - 1800       // [임시] 90초 → 3,600틱(원문 값), 60초 → 1,800, 120초 → 5,400

InThorn(pos, k):      // pos = 피격 원 중심, k = ring
    cx = floor(pos.x) ; cy = floor(pos.y)
    return k > 0 and min(cx, 23 - cx, cy, 13 - cy) < k

매 틱: if t_round >= thornStart and (t_round - thornStart) % 30 == 0:
          for p in players: if InThorn(p.hitCenter, ring(t_round)):
              ApplyDamage(p, ceil(p.maxHp * 4 / 100), source = Thorn)
```

- 첫 피해 틱은 가시밭이 처음 생기는 틱(3,600)이다 [임시].
- 가시밭 피해는 순간 피해 상한과 연장 2배를 받는다 [임시]. 피격 벌칙(콤보 0, 결정 파괴)은 일으키지 않는다(상대의 공격이 아니므로) [임시]. "준 피해 합"에 넣지 않는다 [임시].
- 고리는 연장에서도 계속 들어오되 6에서 멈춘다 [임시].
- 4% 값: 달구 800 → 32, 성에 700 → 28, 갈피 600 → 24, 그믐 500 → 20, 초롱 400 → 16 (체력 배율 옵션이 있으면 그 최대 체력 기준).

### 3.5 야생 난입 (방 옵션) (O 4.1)

- 20초마다 중립 슬라임 4마리가 나온다. 슬라임을 맞혀도 콤보가 오른다. 접촉 피해는 100. 사용자 방에서만 켤 수 있다 [제안].
- 슬라임 기본값은 이끼 슬라임(`slime_moss`): 체력 20, 속도 3.0, 접촉 공격, 예고 없음 (M 2.1) [제안].
- [임시] 나오는 자리: (1.5, 1.5), (22.5, 1.5), (1.5, 12.5), (22.5, 12.5). 첫 출현은 라운드 경과 1,200틱. 가장 가까운 플레이어 쪽으로 걷는다(같으면 왼쪽 시작 플레이어). 접촉 피해는 슬라임 한 마리가 같은 플레이어에게 60틱에 1번. 슬라임 접촉은 "피격"으로 보아 벌칙 규칙(5절)을 탄다. 결투 규칙대로 속성 배율은 적용하지 않는다. 라운드가 끝나면 사라진다. 슬라임이 탄 상한에 영향을 주지 않는다.

### 3.6 순간 피해 상한 (O 4.2)

- 0.5초 동안 받는 피해는 최대 체력의 30%까지 [제안].
- 패시브와 고유 비기의 피해도 상한 안에 든다 [제안] (O 4.5).
- 결과: 어떤 캐릭터도 1.7초 안에는 죽지 않는다 (O 4.5 끝) [제안. 21절 충돌 C2: 이 상한의 정확한 최소 사망 시간은 90틱 = 1.5초다].

구현 [임시: "0.5초 동안"을 미끄러지는 30틱 창으로 읽는다]:

```
// 사람마다 최근 30틱의 '실제로 깎인 피해' 원형 버퍼
AllowedDamage(p, t):
    cap  = p.maxHp * 30 / 100                  // Q32.32
    used = sum(p.taken[t-29 .. t])             // 이번 틱에 이미 깎인 것 포함
    return max(0, cap - used)

ApplyDamage(p, raw, source):
    if p.invulnerable: return 0
    dmg = raw
    if round.inOvertime: dmg = dmg * 2         // 연장 2배는 상한 전에 [임시]
    dmg = min(dmg, AllowedDamage(p, now))
    p.taken[now] += dmg ; p.hp -= dmg
    return dmg
```

- 같은 틱 안의 피해 처리 순서: 탄·비기 적중을 (탄 생성 순번) 오름차순으로 처리하고, 가시밭과 슬라임은 그 뒤에 처리한다 [임시]. 상한에 닿은 뒤의 피해는 0이 되지만 **피격 판정(벌칙)은 피해 0이어도 일어난다** [임시].

### 3.7 이탈·끊김·무효 (O 4.10, 7.7)

- 중도 이탈은 패배다. 접속이 끊기면 20초 기다리고 돌아오지 않으면 패배 처리 [제안].
- 하루 3회 넘게 이탈하면 30분 대기열 금지 [제안].
- 서버(맥미니)가 내려가거나 서버 회선이 끊겨 양쪽이 다 끊기면 그 경기는 무효, 점수가 변하지 않는다 [제안].
- 일시정지 메뉴는 "계속", "설정", "기권"뿐이고 경기는 멈추지 않는다 (U 4.16) [제안]. 기권은 경기 패배 [임시].
- 계획 점검 때는 새 접속을 막고 진행 중인 결투가 끝나기를 5분 기다린 뒤 내린다 (O 7.7) [제안].

끊김 중 처리 [임시]: 경기는 멈추지 않는다. 끊긴 사람의 틱은 4.11-4의 규칙대로 "변화 없음"으로 봉인된다(키 상태 유지 아님: 끊긴 순간 모든 키를 뗀 것으로 본다 [임시]). 20초 안에 돌아오면 서버가 상태 전체를 보내 이어서 한다. 20초가 지나면 그 틱에 경기 패배로 끝낸다. "이탈 횟수"에는 20초를 넘겨 패배한 경우와 기권만 센다 [임시].

## 4. 결투에서 바뀌는 수치의 적용 규칙 (O 4.2)

2.2절 상수표가 값이다. 이 절은 적용 방법만 적는다.

### 4.1 강화 배율

```
EnhanceMultDuel(appliedStage) = (100 + 3 * appliedStage) / 100      // Q32.32
```
- `appliedStage`는 리그 제한·방 강화 상한·장비 평준화를 거친 값이다(11.4절) [제안].
- +0 1.00, +4 1.12, +9 1.27, +11 1.33, +13 1.39 (O 4.2) [제안].

### 4.2 피해 공식 (G 4에서 결투가 바꾸는 것만)

```
피해 = 기본 × EnhanceMultDuel × (1 + 변형 보너스 합) × 변이 배율 × 임계 배율 × 비기 배율
       × 감쇠^깊이 × 1(속성 배율 없음) × 대상 상태 배율 × 캐릭터 배율
```
- 속성 배율 = 1. 플레이어에게는 약점이 없다 [제안] (O 4.2). 패시브와 고유 비기의 피해도 속성 배율을 받지 않는다 [제안] (O 4.5).
- 대상 상태 배율 = 잠식에 걸린 상대 1.08, 아니면 1 [제안] (O 4.2). 잠식을 건 그 탄의 피해에는 적용하지 않고 다음 피해부터, 겹치지 않고 시간만 갱신 (G 10.3) [제안].
- 임계 배율 = (과열 3배 블록 있으면 3, 없으면 2) + (유리 지팡이 변이가 있고 꺼짐 상태가 아니면 1). 임계 아니면 1 (G 4; O 4.2) [제안].
- 비기 배율과 임계 배율은 같이 적용하지 않는다 (G 4) [제안].
- 캐릭터 배율 = 그믐의 그림자 계약: 가진 결정 1개당 +3%(7개에서 +21%), 빚은 0개로 셈, 비기는 비용을 쓴 뒤 남은 개수로 (W 4.5, 5.4 "그대로") [제안].
- 그 뒤 순간 피해 상한(3.6절)과 연장 2배.

### 4.3 상태를 바꾸는 효과의 지연 적용

- 기절, 넉백, 감속, 결정 파괴는 적중 3틱 뒤에 적용한다 [제안] (O 4.2, 4.11). 캐릭터 능력의 넉백, 당김, 경직, 감속도 같다 [제안] (O 4.5).
- 피해는 적중 틱에 즉시 들어간다 [제안] (O 4.3 "피격 피해: 맞을 때마다 들어간다").
- [임시] 피격 벌칙 전체(콤보 0, 결정 파괴, 성에의 금 변화, 그믐의 빚 증가)를 적중 3틱 뒤에 한 번에 적용한다. 벌칙 창은 적중 틱에 연다. 그믐의 "+100 추가 피해"는 피해이므로 적중 틱에 들어간다(빚이 있는지는 적중 틱의 상태로 본다).
- [임시] 3틱 안에 같은 대상에게 같은 종류가 또 오면 각자 자기 적용 틱에 적용한다(감속은 가장 큰 값, 시간은 각자 갱신).

```
OnHit(target, effect, tHit):  pendingEffects.Add(target, effect, applyAt = tHit + 3)
매 틱 시작: 적용 틱이 된 pendingEffects를 (applyAt, 생성 순번) 순으로 적용
라운드가 끝나면 pendingEffects를 버린다
```

### 5.2 상태 기계: 스침 인정 (상대 한 명당)

```
상태: Ready | Cooldown(until)
Ready    --스침 감지(묶음이 처음 스침)--> Cooldown(until = t + 60), 보상 지급, 이벤트 GrazeAccepted
Cooldown --스침 감지--> Cooldown(변화 없음), 이벤트 GrazeCosmetic
Cooldown --t >= until--> Ready
라운드 시작 --> Ready
```
- 같은 묶음은 인정이든 연출이든 한 번만 스침으로 센다 (G 6) [제안].
- 경계: 인정이 틱 g에 났으면 틱 g+59의 스침은 연출만, 틱 g+60의 스침은 인정 [임시].

### 5.3 상태 기계: 피격 벌칙 (사람마다)

```
상태: Ready | Window(until)
Ready  --피격(무적 아님)--> Window(until = t + 60); 피해 즉시; 벌칙을 t+3에 예약; 이벤트 HitPenaltyTriggered
Window --피격--> Window(변화 없음); 피해만; 이벤트 HitDamageOnly
Window --t >= until--> Ready
라운드 시작 --> Ready
```

벌칙 적용(t+3) 의사코드:

```
ApplyPenalty(p):
    p.combo = 0
    switch p.character:
      case 성에(얼린 결정):                      // W 5.4 "성에의 얼린 결정"
          if p.frostCrack == 0: p.frostCrack = 1
          else: p.frostCrack = 0 ; if p.crystals > 0: p.crystals -= 1
      case 그믐:                                  // W 5.4 "그믐의 외상"
          if p.debt > 0: p.debt = min(2, p.debt + 1)
          else: p.crystals = max(0, p.crystals - 2)
      default:
          p.crystals = max(0, p.crystals - 1)
```

- 성에의 금: 0 아니면 1. 시간이 지나도 지워지지 않고 라운드가 바뀌면 0. 벌칙 창 안의 피격은 금을 올리지 않는다. "같은 벌칙 창 안에서 두 번째로 맞으면 잃는다"는 쓰지 않는다. 그래서 성에가 결정을 잃는 최고 속도는 2.0초에 1개(다른 캐릭터 1.0초에 1개, 그믐 1.0초에 2개). 금이 1인 동안 맨 끝 결정에 금 간 표시 (W 5.4) [제안] (G 개발자 확인 43).
- 그믐: 빚이 있는 동안(결정 0개) 벌칙이 발동하면 결정 파괴 대신 빚 +1(최대 2). 빚이 있는 동안의 "받는 피해 +1칸" = +100, 벌칙이 발동한 피격에만, 벌칙 창 안의 피격에는 안 붙음, 곧 1.0초에 한 번 (W 5.4) [제안] (G 개발자 확인 44).
- 그믐의 +100: 벌칙이 발동한 그 피격의 피해에 더해 적중 틱에 넣는다. 순간 피해 상한 안에 든다 [제안] (O 4.5 "그믐의 빚이 있을 때의 +100 ... 상한 안"). 빚 여부는 적중 틱의 빚으로 본다 [임시].

### 5.4 피격의 정의 [임시]

"피격" = 상대 플레이어(탄, 비기, 지대, 패시브, 벽 파편, 벼락) 또는 야생 난입 슬라임에게서 피해 판정을 받은 것. 무적(벼락 질주 0.2초, 잔상 걸음 0.15초) 중에는 피격이 아니다. 가시밭은 피격이 아니다.

### 6.3 알고리즘

```
// 각도는 BAM32(uint32, 한 바퀴 2^32), 좌표는 Q32.32
AimDirection(shooterHitCenter, facing8, opponent):
    base   = Facing8ToBam(facing8)                 // 0, 45°, 90° ...
    if opponent == null or !opponent.alive: return base
    target = Atan2Bam(opponent.hitCenter - shooterHitCenter)   // 결정론 CORDIC 또는 표
    delta  = (int32)(target - base)                // 부호 있는 최단 차이(−180°~+180°)
    if |delta| <= AIM_MAX: return target
    return base + sign(delta) * AIM_MAX            // AIM_MAX = 119,304,647 (10°)

FireDirection = AimDirection(...) + (뒤틀린 총열이면 RNG(−25°, +25°))
```

- 상대가 뒤쪽(delta ±180°)이어도 원문대로 10도 꺾는다 [임시: 원문 "밖이면 10도까지만 꺾는다"를 글자대로. 22절 U-04].
- delta가 정확히 ±180°(−2^31)이면 +쪽으로 꺾는다 [임시].
- 시야(facing8)는 바꾸지 않는다. 시야 화살표, 커맨드의 앞/뒤/옆 해석, 자세 규칙(G 3)은 그대로다 [임시].
- 상대의 무적·잔상 중에도 보정한다 [임시].
- 조준선(0.5칸)은 매 프레임 같은 함수로 계산해 그린다(표시 계층).

### 7.4 능력별 구현 세부 [임시가 섞임]

**끓어넘침(달구)** — 잠금 진입 틱에 내 발밑 반경 2.5 안에 상대 피격 원이 닿으면 1.5T, 넉백 1칸(3틱 뒤, 내 중심에서 바깥쪽 방향). 넉백 이동은 벽·기둥에서 멈춘다 [임시]. 비기가 아니라 패시브이므로 준비 2틱이 없다 [임시].

**불가마(달구)** — 지대 판정: 상대 피격 원 중심이 지대 원(반지름 2.5) 안 [임시]. 지대 안에 있는 동안 감속 −10%(가장 큰 감속 하나 규칙), 0.5초마다 0.25T. 피해 틱 기준은 지대가 생긴 틱부터 30틱 간격 [임시]. 감속은 지대 안에 들어온 틱 + 3에 걸리고 나간 틱 + 3에 풀린다 [임시]. 열 흡수 규칙은 W 4.1 그대로(임계로 판정된 발사의 열만, 합계 16, 남은 만큼만, 새로 깔면 이어받지 않음).

**피뢰침 체질(초롱)** — 
```
OnGrazeAccepted(chorong):
    if t < chorong.boltReadyAt: return
    opp = 상대
    if dist(opp.hitCenter, chorong.hitCenter) > 5: return       // 반경 5 [제안]
    marker = opp.hitCenter (고정)                               // [제안] 따라가지 않음
    chorong.boltReadyAt = t + 120
    schedule at t + 15: if CircleOverlap(marker, 0.5, opp.hitCenter, 0.30): Hit(opp, 0.5T, kind=Passive)
```
- "원을 벗어나면 안 맞는다"를 "피격 원(0.30)과 표시 원(반지름 0.5)이 겹치지 않으면"으로 읽는다 [임시]. 0.25초에 벗어나려면 중심이 0.8칸 넘게 움직여야 하고 가장 느린 자세 속도 3.76으로도 0.94칸을 간다.
- 2초 쿨다운은 벼락이 "떨어진" 시점이 아니라 표시가 뜬 시점부터 잰다 [임시].
- 벼락 피해는 피격이다(벌칙 대상) [임시]. 콤보에 안 넣는다 [제안].
- 비기가 아니므로 준비 2틱이 없다 [임시].

**벼락 질주(초롱)** — 비기 준비 2틱 뒤 발동. 이동은 [임시] 4칸을 6틱(0.1초)에 걸쳐 직선으로 간다(원문에 이동 시간이 없다. 22절 U-10). 0.2초 무적은 발동 틱부터 12틱. 길(폭 1.0) 위에 상대 피격 원이 닿으면 3T, 경직 0.3초(3틱 뒤 적용). 길 위 상대 탄은 스침 1회(1.0초 제한 안). 상대를 뚫고 지나간다. 벽·기둥 앞에서 멈춘다(W 4.2).

**베껴 쓰기(갈피)** — 사본 자리 = 발동 틱의 내 발밑. 내 J 발사마다 사본이 18틱 쿨다운 안이 아니면 트리 1회 실행(피해 50%, 열 없음, 콤보 없음, 같은 묶음). 8번 쏘거나 360틱이 지나면 사라진다. 사본은 맞지 않고 움직이지 않는다. 사본 탄도 내 150 상한에 센다.

**살얼음(성에)** — 상대마다 `hitCount`, `immuneUntil`. 내 적중(비기 포함, 폭발·관통은 1회)마다 `immuneUntil` 전이 아니면 +1, 6이 되면 0으로 돌리고 −30% 감속 60틱(3틱 뒤), `immuneUntil = 적용 틱 + 360` [임시: 6초를 감속이 걸린 틱부터 잰다]. 라운드가 바뀌면 둘 다 0 [임시].

**얼음 병풍(성에)** — 벽은 내 시야(보정 적용, 6.2절) 방향 1.5칸 앞 중심, 폭 3칸·두께 0.5칸 직사각형. 
- 상대의 탄이 벽에 닿으면 사라지고 그 탄의 피해(공식을 거친 값, 대상 상태 배율 제외)만큼 벽 체력이 깎인다 [임시]. 상대 탄의 적중 시 발동·폭발은 벽에서 일어나지 않는다 [임시]. 벽 튕김 블록의 상대 탄도 튕기지 않고 막힌다 [임시]. 막은 탄은 스침이 아니다 (W 4.4).
- 상대의 비기 탄(트리 실행)도 "상대의 탄"이므로 막는다. 직선 번개(연쇄 번개), 꿰뚫는 창은 막는다 [임시]. 폭발 범위·지대·그림자 손 당김·피뢰침은 막지 않는다 [임시].
- 상대 플레이어는 지나간다. 내 탄은 통과한다.
- 벽 체력 0이 된 틱에 부서지고 파편 2T. 4초가 다 된 틱에도 파편 2T. 파편 범위는 벽 앞쪽(내 시야 방향) 폭 3칸·길이 2칸 직사각형, 한 번만 (W 5.4; E 17).
- 동시에 1개. 새로 세우면 이전 벽은 파편 없이 사라진다 [임시].

**그림자 손(그믐)** — 
```
판정 틱 j → 준비 2틱 → 발동 틱 a = j + 2 (결정 소모, 범위 고정: 중심 = 내 위치 + 보정 방향 × 3칸)
a ~ a+17: 범위 예고(상대 화면 빨강 원, 내 화면 보라 고리)          // 0.3초 = 18틱 [제안]
a + 18: 판정. 상대 피격 원 중심이 중심에서 4.5 안이면 3T 피해(즉시), 당김 2칸(a + 21에 적용)
```
- 0.3초 예고가 준비 2틱과 별개로 발동 뒤에 붙는다고 읽는다 [임시: 원문 "발동 전에 0.3초"]. 범위 반지름 4.5는 W 4.5의 무한 웨이브 값 그대로 [제안: W 5.4에 줄이 없으므로].
- 당김: 상대를 중심 쪽으로 최대 2칸, 중심을 넘지 않는다. 벽·기둥에서 멈춘다 [임시]. 경직 없음 [제안].

## 8. 비기 (결투에서 달라지는 것) (O 4.2, 4.11; G 8)

### 8.1 규칙

- 판정기(트라이, 실패 링크, 간격, 섬, 만개 예외, 결정 부족 처리)는 G 8 그대로 [제안]. 결투에서는 공용 10 + 고유 1 전부 해금된 것으로 트라이를 만든다 [제안].
- 판정 뒤 준비 2틱을 거쳐 발동한다(코어 규칙, 양쪽 같음) [제안].
- 커맨드 해석(어느 노드가 골라지는가)은 되감기지 않는다. 내 입력의 시각과 순서만 보고 정해진다 [제안] (O 4.11).
- 발동은 되감길 수 있다. 상대 입력이 뒤늦게 확정되어 그 사이 내가 기절하거나 밀려났다면 내 화면에서 나간 것처럼 보였던 비기가 취소될 수 있다 [제안] (O 4.11).

### 8.2 상태 기계: 비기 한 번

```
Idle --K 판정(노드 결정, 자원 확인 통과)--> Prep(j, art)
Prep --t == j + 2 and 시전 가능--> Active(a)        // 결정 소모, 대기 0.4초 시작, 이벤트 ArtActivated
Prep --기절·경직 상태가 됨--> Canceled              // 결정 소모 없음 [임시], 이벤트 ArtCanceled
Active --기술별 진행--> Done
```

- [임시] "취소" 조건: 준비 2틱 사이에 내가 기절(뇌광창 0.5초) 또는 경직(벼락 질주 0.3초)에 걸리면 취소. 넉백·당김으로 밀리면 취소하지 않고 밀린 자리에서 발동한다. 원문 "밀려났다면 취소될 수 있다"를 넉백·당김 적용이 준비 중에 일어나 그 결과 상태가 기절·경직인 경우로 좁혔다(22절 U-11).
- [임시] 결정 소모와 0.4초 공통 대기(G 8)는 발동 틱에 시작한다. 판정 틱의 자원 확인은 그 틱의 상태로 하고, 발동 틱에 다시 보지 않는다.
- 판정(커서·입력 기록 비우기)은 판정 틱에 한다 (G 8 "발동하거나 불발하면 커서와 입력 기록을 비운다").
- 문양과 소리는 발동 틱이 서버 확정을 받았을 때 낸다 [제안] (O 4.11). 보통 준비 2틱 안에 확정되므로 체감은 그대로. 확정 전에 그린 연출(적중 불꽃, 피해 숫자, 발동 문양)은 번복되면 0.1초에 걸쳐 흐려지고, 피격 연출과 발동 소리는 확정 뒤에만, 한 번 낸 소리는 끊지 않는다 (E 17) [제안]. 21절 충돌 C1 참고.
- 탄의 위치와 이동은 확정을 기다리지 않고 바로 그린다 [제안] (O 4.11).

### 8.3 결투 값이 바뀐 공용 비기 (O 4.2)

| 비기 | 결투 |
|---|---|
| ② 반동 사격 | 상대 넉백 1.5칸(3틱 뒤). 내 뒤로 2칸은 그대로 [임시] |
| ⑦ 방열 폭발, ⑩ 만개 | 탄 소거 동일(상대 탄을 지운다) |
| ⑨ 뇌광창 | 기절 0.5초(3틱 뒤) |
| 그 밖 | GDD 그대로 |

[임시] 플레이어의 기절·경직: 지속 동안 이동, 발사(J), K가 막힌다. 키 이벤트는 키 상태에 반영하지만 커맨드 입력으로 읽지 않고, 기절·경직이 걸리는 틱에 커맨드 커서를 비운다. 과열 냉각은 계속된다.

- 서버 프로필에서만 된다. 오프라인 프로필에는 사람 상대 결투가 없고, 허수아비 연습과 봇 결투 연습은 둘 다 된다 [조율] (O 8.1; D 2.6).

## 10. 아이템 레벨 IL (O 4.7)

### 10.1 장착 IL

```
장착 IL = 10 × 강화 단계
        + 장착 블록 점수 합 (일반 2, 희귀 5, 영웅 10) — 코어 1칸 + 연결 4칸 + 확장 칸
        + 6 × 변이 수 (2개까지만 센다)
        + 5 × 확장 슬롯 수
```
[제안] (O 4.7)

- 최대 = 130 + 80(8칸 전부 영웅) + 12 + 15 = 237. 다섯 캐릭터가 같다 [제안].
- 캐릭터가 타고난 것은 넣지 않는다. 갈피의 다섯째 기본 칸에 낀 블록(점수가 가장 낮은 블록 하나를 뺀다)과 초롱의 셋째 변이는 세지 않는다 [제안] (O 4.7; W 5.1 끝).
- "강화 단계"는 지팡이의 실제 단계다(깎아 적용하기 전) [임시].

```
EquippedIL(wand):
    ext    = wand.slotsExtra                         // 0..3
    scores = sort_desc([BlockScore(b) for b in wand.loadout.blocks])   // 코어+연결+확장 칸의 블록
    counted = sum(scores[0 : 1 + 4 + ext])           // 갈피의 다섯째 기본 칸이 차 있으면 가장 낮은 하나가 빠진다
    return 10 * wand.stage + counted + 6 * min(2, wand.mutations.Count) + 5 * ext
BlockScore: Common=2, Rare=5, Hero=10
```
- "가장 낮은 블록 하나를 뺀다"를 "점수 순으로 위에서 `1 + 4 + ext`개만 센다"로 구현한다 [임시]. 갈피가 아니면 블록 수가 `1 + 4 + ext`를 넘을 수 없으므로 같은 식이 된다.

### 10.2 보유 IL

- 그 계정이 낼 수 있는 가장 높은 장착 IL [제안] (O 4.7).
- 계정의 지팡이 각각(개수 제한 없음)에 대해, 가진 블록(서고 + 어느 지팡이에든 끼워 둔 것 전부) 중 점수가 가장 높은 것을 칸 수만큼 채웠다고 치고 계산. 그중 최댓값 [제안].
- 우편함에 있는 것, 장터에 올려 둔 것, 거래 잠금 중, 검증 대기 중인 것도 포함 [제안].
- 최근 14일의 최고값. 올라갈 때 즉시, 내려갈 때 14일 뒤 [제안].
- 지팡이를 여러 자루 가져도 더해지지 않는다. +0 지팡이를 몇 자루 사도 바뀌지 않는다. 낮은 지팡이를 쌓아 낮추는 길도 없다 [제안].
- 서버는 지팡이 한 자루가 바뀔 때(강화, 받음, 내줌) 그 자루의 값만 다시 계산해 저장하고 계정 최댓값을 갱신한다 [제안].
- 받은 지팡이를 실제로 들지 않아도, 그 캐릭터를 한 번도 안 해도 보유 IL은 오른다. 리그는 "가진 것"으로 나눈다 [확정] (O 4.7; D 1.9, 2.7).

```
RawHoldingIL(account):
    pool = 계정의 모든 블록(서고, 끼워 둔 것, 우편, 장터, 잠금, 검증 대기)의 점수, 수량만큼 펼쳐 내림차순
    best = 0
    for wand in account.wands (우편·장터·잠금·대기 포함):
        k    = 1 + 4 + wand.slotsExtra
        il   = 10 * wand.stage + sum(pool[0:k]) + 6 * min(2, wand.mutations.Count) + 5 * wand.slotsExtra
        best = max(best, il)
    return best

HoldingIL(account, today):
    raw = RawHoldingIL(account)
    il_history.upsert(account, today, max(existing, raw))      // 그날의 최고값
    return max(raw, max(il_history.holding_il where day >= today - 13))
```
- 14일 창은 서버 날짜 기준, 오늘을 포함한 14일 [임시]. 날짜 경계는 서버 시각 00:00(KST) [임시].
- 코어에 투사체만 들어간다는 제약과 "블록 하나는 한 지팡이에만" 제약은 보유 IL 계산에서 무시한다(상한값) [임시].
- 갈피의 다섯째 기본 칸: `k = 1 + 4 + ext`이므로 자동으로 빠진다. 초롱의 셋째 변이: `min(2, …)`로 빠진다.

### 10.3 지팡이가 오갈 때 (직접 거래, 장터, 선물, 떠나보내기 모두 같은 규칙) (O 4.7)

| 일 | 보유 IL | 리그 |
|---|---|---|
| 지팡이를 받았다(샀다) | 거래가 확정된 순간 다시 계산. 장터에서 산 것은 우편함에서 꺼내기 전이라도 산 순간부터 센다 | 경계를 넘으면 **즉시** 위 리그로. 아래 리그 자동 매치 대기열에 있었다면 빠진다. 이미 시작한 경기는 그대로 끝낸다 |
| 지팡이를 내줬다(팔았다, 줬다, 떠나보냈다) | 그 지팡이가 14일 최고값을 만들고 있었다면 14일 뒤 남은 지팡이와 블록으로 다시 계산한 값으로 내려간다 | 그 14일 동안 그대로. 14일 뒤 값이 내려가도 리그가 내려가는 것은 **다음 시즌 시작** |
| 장터에 올렸다 | 변하지 않는다(올려 둔 동안 내 것). 팔린 순간부터 "내줬다" | 변하지 않는다 |
| 블록을 사고팔았다 | 지팡이와 같은 규칙 | 같다 |
| 강화 성공 / 하락 | 성공은 즉시, 하락은 14일 뒤 | 같다 |

[제안] (O 4.7). 살 때 거래 확인 창과 장터 구매 확인 창에 "이 거래로 리그가 맹수 → 후계로 올라갑니다"를 적는다 [제안]. +13 지팡이 한 자루를 사면 그 순간 후계 리그 [제안].

## 11. 리그 (O 4.8; D 1.9, 2.7)

### 11.1 경계와 제한 [확정: 3개, 소지한 아이템의 레벨 기준 / 제안: 경계·제한]

| 리그 | id | 보유 IL | 경기 중 제한 | 보상 계수 |
|---|---|---|---|---|
| 새싹 | `Sprout` | 70 이하 | 강화 +4까지, 영웅 블록 1개까지, 변이 없음, 확장 칸 사용 불가(기본 칸만: 4칸, 갈피 5칸) | 0.4 |
| 맹수 | `Beast` | 155 이하 | 강화 +9까지, 영웅 블록 3개까지, 변이 1개까지, 기본 칸 + 확장 2칸까지 | 0.7 |
| 후계 | `Heir` | 제한 없음 | 없음(초롱은 변이 3개 전부) | 1.0 |

경계 근거 (O 4.8): 새싹 70 = +4(40) + 영웅 1(10) + 희귀 4(20). 맹수 155 ≈ +9(90) + 영웅 3(30) + 희귀 4(20) + 변이 1(6) + 확장 2(10) = 156. (21절 충돌 C3)

- "기본 칸만: 4칸, 갈피 5칸"의 "칸"은 연결 슬롯 수다(코어 1칸은 별도). 근거 계산이 블록 5개(코어 + 연결 4)를 센다 [임시 해석, 21절 C9].

```
LeagueOf(holdingIL): holdingIL <= 70 ? Sprout : holdingIL <= 155 ? Beast : Heir
```

### 11.2 리그 이동 규칙

- 리그는 보유 IL로 자동 결정. 실력으로 나누지 않는다 [확정] (D 1.9).
- 자기 리그보다 **위** 리그에는 스스로 올라갈 수 있다(시즌 중 1회 선택, 그 시즌에는 못 내려온다). 아래 리그에는 못 들어간다 [제안].
- 리그는 시즌 안에서 올라가기만 한다. 보유 IL이 경계를 넘으면 즉시 올라가고, 내려가도(14일 규칙) 시즌 끝까지 그대로. 다음 시즌 시작 때의 보유 IL로 다시 정한다 [제안] (O 14-11, G 개발자 확인 49).
- 시즌 중 위 리그로 가면: 결투 점수는 리그마다 따로이므로 새 리그는 시작값(1500/350)으로 배치전부터. 후계 점수(O 6.3)는 정산할 때의 리그 하나에서만 매기고, 무한 웨이브 S는 그대로 가져가고, 결투 점수 R과 판 수 조건은 정산 리그에서 쌓은 것만 [제안].
- 리그 안의 매치는 결투 점수가 가까운 순 [제안].
- 보상 계수는 시즌 보상의 재료 양에만 곱한다. 후계 점수 계산에는 안 들어간다 [제안] (O 4.8, 6.4).

### 11.3 상태 기계: 계정의 시즌 리그

```
SeasonStart: league = LeagueOf(HoldingIL), voluntaryUsed = false
(보유 IL 갱신) --LeagueOf(new) > league--> league = LeagueOf(new); 아래 리그 대기열에 있으면 빼기; 진행 중 경기는 끝까지
(스스로 승급, voluntaryUsed == false, target > league) --> league = target; voluntaryUsed = true
(보유 IL 하락) --> 변화 없음
SeasonEnd → 다음 SeasonStart
```
- `account.league`, `account.league_season_id`에 저장 (O 7.9) [제안].
- 스스로 승급은 시즌 중 1회. 맹수에서 후계로 간 뒤에는 더 위가 없다. 새싹에서 맹수로 간 뒤 IL이 올라 후계로 자동 승급하는 것은 막지 않는다 [임시].

### 11.4 제한을 넘는 장비: 경기 중에 깎아 적용 (O 4.8)

- 제한을 넘는 장비는 못 들고 들어가는 것이 아니라 경기 중에 제한값으로 깎여 적용된다(+11 지팡이는 맹수 리그에서 +9로 계산) [제안].
- 지팡이 본체 모양은 실제 단계 그대로, 이름표에 "적용 +9", 봉인 끈 한 줄이 더 감긴다 [제안] (그림은 지팡이 문서. G 개발자 확인 28).

```
ApplyLimits(wand, limits):                                   // 서버가 경기 시작 때 한 번 계산해 양쪽에 내려 준다
    applied.stage = min(wand.stage, limits.maxStage)          // [제안]
    applied.slotsExtraUsable = min(wand.slotsExtra, limits.maxExtSlots)
    // [임시] 사용 못 하는 확장 칸의 블록은 빈 칸으로 본다(뒤쪽 칸부터)
    // [임시] 영웅 블록이 상한을 넘으면 슬롯 순서상 뒤쪽 영웅 블록부터 빈 칸으로 본다.
    //        코어가 영웅이면(연쇄 번개) 코어는 남기고 연결 칸에서 뺀다. 코어 영웅 1개가 상한을 다 쓰면 나머지 영웅은 빈다
    // [임시] 변이가 상한을 넘으면 가장 최근에 얻은 것부터 남긴다(초롱의 "가장 오래된 것을 밀어냄"과 같은 방향)
    applied.mutations = newest(wand.mutations, limits.maxMutations)
    return applied
```
- 초롱의 셋째 변이: 후계에서 3개 전부. 새싹 0개, 맹수 1개는 초롱에게도 같다 [임시: 원문 표 그대로, 22절 U-14].
- 갈피의 다섯째 기본 칸: 새싹에서도 쓴다(5칸) [제안].
- 깎아 적용한 값은 `duel_match.snapshots`에 남긴다 [제안] (O 7.9).
- 광장 도전에서 "리그 규칙 적용"이면 둘 중 낮은 리그의 제한을 양쪽에 [제안] (O 4.6).

## 13. 결투 점수, 매치메이킹, 보상 (O 4.10, 2.2, 6.3~6.5)

### 13.1 규칙

- 리그마다 따로 가진다. Glicko-2, 시작 1500, 편차 350 [제안].
- 자동 매치 결과만 반영. 광장 도전과 결투 방은 전적에만 [제안].
- 같은 상대와의 경기는 하루 3판까지만 반영. 자동 매치는 직전 상대와 연속으로 잡지 않는다 [제안].
- 중도 이탈은 패배(3.7절) [제안]. 서버가 내려가 양쪽이 다 끊기면 무효, 점수 불변 [제안].
- 매치 범위: 처음 ±100, 10초마다 ±50씩 넓힌다. 서버 왕복 120ms 초과는 자동 매치에 못 들어간다 [제안].
- 시즌 초기화: `1500 + 0.5 × (R − 1500)`로 당기고 편차를 200으로 올린다 [제안] (O 6.5).

### 13.2 Glicko-2 매개변수 [임시: 원문은 "Glicko-2, 1500, 350"만 정했다]

### 13.3 매치메이킹 알고리즘 [제안 + 임시]

```
대기열: 리그별. 항목 = (account, rating, enqueuedAt, lastOpponent, rtt, transport, deviceId)
Window(entry, now) = 100 + 50 * floor((now - entry.enqueuedAt) / 10s)          // [제안]

  for 리그 L: 항목을 enqueuedAt 오름차순으로 훑어
     a와 짝이 될 후보 b: 같은 리그, |a.rating - b.rating| <= min(Window(a), Window(b)) [임시: 둘 다 받아들일 때],

저인구 모드: 리그 대기 인원이 [임시] 10명 미만인 상태가 매치 시점에 성립
```
- 넓히는 폭에 상한이 없다(원문에 없음) [임시: 상한 없음].

## 14. 넷코드: 서버 시뮬레이션 + 예측/되감기 (O 4.11; D 2.6)

### 14.1 원칙 [조율] (D 2.6 "결투는 서버가 판정한다. 클라이언트가 보낸 입력의 시각과 순서를 서버가 검증한다")

입력의 시각은 누른 기기에서 찍고, 그 시각이 거짓이 아닌지는 서버가 도착 시각으로 검증하고, 시뮬레이션의 정본은 서버가 돌린다. 클라이언트는 같은 결정론 코어로 앞서 그려 보이고, 서버가 확정한 입력과 다르면 되감아 고친다 (O 4.11).

| 대상 | 계산하는 곳 | 표시 |
|---|---|---|
| 결투 전투(이동, 탄, 피해, 비기 판정) | 서버의 결투 프로세스(`wizard-duel`)가 정본. 양쪽 클라이언트는 같은 코어로 예측만 | [조율] |
| 입력의 순서와 시각 | 클라이언트가 적고 서버가 검증해 확정 | [조율] |
| 승패, 점수, 보상 | 서버. 클라이언트의 결과 보고는 받지 않는다 | [조율] |
| 장비·조립·리그 제한 적용 | 서버가 경기 시작 때 양쪽에 같은 값을 내려 준다 | [제안] |
| 관전 | 서버가 확정 입력을 2초 늦게 관전자에게 보낸다. 관전자 클라이언트가 직접 시뮬레이션 | [제안] |
| 다시 보기 | 서버가 가진 확정 입력 기록 | [제안] |

코어: 고정 60틱, Q32.32, 유니티 물리 안 씀(원 판정 직접 계산), 씨앗 하나에서 갈라 낸 PCG 계열 난수, 반복 순서가 정해진 자료구조만 (O 3.1) [제안]. `Wizard.Sim`은 클라이언트·결투 프로세스·검증 워커가 같은 소스 (O 3.1) [제안]. 히트스톱·화면 흔들림은 표시 계층이고 게임 시간은 멈추지 않는다 (O 3.1; E 0.2) [제안].

### 14.2 입력 이벤트 (O 3.1; G 3)

입력 이벤트 구조체는 하나다. 무한 웨이브 기록과 결투 패킷이 같은 것을 쓴다 [조율].

```csharp
public enum DuelKey : byte {          // 4비트. [임시] 값 배정
    Up = 0, Down = 1, Left = 2, Right = 3,   // WASD(재설정 가능, 물리 키 기준)
    Fire = 4,      // J
    Art = 5,       // K
    Stance = 6,    // Shift
    Reverse = 7,   // Space
    // 8..15 예약
}

public readonly struct InputEvent {   // 코어 안 표현
    public readonly uint   EffectiveTick;  // 유효 틱
    public readonly byte   Offset;         // 틱 안 오프셋 0..255 (1/256틱)
    public readonly DuelKey Key;           // 4비트
    public readonly bool   Pressed;        // 누름 1 / 뗌 0
    public readonly uint   Seq;            // 플레이어별 순번, 경기 처음 1부터 1씩 증가 [임시: 시작값]
    public long SubtickTime => (long)EffectiveTick * 256 + Offset;   // 판정기 시각 단위
}
```

- 한 틱에 최대 8개 [제안].
- 실제 시각 = `(유효 틱 + 오프셋 ÷ 256) × 16.667ms` [제안] (O 3.1). 0.07초 섬 판정도 이 값으로 한다.
- 처리 순서: (유효 틱, 오프셋, 순번) 순. 오프셋이 같으면 방향 키가 K보다 먼저(클라이언트가 한 프레임에 두 키를 같이 읽었을 때의 동률 규칙, 코어 안) [조율] (O 3.1; G 3).
- [임시] 같은 (틱, 오프셋) 안의 정렬 키: 자세 키(Stance, Reverse) 0 → 방향 키 1 → Fire 2 → Art(K) 3, 같은 종류 안에서는 순번. 방향 < K만 원문 규칙이고 나머지 순서는 이 문서의 기본값이다.

```
SortKey(e) = (e.EffectiveTick, e.Offset, KeyClass(e.Key), e.Seq)
KeyClass: Stance/Reverse = 0, Up/Down/Left/Right = 1, Fire = 2, Art = 3
```

판정기 간격 상수(서브틱): 0.07초 = 1,075, 0.18초 = 2,765, 0.2초 = 3,072, 0.25초 = 3,840, 0.3초 = 4,608 (G 8 판정기) [제안].

### 14.3 패킷

클라이언트 → 서버, 매 틱 1개(입력이 없어도) [제안] (O 4.11-3):

```
DuelClientPacket {
    header: match_token_id(u32), packet_number(u64)          // AEAD nonce에 쓴다
    sealed_through_tick : u32   // 내가 봉인하는 마지막 유효 틱
    events              : InputEvent[]   // 최근 8틱(유효 틱 기준 sealed_through_tick-7 .. sealed_through_tick)의 이벤트 전부
    ack_confirmed_tick  : u32   // 받은 확정 틱
    client_send_time    : u32   // [임시] 시계 측정용(서버 RTT 추정)
    tag                 : 16B   // Poly1305
}
```
- 최근 8틱분을 겹쳐 보내므로 패킷 하나가 사라져도 다음 패킷이 메운다 [제안].
- [임시] 키 이벤트가 생기면 다음 틱 경계를 기다리지 않고 즉시 패킷을 하나 더 보낸다(22절 U-16. 마감 여유 표의 전제).
- 크기 목표: 약 85바이트, 초당 60패킷, 사람당 올림·내림 각각 약 40kbps (O 7.5) [제안].
- [임시] 이벤트 직렬화: 첫 이벤트는 (tick u32, offset u8, key·pressed u8, seq u32), 다음부터 tick·seq를 앞 이벤트와의 차이로 가변 길이 정수.

서버 → 클라이언트 [제안] (O 4.11-5):

```
DuelServerPacket {
    header, packet_number
    confirmed: [ { tick: u32, p1_events: InputEvent[], p2_events: InputEvent[] } ... ]   // 아직 ack 안 된 확정 틱들
    state_hash: { tick: u32, hash: u64 }?        // 30틱마다
    dropped: [ { seq, reason } ]                 // 버린 내 이벤트(본인에게 알림) [제안]
    server_time: u64, echo_client_send_time: u32 // 시계 동기 [임시]
    my_margin_ms_estimate: i16                   // [임시] 마감 여유 HUD용 측정값
}
```

### 14.4 시계 맞추기 (O 4.11-1)

- 경기 시작 전 왕복 16회 측정, 가장 짧은 값 기준 [제안].
- 경기 중 1초마다 다시 재고, 어긋나면 틱 속도를 ±0.5% 안에서 천천히 맞춘다. 건너뛰지 않는다 [제안].

```
Sync(samples[16]):    // 각 표본: t0(보냄, 클라 시각), ts(서버 시각), t1(받음, 클라 시각)
    s = argmin(t1 - t0)
    rtt    = s.t1 - s.t0
    offset = s.ts - (s.t0 + rtt / 2)                 // 서버시각 = 클라시각 + offset
TickAdjust: err = (서버 기준 목표 틱 시각 - 내 틱 시각); 틱 길이 = 16.667ms × (1 - clamp(err / 1s, -0.005, +0.005)) [임시: 비례 보정]
```

### 14.5 입력 지연 D (O 4.11-2, 4.12)

| 서버 왕복 지연(경기 시작 때 측정) | D | 자동 매치 |
|---|---|---|
| 60ms 이하 | 2틱(33ms) | 가능 |
| 90ms 이하 | 3틱(50ms) | 가능 |
| 120ms 이하 | 4틱(67ms) | 가능 |
| 120ms 초과 | 4틱 고정 | 불가(도전·방에서만 경고와 함께) |

- 경기 시작 때 사람마다 정하고 경기 중에는 바꾸지 않는다 [제안].
- 내가 틱 `t`에 누른 키는 양쪽 모두에서 유효 틱 `t + D`에 적용된다. 누른 순간의 틱 안 오프셋은 그대로 보존 [제안].
- 허수아비 연습과 봇 결투에서 같은 D를 걸고 연습할 수 있게 한다 (O 4.12-3) [제안]. 광장 연습 허수아비에 "결투 입력 지연 체험" (O 5.2) [제안].
- `duel_match.input_delay`에 양쪽 D를 남긴다 (O 7.9) [제안].

```
ChooseD(rttMs): rttMs <= 60 ? 2 : rttMs <= 90 ? 3 : 4
```

### 14.6 봉인과 확정 (O 4.11-4, 4.11-5)

```
서버, 사람 p, 유효 틱 T:
  Sealed(p, T) 조건:
     (a) p의 패킷이 sealed_through_tick >= T 를 보냄  → 그 패킷까지 받은 T의 이벤트로 봉인
     (b) 서버 시각 >= T + 1틱                          → 받은 것까지로 봉인("변화 없음"이면 빈 목록)
  한 번 봉인된 틱의 이벤트는 더 받지 않는다.

서버 시뮬레이션:
  while Sealed(p1, next) and Sealed(p2, next):
      events = Sort(p1[next] ∪ p2[next])               // 14.2 정렬
      sim.Step(next, events) ; Broadcast(confirmed next) ; if next % 30 == 0: Broadcast(hash)
      next++
```

- "서버 시각 T + 1틱"의 시각 0은 경기 시계의 기준점(라운드 첫 카운트다운 틱 0이 서버 시각 0)이다 [임시].
- 봉인된 틱 T의 상대 입력을 A에게 보내는 것은 **A의 틱 T가 봉인된 뒤에만**(반대도 같다) [제안] (14.8절).

### 14.7 클라이언트 예측과 되감기 (O 4.11-6, 4.11-7)

```
클라이언트 매 틱 now:
  1. 내 키 입력을 이벤트로 만든다(EffectiveTick = now + D, Offset = 누른 순간의 틱 안 위치)
  2. 상대의 아직 확정 안 된 틱 입력 = "직전 키 상태 유지"(새 이벤트 없음)로 예측        // [제안]
  3. if now - lastConfirmedTick > 8: 진행을 멈추고(시뮬레이션 틱을 올리지 않음) 서버를 기다린다   // [제안]
  4. 받은 확정 틱 T마다: 그 틱에 쓴 예측(상대 + 내 이벤트)과 다르면 T부터 now까지 다시 돌린다
     (내 이벤트가 서버에서 버려진 경우도 다름으로 본다)
  5. 30틱마다 오는 해시가 내 확정 상태 해시와 다르면 서버에 상태 전체를 요청해 덮어쓴다      // [제안]
```

- 되감기 한도 8틱. 넘으면 잠깐 멈추고 서버를 기다린다 [제안].
- 서버 상태가 정본이므로 다툴 것이 없다. 한 경기에 3번 넘게 해시가 어긋난 클라이언트는 기록해 표시한다 [제안].
- 저장: 클라이언트는 최근 확정 틱부터 지금까지(최대 8+α틱)의 상태 스냅숏을 보관한다 [임시: 매 틱 스냅숏, 링 버퍼 16].
- 상태 해시: 코어 상태(플레이어, 탄, 지대, 대기 효과, 난수기 상태, 틱)를 정해진 순서로 64비트 해시(예: xxHash64) [임시].

### 14.8 서버가 입력에서 검증하는 것 (O 4.11)

| 검사 | 규칙 | 어기면 | 표시 |
|---|---|---|---|
| 순서 | **한 패킷 안에서** 이벤트는 순번이 늘어나고 (유효 틱, 오프셋)이 역행하지 않는다 | 그 패킷을 버린다. 반복되면 경기 몰수 | [조율: dev REVIEW-LOG D01] |
| 순번의 공백 | 순번이 건너뛰었다(8틱 넘게 패킷이 끊겨 겹쳐 보내는 창 밖으로 밀려난 이벤트) | 빠진 순번을 유실로 소비하고 패킷은 계속 처리한다. 본인에게 알린다. 몰수에 세지 않는다 | [조율] |
| 봉인된 틱 | 이미 봉인된 틱의 이벤트 | **그 이벤트만** 늦음으로 버린다(아래 "늦은 시각"과 같다). 순번은 소비한다 | [조율] |
| 틱 안 순서 | 같은 오프셋이면 방향 → K | 서버가 같은 규칙으로 다시 정렬 | [조율] |
| 늦은 시각(과거 주장) | 유효 틱 T의 이벤트는 서버 시각 T + 1틱 전에 도착해야 한다 | 그 이벤트를 버린다(다른 틱으로 옮기지 않는다). 본인에게 알리고, 본인 화면은 그 입력을 되감는다 | [제안] |
| 이른 시각(미래 주장) | 이벤트가 주장하는 누른 시각이 `서버 도착 시각 − 측정된 편도 지연`보다 1틱 넘게 앞설 수 없다 | 버린다. 시계를 빨리 돌리는 클라이언트가 걸린다 | [제안] |
| 키 상태 | 눌린 키의 누름, 안 눌린 키의 뗌 | 무시 | [제안] |
| 양 | 틱당 8개 | 넘는 것은 버린다 | [제안] |

> **[조율: dev REVIEW-LOG D01]** 아래 의사코드의 처음 꼴은 봉인된 틱의 이벤트와 순번 건너뜀을 "패킷 버림"으로 처리했다. 그러면 늦은 이벤트 하나가 뒤따르는 최대 8개 패킷을 통째로 버리게 하고, 8틱(133ms)을 넘는 연속 유실 뒤에는 이후 모든 패킷이 순서 위반이 되어 정직한 플레이어가 몰수패한다. 위 표의 "늦은 시각" 줄(그 이벤트만 버린다)과도 어긋났다. 정본은 `docs/dev/CONTRACTS.md` 10.6절의 순서이고 아래는 그 요약이다.

```
ValidatePacket(p, pkt, arrivalServerTime):
    if 한 패킷 안에서 순번이 늘지 않거나 (EffectiveTick, Offset)이 역행:   reject Packet (order), p.orderViolations += 1; return
    if pkt.base_seq > p.lastSeq:                           mark lost (p.lastSeq+1 .. base_seq), p.lastSeq = base_seq
  for e in pkt.events:
    if e.Seq <= p.lastSeq:                                 skip                        // 겹쳐 보낸 것
    if e.Seq > p.lastSeq + 1:                              mark lost (사이 순번)        // 유실로 소비, 패킷은 계속 처리
    p.lastSeq = e.Seq
    if Sealed(p, e.EffectiveTick):                         drop Event (late) → notify
    if arrivalServerTime >= e.EffectiveTick + 1 tick:      drop Event (late) → notify
    claimedPress = (e.EffectiveTick - p.D) * 256 + e.Offset          // 서브틱
    if claimedPress > ToSubtick(arrivalServerTime - p.oneWayEstimate) + 256: drop Event (future)
    if e.Pressed == p.keyDown[e.Key]:                      ignore Event (state)
    if count(p.tickEvents[e.EffectiveTick]) >= 8:          drop Event (quantity)
    accept
```
- "반복되면 경기 몰수": [임시] 한 경기에서 순서 위반(한 패킷 안의 역행)으로 버린 패킷이 30개를 넘으면 그 사람의 몰수패. 늦음과 유실은 세지 않는다.
- "측정된 편도 지연": [임시] 서버가 그 사람의 최근 16회 왕복 측정 중 최솟값 ÷ 2.
- 버린 이벤트의 순번은 소비된 것으로 본다(다음 이벤트는 순번 +1이어야 한다) [임시].
- 서버는 사람별로 패킷 도착 시각 분포, 봉인 마감에 걸린 횟수, 버려진 이벤트 수를 남긴다(`duel_match.net_stats`) [제안] (O 4.11, 10).

**미리 보기 막기** (O 4.11) [제안]:
- 서버는 B의 틱 T 입력을 A의 틱 T가 봉인된 뒤에만 A에게 보낸다(반대도 같다). 누구도 자기 틱 T를 닫기 전에 상대의 틱 T를 볼 수 없다.
- 그래서 변조된 클라이언트가 상대의 발사나 비기를 받은 뒤 과거 틱으로 "이미 피했다"는 입력을 지어 보낼 수 없다(그 틱은 이미 봉인).
- 정직한 클라이언트는 매 틱 패킷을 보내므로 이 규칙으로 늦어지는 시간은 "내 패킷이 서버에 닿는 시간"뿐이다.

### 14.9 관전과 다시 보기

- 관전: 서버가 확정 입력을 2초(120틱) 늦게 관전자에게 보낸다. 관전자 클라이언트가 직접 시뮬레이션 [제안]. 관전 HUD에는 마감 여유·입력 버려짐·조준선이 없고 "관전 중 · 2초 늦게 본다" (U 4.9) [제안].
- 다시 보기: 서버의 확정 입력 기록. 파일로 두고 `duel_match.replay_key`로 가리킨다 [제안] (O 7.9).
- 관전 시작 시 [임시] 서버가 120틱 전 시점의 상태 전체를 보내고 이어서 확정 입력을 흘린다.

### 14.10 전송 (O 4.11 전송)

- 결투 패킷은 UDP로 맥미니의 결투 프로세스에 직접. 경기마다 서버가 TLS 연결로 내려 준 키로 암호화·인증(ChaCha20-Poly1305, 패킷 번호로 재전송 공격 차단). 유효한 경기 토큰이 없는 패킷은 열어 보지 않고 버린다 [제안].
- UDP가 막힌 환경(서버를 터널 뒤에 둔 경우 포함)에서는 같은 내용을 웹소켓(TLS)으로. 이 경로는 자동 매치에 쓸 수 없다. 광장 도전과 결투 방에서만 경고와 함께 [제안].
- 클라이언트 인터페이스 [제안]:

```csharp
public interface IDuelTransport {
    void Send(ReadOnlySpan<byte> packet);
    bool TryReceive(out ReadOnlySpan<byte> packet);
    DuelTransportKind Kind { get; }        // Udp, WebSocket, Loopback
}
// 구현: UdpDuelTransport, WebSocketDuelTransport, LoopbackTransport(한 기기 2인과 봇 연습)
```
- [임시] 재전송 차단: 방향별 패킷 번호 u64, 받은 최고 번호와 64개 비트맵 창. 창보다 오래됐거나 이미 받은 번호는 버린다. nonce = 방향 1비트 ‖ 패킷 번호 64비트(96비트로 0 채움).
- 서버 쪽 키 배포: 경기 시작 때 `wizard-api`가 TLS로 경기 토큰과 32바이트 키를 양쪽에 [임시].

### 14.11 되감기와 비기의 관계 (O 4.11)

8.2절 참고. 요점:
1. 비기는 판정 뒤 준비 2틱(코어 규칙).
2. 상태를 바꾸는 효과는 적중 3틱 뒤.
3. 그래도 취소되면 문양이 0.1초 동안 흐려지며 사라진다. 피격 연출과 소리도 확정된 틱에 대해서만 낸다.

### 14.12 버린 방식 (참고, O 4.11)

| 방식 | 버린 이유 |
|---|---|
| 서버 도착 시각으로 커맨드 판정 | 지연의 흔들림이 0.07초 판정에 섞인다 |
| 지연 기반 락스텝 | 상대의 지연이 내 화면 반응을 늦춘다 |
| 클라이언트끼리만 계산, 서버는 중계 | 서버가 판정하지 않고 입력 시각을 아무도 검증하지 않는다 |

### 14.13 서버 구성 (O 7.2, 7.5)

- 결투 프로세스 `wizard-duel`(C#), 같은 `Wizard.Sim`을 참조 [제안] (O 11-7).
- 한 경기 CPU: 60틱 × 틱당 0.2ms(두 사람, 탄 300개 이하) ≈ 코어 하나의 1.2% [제안]. 동시 결투 60(300명 기준)~100(500명), 결투 30경기 0.4코어 / 50경기 0.6코어 [제안] (O 7.5).
- UDP 주소와 포트, 연결 경로 종류는 맥미니 밖 정적 JSON에 둔다 (O 7.4) [제안]. 터널 경로면 결투가 웹소켓이 되어 자동 매치를 열 수 없다 (O 7.4) [제안].

## 15. 지연 허용: 섬(0.07초)은 지연을 얼마나 견디는가 (O 4.12)

1. 지연의 크기는 섬 판정에 들어가지 않는다. 섬은 "방향을 누른 시각"과 "K를 누른 시각"의 간격이고 둘 다 내 기기에서 찍힌다. 서버 왕복이 20ms든 120ms든 0.05초 간격으로 눌렀으면 서버도 0.05초로 판정한다. 무한 웨이브(통신 없음)와 같은 결과가 나와야 하고 이것이 QA 통과 기준이다 [제안].
2. 깨지는 경우는 내 패킷이 마감을 넘길 때뿐이다. 마감 여유 = `(D + 1)틱 − 편도 지연`. 지터나 연속 유실이 이 여유를 넘으면 그 순간의 입력이 버려지고 비기가 안 나간다 [제안].

| 서버 왕복 | D | 마감 여유 | 견디는 범위 | 자동 매치 |
|---|---|---|---|---|
| 60ms 이하 | 2틱(33ms) | 20ms 이상 | 지터 15ms까지, 또는 패킷 1개 유실까지 영향 없음(둘이 겹치면 버려질 수 있다) | 가능 |
| 90ms 이하 | 3틱(50ms) | 22ms 이상 | 위와 같음 | 가능 |
| 120ms 이하 | 4틱(67ms) | 23ms 이상 | 위와 같음 | 가능 |
| 120ms 초과 | 4틱 고정 | 줄어든다 | 150ms에서 여유 8ms. 입력이 자주 버려진다 | 불가(도전·방에서만 경고와 함께) |

3. 입력 지연 D는 손맛을 바꾸지만 판정을 바꾸지 않는다. 누른 뒤 화면 반응까지 33~67ms가 일정하게 걸린다 [제안].
4. 상대를 보고 맞춰 누르는 타이밍은 지연만큼 불리하다. 상대의 행동은 내 화면에 `max(내 편도, 상대 편도) + 내 편도 − D`만큼 늦게 닿고 그만큼 되감겨 보인다. 둘 다 왕복 60ms면 약 27ms(2틱), 둘 다 120ms면 약 53ms(4틱). 섬과는 무관 [제안].
5. 와이파이가 순간 30ms 이상 튀면 그 순간의 섬은 안 나갈 수 있다(왕복 60ms, D = 2에서 여유 20ms). 숨기지 않는다. 대기열 화면에 "유선 연결 권장", 경기 중 HUD 구석에 내 마감 여유를 초록(15ms 이상) / 노랑 / 호박색(5ms 미만, 빨강은 위험색이라 안 씀)으로. 입력이 버려지면 그 틱에 작은 표시로 "내 실수가 아니라 회선"임을 알린다 [제안].
6. 서버가 가정집 회선이므로 서버 쪽 흔들림은 모든 경기에 실린다. 서버 쪽 지터가 10ms를 넘는 시간이 하루 1% 이상이면 노출 방식(O 7.4)을 바꾼다 [제안].

국내 가정용 광회선끼리의 왕복은 보통 10~40ms이므로 대부분 D = 2틱에 든다. 실제 분포는 서버를 세운 뒤 잰다 (O 4.12) [제안].

```
MarginMs(D, rttMs) = (D + 1) * 1000 / 60 - rttMs / 2
HudBand(marginMs)  = marginMs >= 15 ? Green : marginMs < 5 ? Amber : Yellow
OpponentLagMs(myOneWay, oppOneWay, D) = max(myOneWay, oppOneWay) + myOneWay - D * 1000 / 60
```
- HUD 값은 [임시] 서버가 패킷마다 측정한 "봉인 마감까지 남은 시간"(마감 시각 − 도착 시각)의 최근 60개 중 10번째로 작은 값을 쓴다(위 식은 시작 때의 예상값).

## 16. 경기 상태 기계 (`DuelMatch`)

```
Created ──(양쪽 접속, 키 배포)──▶ ClockSync ──(16회 측정 끝, D 결정)──▶ Loading
Loading ──(양쪽 준비 / [임시] 15초 타임아웃이면 안 온 쪽 이탈패)──▶ RoundCountdown(180틱)
RoundCountdown ──▶ RoundLive
RoundLive ──(한쪽 체력 0)──▶ RoundResult
RoundLive ──(시간 끝, CompareTimeout != Tie)──▶ RoundResult
RoundLive ──(시간 끝, Tie)──▶ Overtime(1,800틱)
Overtime ──(한쪽 체력 0 / 시간 끝)──▶ RoundResult(끝이면 CompareTimeout, Tie면 무승부 라운드)
RoundResult ──(승수 == 선승 수 or 라운드 상한)──▶ MatchResult
RoundResult ──(아니면)──▶ Intermission([임시] 180틱) ──▶ RoundCountdown
아무 상태 ──(한쪽 끊김)──▶ (경기 계속) + Disconnected 타이머 20초
Disconnected ──(20초 안 복귀)──▶ 원래 상태(상태 전체 재전송)
Disconnected ──(20초 경과)──▶ MatchResult(끊긴 쪽 패배, reason=Leave)
아무 상태 ──(기권)──▶ MatchResult(기권한 쪽 패배, reason=Forfeit)
아무 상태 ──(순서 위반 반복)──▶ MatchResult(위반한 쪽 몰수패, reason=Confiscated)
아무 상태 ──(서버 다운·서버 회선 끊김으로 양쪽 동시 끊김)──▶ Void(점수·보상 없음)
MatchResult ──▶ 점수 갱신(rated일 때), 보상, 전적, 다시 보기 저장, 지팡이 잠금 해제
```

- 경기 중 지팡이는 `lock_state = 결투`로 잠겨 거래할 수 없다 [제안] (O 7.9, 5.5).
- 서버 전체 알림은 결투 중 뜨지 않고 결과 화면 뒤로 미룬다 (E 8, 17) [제안].
- 양쪽 동시 끊김과 한쪽 끊김의 구분 [임시]: 서버 프로세스가 살아 있고 한쪽 패킷만 끊기면 한쪽 끊김. 서버가 내려갔다가 올라오면(진행 중 경기 기록이 메모리에만 있으므로) 그 경기는 Void로 정리한다. 서버 회선 끊김 판정: 두 사람의 패킷이 같은 1초 안에 모두 끊기면 Void [임시].
