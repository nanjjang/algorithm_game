# 11. 온라인 — 협동 · 1대1 결투 · 광장 (solo 구조)

사용자 결정(2026-11-15): 인터넷 온라인, solo 헤드리스 서버, 오프라인·서버 프로필 따로, 협동 먼저.
규칙 원문은 `docs/online.md`, `docs/spec/09~12`를 읽는다. 이 문서는 그것을 **solo 코드 위에 어떻게 얹는지**만 정한다. 원문과 다르게 정한 곳은 "solo 결정"으로 적는다.

## 0. 모드 넷

| 모드 | 접속 | 판을 돌리는 곳 | 프로필 |
|---|---|---|---|
| 솔로 | 없음 | 내 기기(지금 그대로) | 오프라인 프로필 |
| 협동 | 온라인 | 전투 서버 | 서버 프로필 |
| 결투 | 온라인 | 전투 서버 | 서버 프로필 |
| 광장 | 온라인 | 광장 서버 | 서버 프로필 |

솔로는 없어지지 않는다. 협동은 같은 시뮬에 `RunConfig.Party`로 동료를 더한 것이고, Party가 비면 지금 솔로와 똑같이 돈다.

## 1. 큰 그림

```
[클라이언트 (solo 빌드)] --UDP(Unity Transport)--> [전투 서버 (solo 헤드리스 빌드)]
         |                                               |
         +----HTTPS---> [계정·로비 서버 (solo/Server, .NET)] <---+  (판 결과 보고, 방 배정)
                                  |
                              [DB (SQLite → PostgreSQL)]
```

- **전투 서버**: solo를 Dedicated Server 빌드 대상으로 화면 없이 빌드한다. 같은 `Wizard.Solo.Sim`을 60틱으로 돌린다. 판(협동 웨이브·결투 라운드)마다 `SimWorld` 하나.
- **계정·로비 서버**(`solo/Server/`, ASP.NET Core 최소 API): 계정(아이디+비밀번호, Argon2id, 세션 토큰), 서버 프로필, 방 만들기/참가/매칭, 전투 서버에 방 배정, 판 결과 받아 서버 프로필에 정산. 강화도 여기서 한다(강화 화면 → 서버 요청, 확률은 서버가 굴린다).
- **solo 결정**: 솔로 시뮬이 float라 원문의 "입력 기록 제출 + 서버 재검증"과 "클라이언트 예측·되감기의 결정론 일치"는 쓰지 않는다. 판은 처음부터 서버에서 돈다.

## 2. 층 나누기 (00-architecture.md 1절에 더함)

| 층 | 위치 | 하는 일 |
|---|---|---|
| Sim | 그대로 | 소켓·시계 없음. 입력은 `InputQueues[slot]`, 상태는 `SimWorld`에서 읽힌다 |
| Net 공용 | `Assets/Scripts/Net/Shared` | 메시지 정의, 직렬화(스냅숏·입력), 버전 |
| Net 서버 | `Assets/Scripts/Net/Server` | 연결 받기, 슬롯 배정, 입력을 큐에 넣기, `Step`, 스냅숏 보내기, 결과 보고 |
| Net 클라이언트 | `Assets/Scripts/Net/Client` | `IInputSource` 입력을 보내기, 스냅숏을 받아 보간한 "보이는 세계"를 뷰에 넘기기 |
| App | `SessionCore` 옆에 `OnlineSessionCore` | 오프라인은 지금 그대로, 온라인은 스스로 `Step`하지 않고 Net 클라이언트가 준 상태를 그린다 |

전송: `INetPipe` 하나로 감싼다. 2단계 = `LoopbackPipe`(같은 프로세스), 3단계 = `TcpPipe`(System.Net.Sockets, [길이][몸] 틀, 추가 패키지 없음). 지연·끊김을 재 보고 필요하면 `com.unity.transport`(UDP) 통로를 더한다. Netcode for GameObjects는 쓰지 않는다(시뮬이 GameObject가 아니라서).

전용 서버(3단계, solo 결정): 이 PC의 Unity에 Dedicated Server 모듈이 없어서 보통 맥 빌드를 `-batchmode -nographics -coopServer [-port 27870]`로 띄운다(`Tools/coop-server.sh build|run`). 서버 하나 = 방 하나. 방장(가장 낮은 슬롯)이 `StartRequest`를 보내면 판이 열리고, 판이 끝나 모두 나가면 새 방을 연다. 기본 포트 27870/TCP.

## 3. 동기화 방식

- 클라이언트 → 서버: `InputEvent(LogicalKey, Down, TimeU)` 묶음, 틱 번호와 순번. 신뢰 순서 채널.
- 서버 → 클라이언트: 20Hz 스냅숏(플레이어·적·탄·장판·웨이브 상태·HUD 숫자). 앞 스냅숏과의 차이만(델타) + 2초마다 전체. 이벤트(피격, 사망, 드랍, 소리 신호)는 신뢰 채널로 따로.
- 보이는 세계: 남은 100ms 늦게 두 스냅숏 사이를 보간. **내 캐릭터만** 클라이언트에서 같은 이동 코드로 미리 움직이고 서버 값으로 맞춘다(예측). 탄·적은 예측하지 않는다.
- 뷰(`View/*`)는 `SimWorld`를 직접 읽지 않고 읽기 인터페이스(스냅숏으로 채운 세계)를 읽게 한다 — 1단계 작업에서 뷰가 읽는 필드 목록을 뽑아 고정한다.

## 4. 단계

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 0 | 이 문서, AGENTS.md 수정 | 완료 |
| 1 | 시뮬 다인용 점검: `P0` 의존 제거, 슬롯별 캐릭터·지팡이 시작, 사망/부활 규칙(협동) | 한 기기에서 봇 3 + 나 = 4인 웨이브가 끝까지 돈다 |
| 2 | Net 공용·서버·클라이언트 + 루프백(한 프로세스 안 서버) | 루프백 협동 판이 오프라인 판과 같은 화면으로 돈다 |
| 3 | 헤드리스 서버 빌드, TCP 통로, 로비의 [참가](주소), 방장 시작 | 두 기기가 서버에서 한 판을 끝낸다 (EditMode: 127.0.0.1 TCP로 손님 둘 확인) |
| 4 | `solo/Server`: 계정, 서버 프로필, 방·초대 코드, 판 결과 정산, 온라인 강화 | 가입 → 방 → 협동 판 → 정산이 서버 프로필에 남는다 |
| 5 | 1대1 결투(`docs/spec/10-duel.md`): 3판 2선승, 라운드 90초, 매칭 | 두 기기 결투 한 경기 |
| 6 | 광장(`docs/spec/11`): 인스턴스 40명, 10틱 이동 동기화, 채팅, 거래 | 두 기기가 광장에서 만나 거래한다 |

## 5. 정할 것 (사용자 확인 대기)

- 협동 인원(2~4)과 적 체력·수 배율, 쓰러진 동료 일으키기 여부, 보상 나누기. 원문에 협동이 없어서 solo 결정이 필요하다.
- 결투 D-51(솔로 제외)은 온라인 결투로 되살린다 — 봇 연습은 여전히 넣지 않는다.
- 맥미니 주소·도메인·TLS 인증서.
