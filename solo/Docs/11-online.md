# 11. 온라인 — 협동 · 1대1 결투 · 광장 (solo 구조)

사용자 결정(2026-11-15): 인터넷 온라인, solo 헤드리스 서버, 오프라인·서버 프로필 따로, 협동 먼저.
규칙 원문은 `docs/online.md`, `docs/spec/09~12`를 읽는다. 이 문서는 그것을 **solo 코드 위에 어떻게 얹는지**만 정한다. 원문과 다르게 정한 곳은 "solo 결정"으로 적는다.

## 0. 모드 넷

| 모드 | 접속 | 판을 돌리는 곳 | 프로필 |
|---|---|---|---|
| 솔로 | 없음 | 내 기기(지금 그대로) | 오프라인 프로필 |
| 협동 | 온라인 | 전투 서버 | 서버 프로필 |
| 결투 | 온라인 | 전투 서버 | 서버 프로필 |
| 광장 | 온라인 | 광장 서버 | 서버 프로필 |

솔로는 없어지지 않는다. 협동은 같은 시뮬에 `RunConfig.Party`로 동료를 더한 것이고, Party가 비면 지금 솔로와 똑같이 돈다.

## 1. 큰 그림

```
[클라이언트 (solo 빌드)] --UDP(Unity Transport)--> [전투 서버 (solo 헤드리스 빌드)]
         |                                               |
         +----HTTPS---> [계정·로비 서버 (solo/Server, .NET)] <---+  (판 결과 보고, 방 배정)
                                  |
                              [DB (SQLite → PostgreSQL)]
```

- **전투 서버**: solo를 Dedicated Server 빌드 대상으로 화면 없이 빌드한다. 같은 `Wizard.Solo.Sim`을 60틱으로 돌린다. 판(협동 웨이브·결투 라운드)마다 `SimWorld` 하나.
- **계정·로비 서버**(`solo/Server/`, ASP.NET Core 최소 API): 계정(아이디+비밀번호, Argon2id, 세션 토큰), 서버 프로필, 방 만들기/참가/매칭, 전투 서버에 방 배정, 판 결과 받아 서버 프로필에 정산. 강화도 여기서 한다(강화 화면 → 서버 요청, 확률은 서버가 굴린다).
- **solo 결정**: 솔로 시뮬이 float라 원문의 "입력 기록 제출 + 서버 재검증"과 "클라이언트 예측·되감기의 결정론 일치"는 쓰지 않는다. 판은 처음부터 서버에서 돈다.

## 2. 층 나누기 (00-architecture.md 1절에 더함)

| 층 | 위치 | 하는 일 |
|---|---|---|
| Sim | 그대로 | 소켓·시계 없음. 입력은 `InputQueues[slot]`, 상태는 `SimWorld`에서 읽힌다 |
| Net 공용 | `Assets/Scripts/Net/Shared` | 메시지 정의, 직렬화(스냅숏·입력), 버전 |
| Net 서버 | `Assets/Scripts/Net/Server` | 연결 받기, 슬롯 배정, 입력을 큐에 넣기, `Step`, 스냅숏 보내기, 결과 보고 |
| Net 클라이언트 | `Assets/Scripts/Net/Client` | `IInputSource` 입력을 보내기, 스냅숏을 받아 보간한 "보이는 세계"를 뷰에 넘기기 |
| App | `SessionCore` 옆에 `OnlineSessionCore` | 오프라인은 지금 그대로, 온라인은 스스로 `Step`하지 않고 Net 클라이언트가 준 상태를 그린다 |

전송: `INetPipe` 하나로 감싼다. 2단계 = `LoopbackPipe`(같은 프로세스), 3단계 = `TcpPipe`(System.Net.Sockets, [길이][몸] 틀, 추가 패키지 없음). 지연·끊김을 재 보고 필요하면 `com.unity.transport`(UDP) 통로를 더한다. Netcode for GameObjects는 쓰지 않는다(시뮬이 GameObject가 아니라서).

전용 서버(3단계, solo 결정): 이 PC의 Unity에 Dedicated Server 모듈이 없어서 보통 맥 빌드를 `-batchmode -nographics -coopServer [-port 27870]`로 띄운다(`Tools/coop-server.sh build|run`). 서버 하나 = 방 하나. 방장(가장 낮은 슬롯)이 `StartRequest`를 보내면 판이 열리고, 판이 끝나 모두 나가면 새 방을 연다. 기본 포트 27870/TCP.

## 3. 동기화 방식

- 클라이언트 → 서버: `InputEvent(LogicalKey, Down, TimeU)` 묶음, 틱 번호와 순번. 신뢰 순서 채널.
- 서버 → 클라이언트: 20Hz 스냅숏(플레이어·적·탄·장판·웨이브 상태·HUD 숫자). 앞 스냅숏과의 차이만(델타) + 2초마다 전체. 이벤트(피격, 사망, 드랍, 소리 신호)는 신뢰 채널로 따로.
- 보이는 세계: 남은 100ms 늦게 두 스냅숏 사이를 보간. **내 캐릭터만** 클라이언트에서 같은 이동 코드로 미리 움직이고 서버 값으로 맞춘다(예측). 탄·적은 예측하지 않는다.
- 뷰(`View/*`)는 `SimWorld`를 직접 읽지 않고 읽기 인터페이스(스냅숏으로 채운 세계)를 읽게 한다 — 1단계 작업에서 뷰가 읽는 필드 목록을 뽑아 고정한다.

## 4. 단계

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 0 | 이 문서, AGENTS.md 수정 | 완료 |
| 1 | 시뮬 다인용 점검: `P0` 의존 제거, 슬롯별 캐릭터·지팡이 시작, 사망/부활 규칙(협동) | 한 기기에서 봇 3 + 나 = 4인 웨이브가 끝까지 돈다 |
| 2 | Net 공용·서버·클라이언트 + 루프백(한 프로세스 안 서버) | 루프백 협동 판이 오프라인 판과 같은 화면으로 돈다 |
| 3 | 헤드리스 서버 빌드, TCP 통로, 로비의 [참가](주소), 방장 시작 | 두 기기가 서버에서 한 판을 끝낸다 (EditMode: 127.0.0.1 TCP로 손님 둘 확인) |
| 4 | `solo/Server`: 계정, 서버 프로필, 방·초대 코드, 판 결과 정산, 온라인 강화 | 가입 → 방 → 협동 판 → 정산이 서버 프로필에 남는다 |
| 5 | 1대1 결투(`docs/spec/10-duel.md`): 3판 2선승, 라운드 90초, 매칭 | 두 기기 결투 한 경기 |
| 6 | 광장(`docs/spec/11`): 인스턴스 40명, 10틱 이동 동기화, 채팅, 거래 | 두 기기가 광장에서 만나 거래한다 |

## 5. 정할 것 (사용자 확인 대기)

- 협동 인원(2~4)과 적 체력·수 배율, 쓰러진 동료 일으키기 여부, 보상 나누기. 원문에 협동이 없어서 solo 결정이 필요하다.
- 결투 D-51(솔로 제외)은 온라인 결투로 되살린다 — 봇 연습은 여전히 넣지 않는다.
- 맥미니 주소·도메인·TLS 인증서.


## 6. 지금 만들어진 것 (2026-11-15)

### 6.1 방 서버와 방 코드 (어몽어스식)
- 전용 서버(`DedicatedServer`)는 `RoomServer` 하나를 돌린다: 방 여러 개 + 광장 하나. 포트 27870/TCP.
- 새 연결의 첫 메시지로 길이 나뉜다: `CreateRoom(mode)` → 6자리 코드(`ABCDEFGHJKMNPQRSTUVWXYZ23456789`, 헷갈리는 0·O·1·I·L 없음) / `JoinRoom(code)` / `EnterPlaza`.
- 방 종류: 협동(4명) · 결투(2명). 방장 = 가장 낮은 슬롯. 방장만 시작·봇 더하기/빼기. 결투는 2명이어야 시작.
- 끝나고 모두 나간 방, 판 전에 10초 넘게 빈 방은 지운다. 판이 시작된 방에는 들어갈 수 없다.
- 클라이언트의 서버 주소는 `DataSolo/Online.json`의 `server_hosts`를 앞에서부터 붙어 본다(`coop.yoonjunseo.com` → 집 안 `192.168.219.112` → `127.0.0.1`).

### 6.2 결투 (solo 결정, docs/spec/10-duel.md 3절에서 고른 것)
- `RunMode.Duel`, 판 상태 `DuelCountdown → DuelFight → DuelRoundEnd`. 규칙은 `RunFlow.Duel.cs`, 값은 `DataSolo/Duel.json`(없으면 원문 [제안] 값).
- 들어간 것: 3판 2선승, 라운드 90초, 카운트다운 3초(못 움직임), 시작 결정 1, 시간 종료 판정(체력 비율 → 준 피해), 연장 30초(받는 피해 2배), 순간 피해 상한(30틱 동안 최대 체력 30%), 결투 강화 배율(1 + 0.03 × 단계), 피격 원 0.30칸, 라운드 상한 5, 기권·끊김 = 패배.
- 아직 없는 것: 가시밭, 기둥, 비기·지대·폭발의 상대 피해, 스침 인정·피격 벌칙, 조준 보정, 리그·점수.
- 화면: 전투 화면 위 가운데 점수판(라운드·남은 시간·승수), 카운트다운·라운드 결과 큰 글자. 끝나면 온라인 방 화면에 승패.

### 6.3 광장 (좀비고식)
- 서버 `PlazaHost`(시뮬 없이 가볍게): 한 광장 40명, 40×22칸, 60Hz 이동·10Hz 상태 전송, 말풍선 6초(60자, 1초에 1번), 감정 표현 8종.
- 화면 `PlazaScreen`: 처음에 이름(기기에 기억, 프로필에 쓰지 않음) → 방향키·WASD로 걷기, Enter로 말하기, 1~4 감정 표현, [방 만들기·참가]로 온라인 방 화면.
- 아직 없는 것: 광장 안 문(포탈)으로 방 들어가기, 친구·귓속말, 거래·장터(원문 11절), 여러 광장 인스턴스.

### 6.4 협동 개선
- 스냅숏 Deflate 압축(약 4.2KB → 0.6KB), 스냅숏 사이 보간(SnapshotSmoother), 온라인 Esc = 판에서 나가기, 서버 안 봇, 부활(쓰러진 동료 곁 3초).

### 6.5 결투 보강 (2026-11-15 뒤)
- 모든 공격이 상대에게: 사람마다 보이지 않는 과녁(`EnemyState.DuelProxyOf`)을 세운다. 적을 맞히는 모든 길(탄·폭발·연쇄·유도·비기·지대·화상)이 그대로 상대에게 닿고, 피해는 `SpellSystem.ApplyDamage`가 결투 피해(`DuelProxyDamage`)로 넘긴다. 자기 과녁은 맞지 않는다. 과녁은 움직이지·생각하지·죽지 않고 그리지 않는다.
- 기둥 넷(칸 (9,3)·(14,3)·(9,10)·(14,10), 탄을 막음 — 그림이 없어 회색 원), 가시밭(라운드 60초부터 5초에 1칸, 최대 6칸, 0.5초마다 최대 체력 4%, 가시 띠로 보임).

### 6.6 광장의 문
- 광장 왼쪽 "협동의 문", 오른쪽 "결투의 문". 문 위에서 Space → 그 종류로 온라인 방 화면.

### 6.7 계정·서버 프로필 (4단계 첫 판, solo 결정)
- **기기 계정**: 처음에 온라인 이름(2~12자, 겹치지 않음)을 정하면 기기가 32바이트 비밀을 만들어 서버에 등록한다. 다음부터 연결 맨 앞에 Login(id, 비밀). 비밀번호·이메일 복구는 TLS를 붙일 때(지금은 통신에 암호화가 없어 비밀번호를 받지 않는다).
- 서버 저장: `~/WizardCoopServer/accounts.json`(비밀은 PBKDF2-SHA256 값만). 이 기기: `persistentDataPath/online_account.json`. 오프라인 프로필과 따로.
- 서버 프로필: 레이팅(Elo, 시작 1000, K 32), 결투 승·패·무, 협동 판 수·최고 웨이브, 골드([임시] 결투 승리 50, 협동 웨이브당 10).
- 판이 끝나면 방 서버가 한 번 적는다(계정이 있는 사람만, 봇 제외). 결투는 두 사람 다 계정일 때만.
- 계정 없이도 방·광장에 들어갈 수 있다(손님, 기록 없음).
- 아직 없는 것: 서버 프로필의 지팡이·강화·인벤토리, 순위표, 친구, 다른 기기로 계정 옮기기.

### 6.8 서버 프로필 확장 — 서버 지팡이·서버 강화·순위표
- 온라인 판의 출발 설정은 오프라인 프로필을 읽지 않는다(`OnlineMember.Build`): 캐릭터 기본 지팡이(코어 마력탄, 기본 연결 칸 빈 채로), 시작 비기(폭발·반동·고유), 지팡이 단계 = 서버 프로필. 서버가 Hello를 받을 때 다시 만든다(손님이 보낸 단계·조립은 믿지 않는다). 손님·봇은 +0. 기본 공격 유형만 오프라인에서 고른 것을 읽는다.
  - 고친 것: 전에는 온라인 방이 오프라인 `BuildRunConfig`를 불러 오프라인 프로필(원정 시작 수·마지막 캐릭터)에 쓰고 있었다.
- 서버 프로필: 캐릭터마다 지팡이 단계·기운·최고 단계, 강화 횟수.
- 서버 강화(내 기록·강화 화면): 규칙은 오프라인과 같은 `EnhanceRules`(기본 확률·기운·대성공·떨어짐, 비용 100 × (단계+1)² + 그 단계의 강화석). 주사위는 서버가 굴린다. 부적을 켜면 떨어짐을 막고 막았을 때만 하나 쓴다. [임시] 제물은 아직 없고, 변이 구간은 성공으로 친다.
- 서버 재료 창고(`ServerProfile.Items`): 협동 판이 끝나면 사람마다 오프라인 정산과 같은 드랍 표(`SettlementService.DrawMaterials`, 판의 추첨 기회)로 따로 굴려 강화석·부적을 넣고, 골드는 원정 지갑 그대로. 결투 승리 = 50골드 + 하급 강화석 1 [임시]. 까마귀 보따리는 서버에 없다.
- 순위표: 결투를 한 번이라도 한 사람, 레이팅 순 20위.
- 제물: 협동 판이 끝나면 판 보관함의 블록(빌린 것 제외)이 사람마다 한 벌씩 서버 창고로 간다([임시] 귀환 가방 칸 제한 없음). 강화 때 블록을 골라 넣으면 오프라인과 같은 `SacrificeBonus`(등급 합·같은 속성)로 확률이 오르고, 결과와 상관없이 사라진다.
- 변이: 변이 구간이면 오프라인과 같은 후보 풀(`MutationPool`, 서버 지팡이 코어는 마력탄이라 폭발 전용은 빠짐)에서 하나를 제시한다. 받으면 변이(캐릭터별 상한, 넘치면 가장 오래된 것이 밀려남) + 기운 1, 단계 그대로. 거절하면 시도 때 미리 계산한 실패(부적 포함). 답하기 전에는 그 지팡이를 다시 강화할 수 없다. 받은 변이는 온라인 판 출발 설정(`RunConfig.Mutations`)에 들어간다.
- 서버 지팡이 조립(6.10, 조립 화면 `OnlineAssemblyScreen`): 캐릭터마다 코어 + 연결 칸(기본 칸 + 대성공으로 늘어난 칸, 오프라인과 같은 GreatGivesSlot·상한). 블록은 서버 창고의 것만, 끼우면 창고에서 빠지고 빼면 돌아온다. 마력탄은 누구나 가진 기본 블록(창고 없이). 저장할 때 서버가 모양(코어 투사체·칸 수)·주문 컴파일(오프라인과 같은 InventoryRules)·수량을 본다. 온라인 판은 이 조립으로 나간다.
- 변이 지우기: 조립 화면의 받은 변이 칩을 누르면 지운다(골드 = 오프라인과 같은 MutationRemoveGold, 단계·기운·칸 그대로).
- 광장 직접 거래(6.11): 가까운 사람(3칸)에게 T로 청하고 상대가 Y로 받으면 거래 판이 열린다. 골드와 창고 아이템(강화석·부적·블록)을 올리고, 둘 다 [확인]하면 서버가 한 번에 맞바꾼다(어느 쪽이든 바꾸면 확인이 풀린다, 가진 것이 모자라면 거래가 안 된다). 온라인 이름이 있는 사람끼리만. [임시] 수수료 없음.
- 직접 거래 수수료: 오간 골드의 5%(받는 쪽에서 뺀다, docs/online.md 경제 표).
- 장터(6.12, `OnlineMarketScreen`): 창고 아이템을 개수·묶음 값으로 올린다. 보증금 1%(팔리면 돌려받고, 내리거나 48시간이 지나 돌아오면 사라진다), 계정당 동시 20건, 수수료 5%(판 값에서). 사면 물건은 산 사람 창고로, 대금은 판 사람의 우편함으로(6.14절 — 받기를 눌러야 골드가 된다). 기한이 지나 돌아온 물건도 우편함으로 간다. 둘러보기는 개당 값 싼 순.
- 친구(6.12, `OnlineFriendsScreen`): 이름으로 신청 → 상대가 받으면 서로 친구(서로 신청하면 바로). 목록에 지금 어디(광장·방·접속 안 함). 끊으면 양쪽에서. 귓속말: 광장 채팅에 "@이름 할 말"(광장에 있는 사람에게만, 없으면 알려 준다).
- 아직 없는 것: 블록 별의 서버 보관, 지팡이 거래. (우편함·차단·시즌은 6.14절에서 들어갔다.)

### 6.13 로그인·DB·암호화 (2026-11-15, 사용자 결정: Postgres, Google은 코드 먼저, 메일 보류)
- **이메일 계정**: 이메일 + 비밀번호(10~128자, 이메일 앞부분 포함 금지) + 이름. 서버는 PBKDF2-SHA256 10만 번(소금 16바이트)만 저장. 같은 이메일 5번 틀리면 1초부터 두 배씩(최대 15분) 기다린다. 틀린 까닭은 하나의 문구로만 알린다.
- **Google 계정**: 데스크톱 OAuth(루프백 + PKCE). 서버가 코드를 바꾸고 id_token의 iss·aud·exp를 본다. 처음이면 이름을 정한다(같은 연결로 GoogleFinish). 클라이언트 비밀은 서버에만.
- **로그인 표(세션)**: 로그인하면 서버가 32바이트 토큰을 주고(60일, 계정당 10개), 기기는 `online_account.json`에 (id, 토큰)만 둔다. 다음 연결은 예전과 같은 Login(id, 토큰). 로그아웃 = 서버에서 그 표를 지우고 파일 삭제. 옛 기기 계정(32바이트 비밀)도 계속 들어올 수 있지만 새로 만들지는 않는다.
- **TLS**: 통로는 TLS 1.2(`TlsPipe`, 연결마다 읽기·쓰기 스레드). 클라이언트는 인증서를 이름이 아니라 SHA-256 지문(`Online.json` `tls_pins`)으로 확인한다. 지문이 비어 있으면 평문 TCP(같은 기기 개발용) — 그때는 비밀번호를 보내지 않는다.
- **DB**: `IAccountDb` — `PostgresAccountDb`(맥미니, 5433) / `JsonAccountDb`(개발·테스트). `AccountStore`가 메모리 사본을 들고, Save() 한 번 = 바뀐 계정 줄·장터 물건·강화 기록을 트랜잭션 하나로. 실패하면 바뀜을 들고 있다가 다음 Save()에서 다시 쓴다. 자세한 운영은 13-coop-server-deploy.md 7절.
- 프로토콜 12: ServerInfoRequest/ServerInfo, EmailSignup, EmailLogin, GoogleLogin, GoogleNeedName, GoogleFinish, Logout/LogoutDone. AuthOk 끝에 토큰·이메일·계정 종류, AuthFail 끝에 기다릴 초.
- 화면: 온라인에 들어가면 계정이 없거나 로그인 표가 지워졌을 때 `OnlineLogin`을 먼저 연다. 화면 구성은 14-online-ui.md.

### 6.14 우편함 · 차단 · 신고 · 리그 · 자동 매치 · 관전 · 시즌 (2026-11-16, 프로토콜 13)
규칙 원문은 `docs/online.md` 3.5·4.6~4.10·5.2~5.3·6절. 수치는 전부 `DataSolo/OnlineRules.json`(없으면 코드 기본값 = 원문 값). 서버 코드는 `AccountStore.Online.cs`(규칙) · `RoomServer.Online.cs`(요청·대기열) · `OnlineRules.cs`(수치·IL·리그 제한·Glicko-2).
- **우편함**: 장터 대금(판 값 − 수수료 + 보증금)과 기한이 지나 돌아온 물건, 시즌 보상이 우편으로 온다. 받기 전에는 골드·창고에 들어가지 않는다. 한 통씩 또는 전부 받기, 30일 뒤 사라진다. (산 물건은 지금처럼 산 사람 창고로 바로 간다.)
- **차단**(200명): 차단하면 친구가 끊기고, 어느 쪽이 막았든 귓속말·거래 청·친구 신청이 오가지 않는다(보낸 쪽에는 알리지 않는다). 차단한 사람의 광장 말풍선은 그 사람에게만 가려서 보낸다. 자동 매치에서도 만나지 않는다.
- **신고**: 이름 + 사유 5종(욕설·사기·현금 거래·부정 프로그램·기타). 서버가 그 사람의 최근 광장 채팅 30줄을 붙인다. 서로 다른 계정 5개에게 24시간 안에 신고당하면 채팅이 1시간 막힌다. 같은 사람을 24시간 안에 다시 신고할 수 없다. 대기열은 서버 저장소(`AccountStore.Reports`)에만 있다 — 관리 화면은 아직 없다.
- **아이템 레벨**: 장착 IL = 10 × 단계 + 블록 점수(일반 2·희귀 5·영웅 10, 코어 + 연결 칸) + 6 × 변이(2개까지) + 5 × 확장 칸. 보유 IL = 가진 블록(창고 + 끼운 것 + 장터에 올린 것 + 우편함)으로 낼 수 있는 가장 높은 값, 최근 14일 최고값(오를 때는 바로, 내릴 때는 14일 뒤). `AccountStore.Save()`가 손댄 계정마다 다시 계산한다.
- **세 리그**(새싹 ≤ 70 · 맹수 ≤ 155 · 후계): 보유 IL로 정해지고 시즌 안에서는 올라가기만 한다. 스스로 위 리그로 한 번 올라갈 수 있다. 다음 시즌이 시작할 때의 보유 IL로 다시 정한다. 리그 제한(단계·영웅 블록·변이·확장 칸)은 자동 매치 방에서 출발 설정을 깎아 적용한다(`LeagueRules.ApplyLimits`). solo 결정: 지팡이는 캐릭터마다 한 자루라 "지팡이 거래 7일 잠금·감정가 수수료"는 없다.
- **자동 매치**: 시즌 화면에서 대기열에 들어간다(웨이브 10 도달 + 누적 플레이 2시간). 같은 리그에서 결투 점수 차 ±100(10초마다 ±50)의 가장 가까운 사람과 잡히고, 직전 상대와는 연속으로 잡지 않는다. 잡히면 서버가 그 두 계정만 들어올 수 있는 결투 방을 만들어 코드를 보내고(`MatchFound`), 둘이 들어오면 서버가 시작한다. 30초 안에 안 들어오면 방을 닫는다(점수 그대로).
- **결투 점수**: 리그마다 따로, Glicko-2(시작 1500, 편차 350). 자동 매치만 반영한다(방·광장 결투는 예전 Elo 전적 그대로). 같은 상대는 하루 3판까지만 반영. 중도 이탈 = 패배 + 이탈 기록, 하루 3회를 넘기면 30분 대기열 금지. 양쪽이 다 끊기면 무효. solo 결정: 통로가 TCP라 왕복 지연 120ms 제한과 끊김 뒤 20초 기다리기는 넣지 않았다(끊기면 바로 패배).
- **관전**: 결투 방 코드로 들어간다(방마다 6명, 판 중에도). 슬롯 없이 판 설정·스냅숏·이벤트만 받고, 보낸 것은 서버가 버린다. 화면은 슬롯 0의 눈으로 본다.
- **판 기록과 순위표**: 협동 판이 끝나면 사람마다 판 기록(점수 = 판의 점수, 웨이브, 캐릭터, 단계)을 적는다. 순위표 = 시즌 종합(상위 3판 평균) · 캐릭터별 · 주간(월요일 0시 UTC) · 주간 "+7 이하" · 역대 · 친구 · 리그 결투 점수 · 후계 점수. solo 결정(1절 그대로): 판은 처음부터 서버가 돌리므로 원문 3.2절의 "입력 기록 제출 + 재실행 검증 + 검증 대기 보상"은 만들지 않았다.
- **시즌**: 10주 + 정산 3일(정산 기간에는 게임은 되지만 시즌 점수·결투 점수에 반영하지 않는다). 처음 서버가 뜰 때 시즌 1이 시작한다. 후계 점수 = E + P(각 500 × 백분위², 리그 안에서, 일반 판 3판·자동 매치 30판 이상이 대상). 정산: 후계 리그 1위(자동 매치 50판 이상) = 후계자, 그다음 9명 = 수제자, 리그마다 상위 1%·10%·30%·참가 보상(재료·골드 × 리그 계수 0.4/0.7/1.0), 결투 점수 상위 10% 골드 — 전부 우편으로. 초기화: 시즌·주간 기록, 결투 점수(1500 쪽으로 반 당기고 편차 200), 스스로 올라간 리그. 지팡이·블록·재료·골드·친구·차단·역대 기록·칭호는 남는다.
- **화면**: 온라인 방 화면 위쪽에 [시즌] 단추 → `OnlineSeasonScreen`(탭: 시즌 / 순위표 / 우편함 / 차단·신고). 글자는 `NamesSolo/OnlineSeason.ko.json`.
- **저장**: 계정마다의 상태는 `ServerProfile.X`(Postgres `accounts.extra` jsonb), 서버 전체 상태(시즌·역대 후계자·신고·판 기록)는 `world_state` 표 한 줄. 스키마 2판 — 서버가 뜰 때 스스로 올린다.
- 아직 없는 것: 꾸미기·시즌 주화·시즌 상점(꾸미기 자체가 solo에 없다), 주간 도전(공용 씨앗), 순위표의 다시 보기, 광장 도전·결투 방 옵션(라운드 수·평준화 등), 채팅 금칙어 필터와 채널, 기기당 계정 수 제한, 신고·제재 관리 화면, 맥미니가 내려가 있던 만큼 시즌을 늦추는 것.
